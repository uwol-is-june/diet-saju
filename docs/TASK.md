### [TASK-42] 홈으로 돌아가는 동선 — 푸터 링크와 법적 고지 페이지 · **(S)** · ⬜ 대기

> **두 증상을 한 태스크로 두는 이유:** 뿌리가 같다. 지금 **홈으로 가는 길이 푸터 링크
> 하나뿐**인데, 그 링크가 이름도 모호하고(`사주 풀이`) 눈에 띄지도 않아서(`text-xs` ·
> `text-ink-muted` · 문서 맨 아래) 사람들이 없는 줄 안다. 실제로 "푸터 사주풀이가 아무
> 데도 안 간다" 와 "고지 페이지에서 나올 버튼이 없다" 가 같은 날 나왔다.

**① 푸터 `사주 풀이` 링크**

`components/SiteFooter.tsx:16` 은 `/` 로 정상 연결돼 있다. **고장이 아니라 홈(`/`)에서
누르면 자기 자신이라 아무 일도 안 일어나는 것**이다. 사용자에겐 그게 곧 고장이다.

- [ ] 이름을 목적지가 드러나게 바꾼다 (`처음으로` · `유형 선택` 중 택일).
      `사주 풀이` 는 어디로 가는지도, 지금 거기 있는지도 알려주지 않는다.
- [ ] **현재 페이지면 링크 대신 글자로 두는 방식(`aria-current`)은 권하지 않는다.**
      `usePathname()` 이 필요해 `SiteFooter` 가 클라이언트 컴포넌트가 되고, 레이아웃에
      있으므로 **`/` 에도 클라이언트 JS 가 들어간다** — `CLAUDE.md` 가 명시한
      "`/` 에는 클라이언트 컴포넌트가 없다" 가 깨진다. 이 정도 문제에 치를 값이 아니다.
      굳이 하려면 그 성질을 포기하는 이유를 `CLAUDE.md` 에 함께 적을 것.

**② `/privacy` · `/disclaimer` 에서 나가는 길**

두 페이지 모두 `<h1>` 로 바로 시작하고 상단에 홈 링크가 없다. 문서가 길어서 **끝까지
스크롤해야 푸터가 나온다.** 읽다 말고 나가려면 브라우저 뒤로가기밖에 없는데, 검색이나
공유 링크로 바로 들어온 사람에겐 그마저 없다.

- [ ] 두 페이지 **상단**에 홈으로 가는 링크를 둔다 (`← 다이어트 사주` 형태).
      `next/link` 를 쓴다 — 새 탭·가운데 클릭이 살아야 한다 (TASK-30 과 같은 이유).
- [ ] **두 페이지에 같은 조각을 두 번 적지 말 것.** 문구가 갈라진다. 공용 컴포넌트로
      빼거나 `app/(legal)/layout.tsx` 로 묶는다. 라우트 그룹으로 묶으면 URL 은 그대로다.
- [ ] 서버 컴포넌트로 유지한다. 두 페이지는 정적이고 클라이언트 JS 가 필요 없다.
- [ ] 포커스 링은 건드리지 않는다 — `globals.css` 전역 `:focus-visible` 하나가 정한다.
- [ ] 색은 시맨틱 토큰만 쓴다 (`lib/design/tokens.test.ts` 가 raw 색상을 막는다).

**함께 판단할 것**

- [ ] **헤더를 둘지 정한다.** 지금 `app/layout.tsx` 에는 헤더가 없다. ②를 고지 페이지에만
      둘지, 모든 페이지 상단에 둘지의 문제다. 전역 헤더를 두면 `/reading/*` 결과 화면
      맨 위에도 링크가 생겨 ①의 무게가 줄지만, **결과 화면은 스트리밍 중 시선을 뺏으면
      안 된다** (`OtherReadingLinks` 를 스트리밍 중에 내지 않는 것과 같은 이유).
      고지 페이지에만 두는 쪽을 기본값으로 하고, 바꾸면 이유를 남긴다.

→ 완료 기준: 푸터 링크 이름만 보고 어디로 가는지 알 수 있다. `/privacy` · `/disclaimer` 에
들어온 사람이 **스크롤하지 않고** 홈으로 나갈 수 있다. 두 페이지의 링크 문구가 한 곳에서만
정의된다. `lint` · `typecheck` · `test` · `build` 통과.
