### [TASK-104] `/` 첫 화면이 위에서부터 순차적으로 나타나게 한다 · **(S)** · ⬜ 대기

`/` 를 열면 머리 띠와 리스트 카드 다섯이 **한꺼번에** 그려진다. 위에서부터 차례로 떠오르게
해서 목록이 훑는 순서(위 → 아래)와 같은 방향으로 읽히게 한다.

**라이브러리를 넣지 않는다.** `/` 는 통째로 정적이고 클라이언트 컴포넌트가 하나도 없다 —
Motion 을 들이면 그 성질이 깨진다(Motion 조사 결과가 `/` 에는 쓰지 않는다고
이미 못 박아 뒀다 — 그 절은 지금 CLAUDE.md 에 없고 `git show e47199a^:CLAUDE.md` 에만 있다). 서버 컴포넌트가 인라인 `style` 로
`animationDelay` 를 박아 내보내면 정적 HTML 그대로다 — 도식 넷이 이미 그 방식이다.

- [ ] `app/globals.css` 에 등장 애니메이션을 정의한다. **기존 `.anim-rise`(0.35s ·
      `translateY(0.375rem)`)를 그대로 쓸지, 카드 크기에 맞는 값을 새로 만들지 정한다** —
      6px 이동은 8px 글자 옆에서 잰 값이라 160px 짜리 카드에서는 안 보일 수 있다.
      새로 만들면 `anim-*` 이름으로 키프레임 옆에 둔다 (Tailwind 임의값 금지)
- [ ] **키프레임은 `from` 만 쓴다.** `to` 로 최종값을 지정하면 모션 최소화에서 숨은 상태에
      갇힌다 — `lib/design/motion.test.ts` 가 막는다
- [ ] **모션 최소화에서 지연이 남는 것을 확인하고 처리한다.** 지금
      `@media (prefers-reduced-motion: reduce)` 는 `animation-duration` 만 0.01ms 로 줄이고
      **`animation-delay` 는 건드리지 않는다.** `both` 라 지연 동안 `from`(투명)에 갇히므로
      **다섯 장이 여전히 시차를 두고 튀어나온다.** 도식들은 최대 420ms 라 안 거슬렸지만
      이 목록은 카드당 지연이 쌓인다 — 그 미디어쿼리에 `animation-delay: 0s !important` 를
      더할지 정하고, **더한다면 도식 넷의 지연도 함께 0 이 된다**는 것을 확인한다
      (그쪽이 오히려 규칙에 맞는 동작이다)
- [ ] **첫 카드 사진이 이 화면의 LCP 요소다** (TASK-87 실측 · `/cards/diet.jpg`).
      투명에서 시작하면 LCP 가 그만큼 밀린다. `node scripts/measure-load.mjs`(프로덕션 빌드 ·
      390px · 1.6Mbps · RTT 150ms)로 적용 전후를 대조한다. **밀리면 첫 카드는 지연 0 으로
      두거나 머리 띠까지만 애니메이션한다** — `priority` 로 300~450ms 를 벌어 둔 자리를
