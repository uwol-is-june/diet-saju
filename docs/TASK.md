# diet-saju 태스크 보드

> 범례·상태 표기·작성 형식은 `CLAUDE.md` 의 "작업 방식" 참고.
> **위에서 아래로 우선순위 순이다.** 순서를 바꿀 때는 이유를 태스크 본문에 적는다.

보류한 작업(결과 캐싱·레이트 리밋 영속화·쿼터 폴백)과 그 판단 근거는 `CLAUDE.md` 의
"보류한 작업" 절에 있다.

# 개발 순서

아래 1~3 은 같은 파일(`components/SajuForm.tsx`)을 만진다. **1 → 2 → 3 순서로 이어서 하면
중복이 없다.** 4(내용)가 5(도식화)보다 앞인 이유는 5 에서 체질·다이어트 판정을 그림으로
만들 텐데, 그리려면 내용이 먼저 굳어야 하기 때문이다.

## 1. [TASK-21] 브랜드 버튼 대비 개선 · **(H)** · ⬜ 대기

**먼저 하는 이유**: 가장 값싸고 즉시 보인다. 대비비 계산은 이미 끝나 있어 판단할 것이 없다.

`사주 풀이 받기` 버튼이 **초록 배경 + 검은 글씨**라 눈에 안 들어온다는 지적.
지금 이 조합은 실수가 아니라 접근성 때문에 고른 것이다 — `green500` 위 흰 글씨는 1.82:1 로
AA(4.5:1) 미달이라 어두운 잉크(9.61:1)를 썼다. **그래서 "흰 글씨로 바꾸기" 만으로는 안 된다.**

실측한 후보 (`lib/design/tokens.test.ts` 와 같은 공식):

| 배경 | 흰 글씨 | 어두운 잉크 | 통과 |
| --- | --- | --- | --- |
| `green500 #50D88F` (현재) | 1.82 | 9.61 | 잉크만 |
| `green600 #25A762` | 3.10 | 5.64 | 잉크만 |
| **`green700 #1C7D4A`** | **5.14** | 3.39 | **흰 글씨만** |
| `#1F9155` (중간값) | 4.01 | 4.36 | **둘 다 미달** |

→ **`green700` 배경 + 흰 글씨**가 답이다. 중간 밝기에는 어느 쪽도 통과하지 않는 사각지대가
있으니 "조금만 어둡게" 로 타협하지 말 것.

- [ ] 시맨틱 토큰 추가 — 채운 버튼용 배경과 그 위 글씨 (예: `--color-brand-solid` / `--color-on-brand-solid`)
      기존 `--color-brand`(연한 초록 면·강조선)와 `--color-on-brand` 는 그대로 둔다
- [ ] hover 상태용 더 어두운 파생값을 만들고 흰 글씨 대비를 다시 검증
- [ ] 채운 버튼 전부 교체 — `SajuForm`(제출), `ShareActions`(이미지로 저장), `FirstVisitNotice`(확인했습니다)
- [ ] `lib/design/tokens.test.ts` 에 새 조합 추가. **"흰 글씨는 brand 배경에서 쓸 수 없다" 는
      기존 단정은 유지**한다 (연한 초록 면에는 여전히 해당된다)
- [ ] 비활성 상태(`disabled:bg-line-strong`) 대비도 다시 확인
- [ ] `docs/design-tokens.md` 에 사각지대(중간 밝기에서 둘 다 미달)를 기록

→ 완료 기준: 채운 버튼의 배경·글씨 대비가 4.5:1 을 넘고 토큰 테스트가 그것을 고정한다.

## 2. [TASK-22] 입력 폼 레이아웃 정리 · **(S)** · ⬜ 대기

**이 순서인 이유**: 입력이 첫 관문이다. 그리고 3번(시각 입력)이 같은 그리드를 건드리므로
정렬을 먼저 바로잡아야 두 번 고치지 않는다.

재현한 문제 (1280·700·390px 전부 확인):

- **음력을 고르면 왼쪽 열에 큰 빈칸이 생긴다.** `양력/음력` 칸에 윤달 체크박스가 추가되면서
  그 행이 높아지는데, 짝인 `생년월일` 칸이 따라 늘어나 아래가 비어 보인다.
- **3행 오른쪽 칸에 라벨이 없어 정렬이 어긋난다.** `태어난 시각`(라벨+입력) 옆에
  `시각을 모릅니다` 체크박스만 놓여, 라벨 줄이 비어 오른쪽 위가 뚫려 보인다.
- **native date/time 컨트롤이 다른 칸과 톤이 다르다.** `연도-월-일`, `-- --:--` 자리표시자가
  스타일을 맞춘 select 옆에서 미완성처럼 보인다.

- [ ] 조건부로 나타나는 체크박스(윤달)가 행 높이를 흔들지 않게 배치 — 짝 칸 안으로 넣거나
      전체 폭 행으로 내리는 방식 중 선택
- [ ] `시각을 모릅니다` 를 라벨 없는 칸에 두지 않는다 — `태어난 시각` 칸 안에 붙이는 쪽이 자연스럽다
- [ ] 세 폭(모바일·태블릿·데스크톱)에서 각 컨트롤의 밑선이 맞는지 실측으로 확인
- [ ] TASK-11 에서 넣은 것들을 되돌리지 말 것 — 모바일 16px 글자(iOS 확대 방지),
      `min-h-11` 터치 타깃, `htmlFor`/`id` 명시 연결, 중첩 label 금지, 전역 포커스 링

→ 완료 기준: 양력·음력 어느 상태에서도, 세 폭 모두에서 빈칸·어긋난 밑선이 없다.

## 3. [TASK-23] 태어난 시각 입력 방식 개선 · **(S)** · ⬜ 대기

**이 순서인 이유**: 2번과 같은 그리드다. 다만 **도메인 판단이 걸려 있어** 태스크를 나눴다.

지금은 `<input type="time">` 이라 데스크톱에서 숫자를 직접 타이핑해야 한다. 눌러서 고르는
방식으로 바꿔 달라는 요청.

**먼저 알아야 할 함정**: 시지(時支) 경계는 경도 보정(서울 −32분)으로 **이동한다.**
그래서 분 단위 입력이 의미가 있다 — 예를 들어 12:20 과 12:40 은 보정 후 다른 시진이 될 수 있다.
**12지시(자시~해시)만 고르게 하면** 그 시진의 대표 시각을 우리가 정해 넣어야 하는데, 그것은
"임의 시각을 채워 넣지 않는다"(시각 미상 처리 원칙)와 충돌한다.

또 하나: iOS·안드로이드에서는 `type="time"` 이 이미 휠 피커를 띄운다. 커스텀 UI 를 만들면
**모바일에서 기본 피커의 이점을 잃을 수 있다.**

- [ ] 방식 결정 — ① 시(0~23) + 분(5·10분 단위) 드롭다운 두 개 ② 12지시 선택 + "정확한 시각을
      알아요" 를 열면 분까지 ③ 모바일은 native 유지, 데스크톱만 커스텀
- [ ] 12지시 선택을 허용하면 **대표 시각을 무엇으로 넣는지 문서화**하고, 보정과의 관계를
      `docs/saju-validation.md` 한계 항목에 적을 것
- [ ] 오전/오후 표기를 쓸지 24시간제를 쓸지 정한다 (지금 native 는 로케일에 따라 "오후 02:30")
- [ ] `시각을 모릅니다` 와의 상호작용 유지 — 체크하면 비활성, 보정도 강제로 끈다
- [ ] 접근성: 드롭다운 두 개로 나누면 각각 라벨이 필요하다. `fieldset`/`legend` 로 묶을 것
- [ ] `sajuInputSchema` 의 `birthTime`(`HH:mm`)은 그대로 두고 **UI 에서만 조립**한다 —
      서버 계약을 바꾸면 만세력 테스트가 전부 영향을 받는다

→ 완료 기준: 키보드 입력 없이 시각을 지정할 수 있고, 분 단위 정보가 보존된다.

## 4. [TASK-24] 잘 맞는 다이어트 방법 추가 · **(O)** · ⬜ 대기

**이 순서인 이유**: 5번(도식화)에서 체질·다이어트 판정을 그림으로 만들 계획이라, 그리기 전에
내용이 굳어야 한다. 그리고 표현 가드레일 판단이 필요해 **(O)** 다.

`diet` 유형에 지금 있는 것은 `잘 맞는 식습관`·`잘 맞는 움직임` 이다. 여기에 **"어떤 방식으로
감량에 접근할 것인가"** 가 빠져 있다는 지적.

이미 재료가 있다 — `lib/saju/constitution.ts` 의 **대사 기조**(발산형/축적형)가 사실상
"쓰는 양을 늘리는 순서 vs 회복을 먼저 고정하는 순서" 를 가리키고 있다. 이걸 독립된 축으로
끌어올리는 작업이다.

- [ ] 다이어트 방식 축을 규칙표로 정의 — 대사 기조 + 한열 + 살이 붙는 패턴에서 결정론적으로.
      `constitution.ts` 의 고전/관례 구분 방식을 그대로 따를 것 (**새 축은 우리 관례**다)
- [ ] 축의 값을 정한다. 예: 활동량 우선 / 리듬 고정 우선 / 식사량 조절 우선 / 회복 우선
      — **동점 처리를 반드시 고정**한다 (안 하면 "같은 사주 = 같은 판정" 이 깨진다)
- [ ] 섹션 계약에 `## 잘 맞는 다이어트 방법` 추가 (`lib/reading/sections.ts`) +
      섹션 지침 추가 (`lib/prompt.ts` 의 `SECTION_INSTRUCTION`)
- [ ] 프롬프트 판정 블록에 새 축을 싣고 "다시 판정하지 말라" 규정 유지
- [ ] **표현 가드레일이 여기서 더 중요하다.** 감량 "방법" 은 의학·영양 조언에 가까워진다.
      금지 어휘 검사(`constitution.test.ts`)를 새 문구에도 적용하고, 단식·특정 식단 이름·
      칼로리 수치·목표 체중 같은 것을 넣지 않는다. 생활 습관 수준을 넘지 말 것
- [ ] `app/disclaimer/page.tsx` 의 "체질 판정은 명리학 오행 해석입니다" 절과 정합 확인.
      방법까지 제시하면 문구를 보강해야 할 수 있다
- [ ] 공유 카드 칩(`lib/share/card-model.ts`)에 넣을지 판단 — 넣으면 `CHIPS.diet` 수정

→ 완료 기준: 같은 사주에 항상 같은 다이어트 방식이 나오고, 금지 어휘 검사를 통과한다.

## 5. [TASK-25] 도식화와 애니메이션 · **(O)** · ⬜ 대기

**마지막인 이유**: 위 네 개가 레이아웃과 내용을 바꾼다. 지금 그림을 얹으면 곧 고칠 것 위에
그리게 된다. 대신 **작업량이 가장 크고 사용자가 중요하다고 말한 항목**이라, 착수하면
범위를 먼저 좁혀 한 덩어리씩 낼 것.

지금 결과 화면은 숫자와 글자뿐이다. 사주는 관계(상생·상극)와 흐름(대운·세운)이 핵심인데
둘 다 그림이 훨씬 잘 전달한다.

- [ ] 범위 결정 — 후보: ① 오행 상생·상극 오각형(관계도) ② 오행 분포 차트 ③ 대운 타임라인
      ④ 한열 눈금(−2~+2) ⑤ 섹션이 도착할 때의 등장 트랜지션
      **한 번에 다 하지 말고 우선순위를 정할 것**
- [ ] 차트 라이브러리를 넣지 않고 **인라인 SVG** 로 구현하는 방향을 먼저 검토
      (번들 비용 + 색을 CSS 토큰에서 읽어야 하는 제약)
- [ ] 색은 시맨틱 토큰만 쓴다. `lib/design/tokens.test.ts` 가 컴포넌트의 raw hex 를 막으므로
      새 컴포넌트를 그 검사 목록에 추가할 것
- [ ] **애니메이션은 `prefers-reduced-motion` 을 존중한다** — `app/globals.css` 에 전역 규칙이
      이미 있으니 그것으로 꺼지는지 확인하고, 안 꺼지는 방식(JS 애니메이션)을 쓰면 직접 분기
- [ ] **스트리밍과 싸우지 않게 한다.** 섹션은 도착하는 대로 렌더된다 — 등장 애니메이션이
      매 조각마다 재생되면 글이 떨리게 보인다. 섹션이 `complete` 될 때 한 번만 재생할 것
- [ ] 공유 카드(`lib/share/draw-card.ts`)와 시각 언어를 맞춘다. 화면과 카드가 달라 보이면 어색하다
- [ ] 다크 모드는 도입하지 않는다 (확정 사항). 밝은 톤 하나만 맞추면 된다
- [ ] 실기 확인 — 모바일 폭에서 도식이 잘리지 않는지, 가로 스크롤이 생기지 않는지

→ 완료 기준: 원국과 대운을 글자 없이도 읽을 수 있고, 모션 최소화 설정에서 정지 상태로 보인다.

## 6. [TASK-26] 파비콘·앱 아이콘 추가 · **(H)** · ⬜ 대기

**요청받은 항목이 아니다** — TASK-10 배포 검증 중에 발견해 적어 둔다. 우선순위는 낮다.

`/favicon.ico`, `/icon.png`, `/apple-touch-icon.png` 가 모두 404 이고 `app/` 에 아이콘 파일이
없다. 브라우저 탭·카카오톡 공유·홈 화면 추가에서 기본 아이콘으로 뜬다.

- [ ] `app/icon.png` (또는 `icon.svg`) 추가 — Next 가 자동으로 메타 태그를 붙인다
- [ ] `app/apple-icon.png` 추가 (홈 화면 추가용)
- [ ] og 카드(`docs/og-card.html`)와 같은 시각 언어로 만들 것

→ 완료 기준: 세 경로가 404 를 내지 않고 탭에 아이콘이 보인다.
