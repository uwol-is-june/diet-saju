### [TASK-34] 유형 선택 화면의 "무엇을 볼까요?" 문구 삭제 · **(H)** · ⬜ 대기

`app/page.tsx:30` 의 `<h2>무엇을 볼까요?</h2>` 를 없앤다. 바로 위 헤더가 이미 무엇을 하는
화면인지 말하고 카드 셋이 제목·설명을 달고 있어서, 이 줄은 아무것도 더 알려주지 않는다.

- [ ] `app/page.tsx` 에서 해당 `<h2>` 제거
- [ ] **목록의 접근 가능한 이름을 잃지 않게 한다** — 지금은 그 `h2` 가 카드 목록의 표제
      역할을 겸한다. `<ul>` 에 `aria-label` 을 주거나 시각적으로 숨긴 제목으로 대체할 것.
      화면에서 글자만 지우고 끝내지 말 것.
- [ ] 제목이 사라지면서 헤더와 카드 사이 여백이 뜨는지 확인하고 간격만 조정
      (`READING_TYPES` 순회 구조·`next/link` 는 그대로 둔다)

→ 완료 기준: `/` 에 "무엇을 볼까요?" 가 보이지 않고, 카드 목록에 접근 가능한 이름이 남아
있으며, `npm run lint` · `npm run typecheck` · `npm test` · `npm run build` 가 통과한다.

### [TASK-35] `/` 하단 안내 문구 삭제 · **(H)** · ⬜ 대기

`app/page.tsx` 맨 아래의 두 줄을 없앤다.

```
유형을 고르면 생년월일을 입력하는 화면으로 넘어갑니다.
입력한 정보는 저장하지 않습니다.
```

**TASK-34 와 같은 블록을 건드리므로 한 번에 처리해도 된다.** 둘 다 여백 조정을 요구하는데
따로 하면 같은 간격을 두 번 재게 된다.

첫 줄은 카드가 이미 보여주는 것을 다시 말한다 — 화살표 달린 링크 카드 3장이면 누르면
넘어간다는 것이 그림으로 설명된다.

**둘째 줄을 지워도 약속이 사라지지 않는다.** 같은 말이 세 군데에 더 있다 —
`FirstVisitNotice`(입력 화면), 폼 아래 한 줄("입력한 정보는 저장하지 않고, 풀이 생성에만
사용됩니다"), 그리고 `app/privacy/page.tsx`. **정보를 넣기 직전에 보여야 뜻이 있다**는 것이
TASK-30 에서 `FirstVisitNotice` 를 입력 화면으로 옮긴 이유이고, 이 줄은 아직 아무것도 넣지
않은 화면에 남아 있던 것이다. 처리방침 링크는 `SiteFooter` 가 모든 페이지에 깔아 두므로
`/` 에서 그 경로도 끊기지 않는다.

- [ ] `app/page.tsx` 의 해당 `<p>` 제거
- [ ] 카드 목록 아래 여백만 조정
- [ ] **`app/privacy/page.tsx` 는 손대지 않는다** — 데이터 흐름이 바뀌는 것이 아니라
      같은 말을 네 번 하던 것에서 하나를 줄이는 것이다

→ 완료 기준: `/` 에 그 두 줄이 없고 "저장하지 않는다" 안내는 입력 화면(`FirstVisitNotice`
· 폼 아래 한 줄)에 그대로 남아 있다. 검증 4종 통과.

### [TASK-36] 유형 선택 카드에 썸네일 이미지 · **(S)** · ⬜ 대기

카드 3장이 제목 + 한 줄 설명뿐이라 셋이 한 덩어리로 보인다.
[Unsplash](https://unsplash.com/ko) 에서 유형마다 한 장씩 골라 붙인다.

**TASK-34·35 를 먼저 한다.** 셋 다 `app/page.tsx` 의 같은 블록이고, 문구를 정리한 뒤의
여백을 보고 카드 높이를 정해야 간격을 한 번만 맞춘다.

#### 반드시 지킬 것 — 이미지를 **내려받아 저장소에 둔다**

**Unsplash URL 을 그대로 `src` 에 넣지 말 것.** 핫링크하면 방문자 브라우저가 Unsplash 로
직접 요청을 보내고, 그 순간 **IP·User-Agent 가 새 제3자에게 전달된다.**
`app/privacy/page.tsx` 4항(제3자 전송)에는 Google·Vercel 둘만 적혀 있으므로 사업자가 하나
느는 것이고, 5항의 "방문자 분석 도구를 전혀 쓰지 않습니다" 와도 결이 어긋난다
(Unsplash 는 이미지 요청으로 조회를 집계한다). **파일로 받아 커밋하면 제3자가 늘지 않아
처리방침을 손대지 않아도 된다.** 파비콘·og 카드와 같은 방식이다.

- `next.config.ts` 에 `images.remotePatterns` 를 추가하지 않는다 — 그게 필요해졌다면
  핫링크하고 있다는 뜻이다.
- 지금 저장소에 **`public/` 이 없다.** 이 태스크에서 처음 만들게 되므로 `README.md` 의
  구조 그림에도 함께 넣는다.

#### 작업

- [ ] 유형마다 한 장씩 고른다. **사람이 크게 나오는 사진을 피한다** — 특정 인물이 서비스의
      얼굴처럼 읽히고, 체질·다이어트 카드에 몸이 나오면 체형 규범으로 읽힌다.
      정물·자연·질감 쪽이 안전하다.
- [ ] Unsplash 라이선스는 출처 표기가 의무가 아니지만 **사진마다 촬영자와 원본 URL 을
      `docs/` 에 기록한다.** 교체할 때 어디서 왔는지 모르면 다시 못 찾는다.
- [ ] `public/` 에 넣고 **webp 로 변환**한다. 카드 폭이 최대 672px(`max-w-2xl`)이므로 2배인
      1344px 이면 충분하다. og 카드 45KB 를 기준선 삼아 **장당 100KB 를 넘기지 않는다** —
      첫 화면이 정적이라는 이점을 사진 셋으로 날리지 말 것.
- [ ] `next/image` 로 넣고 `width`·`height` 를 주어 레이아웃 이동(CLS)을 막는다.
      **`priority` 는 첫 카드에만** 준다 (셋 다 주면 우선순위가 없는 것과 같다).
- [ ] `alt` 에 유형 라벨을 되풀이하지 않는다 — 바로 옆에 제목이 있어 스크린리더가 같은 말을
      두 번 읽는다. 사진이 정보를 나르지 않으면 `alt=""` 로 장식임을 밝힌다.
- [ ] **사진 위에 글자를 얹지 않는다.** 얹으려면 대비 4.5:1 을 사진마다 따로 재야 하는데
      `lib/design/tokens.test.ts` 의 대비 검사는 **사진 위 글자를 잴 수 없다.**
      제목·설명은 지금처럼 사진 옆이나 아래의 단색 면에 둔다.

#### 손대지 않을 것

- **og:image 는 그대로 둔다** (`app/opengraph-image.png`). 사진으로 바꾸려면
  `docs/og-card.html` 원본과 팔레트 검사까지 함께 손봐야 하고, 지금 카드는 서비스 소개용으로
  이미 자리를 잡았다.
- **결과 화면에는 사진을 넣지 않는다.** 거기 그림 넷은 데이터 도식이고(TASK-25),
  장식 사진이 섞이면 어느 것이 근거인지 흐려진다.

→ 완료 기준: 카드 3장이 서로 다른 이미지를 달고 나오며 셋 다 `public/` 에서 나간다.
`next.config.ts` 에 원격 이미지 설정이 없고 네트워크 요청에 `unsplash.com` 이 없다.
장당 100KB 이하이며 출처가 `docs/` 에 적혀 있다. 검증 4종 통과.

### [TASK-33] 삼합·방합을 세력 판정에 반영 · **(O)** · ⏸ 보류

TASK-32 와 같은 사례에서 확인된 두 번째 누락. `1999-12-09 22:12` 은 지지가
**해(亥) · 묘(卯) · 미(未)** 로 **삼합 목국(木局)** 을 온전히 이룬다 — 지지 4개 중
3개이고 왕지 묘까지 갖췄다. 삼합을 보는 앱에서는 이 세 글자가 묶여 목으로 작동하므로
일간 을목이 자기 오행 덩어리 위에 앉은 형국이 되고, 신약이 나올 수가 없다.
지금 코드에는 합충 로직이 **전혀 없다.**

**보류 이유**: 성립 조건을 우리가 정해야 해서 "우리 관례" 가 크게 는다 — 합화(合化)
인정 여부, 글자 사이 거리, 반합 처리, 쟁합·투합, 그리고 월령이 국의 오행이 아닐 때
(이 사례가 그렇다 — 월지가 자수다) 화(化)를 어디까지 볼 것인가. `CLAUDE.md` 의
"고전 규칙과 우리 관례를 섞지 말 것" 에 정면으로 걸린다.

**TASK-32(통근)로 이 사례는 해결됐다** — `1999-12-09 22:12` 이 `약간 신강` 으로 나온다.
그 뒤에도 실측에서 어긋나는 사주가 남는지 보고 착수 여부를 판단한다. 근거 없이 관례를
늘리지 않기 위한 순서다.

→ 완료 기준: 착수 시 정한다. 최소한 위 조건 목록 각각에 대해 어느 쪽을 택했는지와
그것이 고전인지 우리 관례인지를 `docs/saju-validation.md` 가 밝혀야 한다.
