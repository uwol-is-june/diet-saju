### [TASK-37] 국내 출생지 선택 UI (경도 보정) · **(S)** · ⬜ 대기

**이 순서인 이유**: 번호는 가장 뒤지만 맨 위에 둔다. TASK-34~36 은 문구·장식이고
이건 **지금 서울 밖에서 태어난 사람에게 틀린 시주가 나가는** 문제다. TASK-32 를 맨 위에
둔 것과 같은 이유다. 건드리는 파일도 거의 겹치지 않는다(`lib/form/`·`components/SajuForm`
vs `app/page.tsx`).

API 는 `longitude` 를 이미 받는데 UI 가 없어 **전국이 서울(126.9784°) 고정**이다.
`docs/saju-validation.md` "남은 한계" 3번에 적혀 있던 것을 이제 닫는다.

#### 무엇이 틀리는가 (실측)

년주·월주는 **영향 없다** — 절기 판정은 절대 시각으로 하므로 출생지와 무관하다
(84건 검사, 차이 0). 흔들리는 것은 일주·시주뿐이다.

| 출생지 | 보정량 | 시주가 갈리는 비율 | 일주가 갈리는 비율 |
| --- | --- | --- | --- |
| 서울 (기본값) | −32분 | — | — |
| 인천 | −33분 | 0.8% | 0.07% |
| 대전 | −30분 | 1.7% | 0.14% |
| 대구 | −26분 | 5.0% | 0.42% |
| 부산 | −24분 | **6.7%** | 0.56% |
| 울릉도 | −16분 | 13.3% | 1.11% |

부산 출생이면 **15명 중 1명꼴로 시주가 틀린다.** 비율은 낮지만 **일주가 갈리는 쪽이 더
아프다** — 일간이 바뀌면 십신·신강신약·체질 판정이 통째로 달라진다.

#### 결정 — 목록 단위는 **시/군 + 광역시 통째** (약 170행)

광역 안에서 동서 끝이 벌어지는 폭을 재고 정했다.

| 구역 | 경도 폭 | 시각차 | 시지가 갈리는 비율 |
| --- | --- | --- | --- |
| 서울 (강서~강동) | 0.27° | 1.1분 | 0.8% |
| 부산 (강서~기장) | 0.37° | 1.5분 | 0.8% |
| 경기도 (김포~가평) | 0.80° | 3.2분 | 2.5% |
| 경상북도 (울릉 제외) | 1.24° | 5.0분 | 4.2% |
| 강원도 (철원~강릉) | 1.59° | 6.4분 | 5.8% |

- **구까지 나누지 않는다.** 광역시 안에서 구를 구분해 얻는 것은 0.8%p 뿐이라 구 목록
  25개씩을 유지할 값이 안 나온다.
- **시/도 17개만으로도 안 된다.** 강원을 한 덩어리로 두면 5.8% 가 남는데, 이건 지금
  고치려는 문제(6.7%)와 거의 같은 크기다. 절반도 못 고친다.
- 도(道) 지역만 시/군까지 받으면 잔차가 어디서나 **1% 안쪽**으로 들어온다.

#### 좌표표의 출처를 반드시 남긴다

서머타임·표준자오선은 Node 내장 tz 데이터를 써서 "표를 손으로 만들지 말 것"을 지켰지만,
**행정구역 좌표는 그런 내장 소스가 없다.** 약 170행을 저장소에 커밋해야 한다.

- [ ] 공개 출처(행정안전부 행정구역 자료·국토지리정보원 등)에서 받고 **어느 자료의 몇 년도
      판인지**를 표 파일 주석과 `docs/saju-validation.md` 에 적는다. 눈대중으로 채우지 말 것.
- [ ] 표는 `lib/form/` 아래 **클라이언트 안전 모듈**로 둔다 (`server-only` 붙이지 않는다).

#### 작업

- [ ] 지역 표 + 조회 함수 추가. 값은 `sajuInputSchema.longitude` 범위(124~132) 안에 있어야
      한다 — 울릉군 130.9° 도 들어온다.
- [ ] `BirthInput` 에 출생지 필드 추가. **기본값은 미선택이고, 미선택이면 지금과 똑같이
      서울 기본값으로 계산된다** — 기존 사용자의 결과가 조용히 바뀌면 안 된다.
- [ ] 폼에 2단계 선택(시/도 → 시/군)을 넣는다. 광역시·특별시는 2단계가 없다.
- [ ] **시각 미상이면 비활성화한다.** `pillars.ts` 가 시각을 모를 때 보정을 강제로 끄므로
      (`solarTimeMode = timeUnknown ? "standard" : …`) 출생지를 골라도 결과가 안 바뀐다.
      고를 수 있게 두면 반영되는 줄 안다. 고급 설정에서 `보정 없음` 을 고른 경우도 같다.
- [ ] 접힌 폼 요약(`describeBirthInput`)에 출생지를 **넣는다.** 이름을 뺀 것과는 경우가
      다르다 — 이름은 계산에 안 쓰이지만 출생지는 잘못 고르면 결과가 틀리므로 확인이 필요하다.
- [ ] 결과의 `CorrectionNote` 가 어느 지역 기준으로 보정했는지 보여준다.
- [ ] `docs/saju-validation.md` — "남은 한계" 3번을 닫고, 위 실측 표와 목록 단위 결정
      근거를 3-2 절 옆에 남긴다. **해외 출생은 여전히 한계로 남긴다** (아래).

#### 개인정보 — 같은 커밋에서 반드시 확인할 것

**출생지는 개인정보다.** 지금 방침 문서가 약속하는 것과 어긋나지 않는지 세 곳을 본다.

- [ ] `app/privacy/page.tsx` **1항(처리하는 정보)** 의 "선택" 목록에 출생지를 넣는다.
- [ ] **4항(제3자 전송)** — 프롬프트가 이미 `correctionMinutes` 를 보낸다
      ("시계시에서 −32분 보정 완료"). 지금은 전국이 −32라 아무것도 새지 않지만,
      **이 태스크 뒤에는 그 숫자가 출생 지역을 도 단위로 알려준다.** 지역명 자체를
      프롬프트에 넣지 않더라도 이 사실은 그대로이므로 4항 문구를 검토한다.
- [ ] `lib/observability.ts` 의 `METRIC_FIELDS` 에 **넣지 않는다.** 넣으면 6항 목록도
      고쳐야 하고, 개인을 좁히는 값이라 애초에 로그에 남길 이유가 없다.

#### 범위 밖 — 해외 출생

스키마가 경도를 124~132°(한반도)로 제한하고 `wallClockToUtc` 가 `Asia/Seoul` 고정이라,
해외 출생자가 현지 시계시를 넣으면 한국 시각으로 취급돼 결과가 크게 틀린다. 이건 경도
하나로 안 되고 **시간대 이력**까지 필요하며 "한국 만세력" 이라는 전제도 흔든다.
이 태스크에서 건드리지 말고 한계로 남긴다.

→ 완료 기준: 출생지를 고르면 `timeCorrection.correctionMinutes` 가 그 지역 값으로 바뀌고,
**고르지 않으면 지금과 동일한 결과**가 나온다. 시각 미상이면 고를 수 없다. 좌표표의 출처가
문서에 적혀 있고 처리방침 1항이 갱신돼 있다. `npm run validate:saju` 를 포함한 검증 4종 통과.

### [TASK-36] 유형 선택 카드에 썸네일 이미지 · **(S)** · ⬜ 대기

카드 3장이 제목 + 한 줄 설명뿐이라 셋이 한 덩어리로 보인다.
[Unsplash](https://unsplash.com/ko) 에서 유형마다 한 장씩 골라 붙인다.

**TASK-34·35 를 먼저 한다.** 셋 다 `app/page.tsx` 의 같은 블록이고, 문구를 정리한 뒤의
여백을 보고 카드 높이를 정해야 간격을 한 번만 맞춘다.

#### 반드시 지킬 것 — 이미지를 **내려받아 저장소에 둔다**

**Unsplash URL 을 그대로 `src` 에 넣지 말 것.** 핫링크하면 방문자 브라우저가 Unsplash 로
직접 요청을 보내고, 그 순간 **IP·User-Agent 가 새 제3자에게 전달된다.**
`app/privacy/page.tsx` 4항(제3자 전송)에는 Google·Vercel 둘만 적혀 있으므로 사업자가 하나
느는 것이고, 5항의 "방문자 분석 도구를 전혀 쓰지 않습니다" 와도 결이 어긋난다
(Unsplash 는 이미지 요청으로 조회를 집계한다). **파일로 받아 커밋하면 제3자가 늘지 않아
처리방침을 손대지 않아도 된다.** 파비콘·og 카드와 같은 방식이다.

- `next.config.ts` 에 `images.remotePatterns` 를 추가하지 않는다 — 그게 필요해졌다면
  핫링크하고 있다는 뜻이다.
- 지금 저장소에 **`public/` 이 없다.** 이 태스크에서 처음 만들게 되므로 `README.md` 의
  구조 그림에도 함께 넣는다.

#### 작업

- [ ] 유형마다 한 장씩 고른다. **사람이 크게 나오는 사진을 피한다** — 특정 인물이 서비스의
      얼굴처럼 읽히고, 체질·다이어트 카드에 몸이 나오면 체형 규범으로 읽힌다.
      정물·자연·질감 쪽이 안전하다.
- [ ] Unsplash 라이선스는 출처 표기가 의무가 아니지만 **사진마다 촬영자와 원본 URL 을
      `docs/` 에 기록한다.** 교체할 때 어디서 왔는지 모르면 다시 못 찾는다.
- [ ] `public/` 에 넣고 **webp 로 변환**한다. 카드 폭이 최대 672px(`max-w-2xl`)이므로 2배인
      1344px 이면 충분하다. og 카드 45KB 를 기준선 삼아 **장당 100KB 를 넘기지 않는다** —
      첫 화면이 정적이라는 이점을 사진 셋으로 날리지 말 것.
- [ ] `next/image` 로 넣고 `width`·`height` 를 주어 레이아웃 이동(CLS)을 막는다.
      **`priority` 는 첫 카드에만** 준다 (셋 다 주면 우선순위가 없는 것과 같다).
- [ ] `alt` 에 유형 라벨을 되풀이하지 않는다 — 바로 옆에 제목이 있어 스크린리더가 같은 말을
      두 번 읽는다. 사진이 정보를 나르지 않으면 `alt=""` 로 장식임을 밝힌다.
- [ ] **사진 위에 글자를 얹지 않는다.** 얹으려면 대비 4.5:1 을 사진마다 따로 재야 하는데
      `lib/design/tokens.test.ts` 의 대비 검사는 **사진 위 글자를 잴 수 없다.**
      제목·설명은 지금처럼 사진 옆이나 아래의 단색 면에 둔다.

#### 손대지 않을 것

- **og:image 는 그대로 둔다** (`app/opengraph-image.png`). 사진으로 바꾸려면
  `docs/og-card.html` 원본과 팔레트 검사까지 함께 손봐야 하고, 지금 카드는 서비스 소개용으로
  이미 자리를 잡았다.
- **결과 화면에는 사진을 넣지 않는다.** 거기 그림 넷은 데이터 도식이고(TASK-25),
  장식 사진이 섞이면 어느 것이 근거인지 흐려진다.

→ 완료 기준: 카드 3장이 서로 다른 이미지를 달고 나오며 셋 다 `public/` 에서 나간다.
`next.config.ts` 에 원격 이미지 설정이 없고 네트워크 요청에 `unsplash.com` 이 없다.
장당 100KB 이하이며 출처가 `docs/` 에 적혀 있다. 검증 4종 통과.

### [TASK-33] 삼합·방합을 세력 판정에 반영 · **(O)** · ⏸ 보류

TASK-32 와 같은 사례에서 확인된 두 번째 누락. `1999-12-09 22:12` 은 지지가
**해(亥) · 묘(卯) · 미(未)** 로 **삼합 목국(木局)** 을 온전히 이룬다 — 지지 4개 중
3개이고 왕지 묘까지 갖췄다. 삼합을 보는 앱에서는 이 세 글자가 묶여 목으로 작동하므로
일간 을목이 자기 오행 덩어리 위에 앉은 형국이 되고, 신약이 나올 수가 없다.
지금 코드에는 합충 로직이 **전혀 없다.**

**보류 이유**: 성립 조건을 우리가 정해야 해서 "우리 관례" 가 크게 는다 — 합화(合化)
인정 여부, 글자 사이 거리, 반합 처리, 쟁합·투합, 그리고 월령이 국의 오행이 아닐 때
(이 사례가 그렇다 — 월지가 자수다) 화(化)를 어디까지 볼 것인가. `CLAUDE.md` 의
"고전 규칙과 우리 관례를 섞지 말 것" 에 정면으로 걸린다.

**TASK-32(통근)로 이 사례는 해결됐다** — `1999-12-09 22:12` 이 `약간 신강` 으로 나온다.
그 뒤에도 실측에서 어긋나는 사주가 남는지 보고 착수 여부를 판단한다. 근거 없이 관례를
늘리지 않기 위한 순서다.

→ 완료 기준: 착수 시 정한다. 최소한 위 조건 목록 각각에 대해 어느 쪽을 택했는지와
그것이 고전인지 우리 관례인지를 `docs/saju-validation.md` 가 밝혀야 한다.
