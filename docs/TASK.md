### [TASK-58] 파생 절 통합 — 같은 값을 네 이름으로 말하지 않는다 · **(O)** · ⬜ 대기

`lib/saju/constitution.ts` 의 판정 축 다섯 중 **셋이 파생값이라 새 정보가 0 이다.**

```
gainPattern (5) ─→ gainSite (2) ─┐
                                  ├→ dietApproach (4) ─→ movementKind (4)
metabolism (2) ──────────────────┘
gainPattern (5) ─→ mealSequence (5)
thermal (5) ─────→ 실행 조건 (독립)
```

독립 정보는 `gainPattern` · `metabolism` · `thermal` 셋이다. 그런데 `diet-method` 는 5절 중
4절이 각각 "판정된 이름을 그대로 쓰고 근거를 이어라" 를 시킨다 — **같은 값을 네 이름으로 네 번
다시 말하는 글**이 된다. 세 절쯤 읽으면 새 얘기가 안 나온다는 걸 알아채고, 그건 "뜬구름" 보다
**"돌려 말한다"** 로 느껴진다.

**이 순서인 이유:** 유일하게 **계약**을 고치는 태스크라 가장 비싸다. 그리고 위 넷을 먼저 하면
**이 태스크의 필요 여부 자체가 달라질 수 있다** — 분량과 장면이 들어가면 파생 절도 각자 다른
장면을 갖게 되어 반복이 덜 보일 수 있다. **재보고 판단한다.**

- [x] **먼저 실측했다** (TASK-53 · `docs/saju-validation.md` 3-6 절). 절 사이 단어 일치도는
      `diet` 0.025 · `gain-cause` 0.038 · **`diet-method` 0.045** 로, 예상대로 방법 유형이
      가장 높지만 **절대값이 너무 작아 이 지표만으로는 반복을 입증하지 못한다.**
      낱말이 겹치지 않아도 같은 얘기일 수 있다 — 파생 절은 **같은 판정을 다른 어휘로**
      돌려 말하므로 Jaccard 가 낮게 나온다. **그래서 이 태스크의 판단 근거는 지표가 아니라
      사람이 읽은 결과여야 한다.** 착수 시 `diet-method` 표본 12건을 통독하고, 닫든 열든
      그 판단을 문서에 남긴다.
- [ ] TASK-54~57 을 마친 뒤 `--label after` 표본으로 이 값을 **다시** 잰다. 분량과 장면이
      들어가면 파생 절도 각자 다른 장면을 갖게 되어 반복이 덜 보일 수 있다 (이 태스크의
      필요 여부 자체가 달라질 수 있다는 원래 판단).
- [ ] 반복이 확인되면 절을 **정보 축으로** 다시 가른다. 파생 셋을 한 절에서 **순서로 엮고**,
      독립 축(`thermal`)은 자기 절을 유지한다.
- [ ] **TASK-48(새 유형 `나에게 맞는 운동`)과 함께 결정한다.** 그쪽은 `movement` 절을 두 유형에
      남기고 지침만 가르는 설계다. 여기서 `movement` 를 다른 절로 접으면 그 설계가 달라진다 —
      **둘 중 하나를 먼저 하면 다른 하나를 다시 써야 한다.**
- [ ] 섹션 id 를 지우거나 합치면 `Record<ReadingSectionId, …>` 가 `SECTION_INSTRUCTION` 과
      **TASK-46 의 아이콘 표**에서 컴파일 오류로 잡아 준다. 그 오류를 따라간다.
- [ ] `ProgressNote` 의 몇/몇 이 계약에서 절 수를 세고 있으면 자동이다 — **확인할 것.**
- [ ] `prompt.test.ts` 의 "두 절 지침이 서로 다른 것을 요구하는지" 검사(TASK-44 방식)를 새 구성에
      맞게 다시 쓴다.
- [ ] `npm run lint` · `typecheck` · `test` · `build` 통과

→ 완료 기준: `diet-method` 의 절이 서로 다른 정보를 말한다(절 사이 단어 일치도가 기준선보다
내려간다). `diet-method` 와 `exercise` 의 지침이 여전히 서로 다른 것을 요구한다.
**또는 반복이 없다는 실측으로 이 태스크가 닫히고 그 근거가 문서에 남는다.**

### [TASK-60] 유형을 오가도 이미 받은 풀이를 다시 만들지 않는다 · **(S)** · ⬜ 대기

`BirthInputProvider` 가 들고 있는 것은 **입력값뿐**이라, 유형을 옮기면 `SajuForm` 이

그래서 `diet` → `gain-cause` → 다시 `diet` 로 돌아오면 **A 를 처음부터 다시 생성한다.**
`OtherReadingLinks` 가 유형 사이를 오가라고 만든 동선이므로 이 왕복은 예외가 아니라 기본 경로다.

"무료 등급 일일 한도" 표)이고, 이 재생성은 사용자가 이미 본 글을 만드느라 그 한도를 쓴다.

      - [ ] 이름을 키에 넣는다 — 호칭이 본문에 박히므로 이름만 바꿔도 다른 글이다.

### [TASK-45] 새 유형 `몸이 바뀌는 10년` — 대운 기반 시간축 · **(O)** · ⬜ 대기

지금 공개 유형 셋은 전부 **현재 시점의 원국**만 말한다. 시간축은 `diet` 의 "올해의 몸 흐름"
한 절뿐이고, 대운은 계산·표시되지만 **해석이 없다**. "20대엔 안 쪘는데 30대 들어 붙는다" 가
사용자가 실제로 하는 질문인데 지금 답할 수 있는 유형이 없다.

**이 순서인 이유:** 미사용 자산 중 새 관례가 가장 적게 늘어난다 — 하나뿐이다(아래).
`analyzeYearly` 의 작용 판정을 대운에 그대로 적용하는 것이고, 문구 표·금지 어휘 검사·
판정 블록 배치가 전부 세운 쪽에 이미 있다. `THEME_LABEL`(생활 영역)을 살리는 쪽은 근거
없는 새 대응표가 필요해 뒤에 둔다 (CLAUDE.md TASK-39 결정 ①).

- [ ] **먼저 정할 것 — 성별 미지정 처리.** `daeun === null` 이면 이 유형은 **성립하지 않는다**
      (대운 순행/역행이 성별로 정해지므로). 세운에는 없던 분기다. 성별을 이 유형에서만
      필수로 할지, 고를 수 없게 안내할지를 착수 전에 정한다. **임의로 순행을 정하지 말 것.**
- [ ] `lib/saju/decade.ts` — 현재 대운의 작용 판정. `analyzeYearly` 와 같은 규칙으로
      대운 오행이 `constitution.deficient` 를 채우는가 / `excess` 에 더하는가를 본다.
      - [ ] **`DaeunPeriod` 는 오행을 두 글자 문자열로 들고 있다** (`pillarOhaeng`, 예 `"금화"`).
            판정에 필요한 `Ohaeng[]` 가 없다. `analyzeYearly` 가 `gan`/`ji` 인덱스를 따로 받아

### [TASK-49] 결과 화면 즐길거리 — 스크롤 등장과 Motion 도입 판단 · **(S)** · ⬜ 대기

**이 순서인 이유:** 사용자가 먼저 꺼낸 항목이지만 **유일하게 도입 여부가 안 정해진 것**이라
뒤에 뒀다. 그리고 TASK-45·48 로 화면이 더 길어진 뒤에 보면 아래 "지금 깨져 있는 것" 을 그
화면에서 바로 확인할 수 있다.

**지금 깨져 있는 것 (이 태스크의 실제 동기)**

- [ ] `anim-*` 은 **mount 시점**에 재생된다. 결과 화면은 원국 → 도식 넷 → 풀이 순으로 길어서
      대운 타임라인은 스크롤해야 보이는데, 도착했을 땐 애니메이션이 이미 끝나 있다.
      **지금 도식 애니메이션의 절반은 아무도 못 본다.**

**먼저 CSS 로 되는 것부터 (라이브러리 없이)**

- [ ] `animation-timeline: view()` 로 뷰포트 진입 시 재생. **우리 키프레임이 `from` 만 쓰기
      때문에 미지원 브라우저에서는 그냥 최종 모습이 남는다** — 점진 향상이 공짜로 된다.
      `@supports` 로 감싸면 미지원 브라우저는 지금 동작 그대로다.
      - 지원 (2026-08): Chromium 115+ · Safari 26+ · **Firefox 는 아직 기본 비활성**(플래그).
        전역 약 84%. 착수 시 caniuse 로 다시 확인할 것.
- [ ] 스크롤 진행 바(`animation-timeline: scroll()`)도 같은 방식으로 CSS 만 있으면 된다.
      다만 `ProgressNote` 가 이미 몇/몇 을 알려주므로 **없어도 되는 축**이다.
- [ ] 여기까지로 위 항목이 해결되면 **Motion 없이 끝난다.** 아래는 CSS 로 안 되는 것만 남긴다.

**Motion 조사 결과 (motion.dev)**

Framer Motion 의 후속. MIT, React/JS/Vue. 진입점이 둘로 갈린다 (문서가 밝힌 Rollup 기준
수치이며, webpack 은 트리셰이킹이 약해 조금 더 커진다고 문서가 덧붙인다).

| 진입점 | 크기 | 하는 것 |
| --- | --- | --- |
| `motion/mini` 의 `animate` | **2.3kb** | tween·spring. 네이티브 브라우저 API 사용 |
| `animate` 하이브리드 | 18kb | 독립 transform, SVG path, 타임라인, CSS 변수 |
| `motion/react` 의 `motion` | **34kb** | 전부 |
| `m` + `LazyMotion` | 4.6kb + `domAnimation` 15kb (`domMax` 25kb) | 기능을 지연 로드 |

우리에게 값이 있는 것과 없는 것:

| 기능 | 판단 |
| --- | --- |
| `inView` · `whileInView` | **CSS `view()` 로 대체 가능** — 위쪽을 먼저 시도 |
| `AnimatePresence`(exit) | **CSS 로 불가.** 폼 접힘/펼침("수정"), 에러 배너, 결과 뒤 링크 |
| `layout`(높이 전환) | **CSS 로 사실상 불가.** 폼이 접힐 때 높이가 튄다 |
| `press`/`hover` 스프링 | 유형 선택 카드 눌림 — 다만 아래 `/` 제약에 걸린다 |
| `stagger` | 이득 없음 — 인라인 `animationDelay` 로 이미 하고 있다 |
| `useMotionValue` 카운트업 | 오행 **개수**(사실)에만. 점수는 우리 관례라 숫자로 내지 않는다 |

**도입한다면 지킬 것**

- [ ] **`/` 에는 쓰지 않는다.** 유형 선택 화면을 통째로 정적으로 두는 성질이 깨진다 —
      `SiteFooter` 를 클라이언트 컴포넌트로 만들지 않기로 한 것과 같은 판단이고, 이미
      테스트가 막고 있다.
- [ ] **`prefers-reduced-motion` 보장이 구조에서 설정으로 내려간다는 것을 알고 할 것.**
      지금은 CSS 한 규칙이 전역으로 막지만 Motion 은 `<MotionConfig reducedMotion="user">`
      를 씌워야 하고, 빠뜨리면 조용히 깨진다. 씌웠는지를 `lib/design/motion.test.ts` 가
      소스에서 검사한다.
- [ ] `motion/react` 전면 전환을 하지 않는다. 필요한 화면에서 `m` + `LazyMotion` 또는
      `motion/mini` 로 시작한다.
- [ ] 채택하면 `CLAUDE.md` "도식과 애니메이션" 절에 "차트 라이브러리는 안 넣지만 애니메이션
      라이브러리는 여기까지" 를 적는다. **채택하지 않으면 이 조사 결과를 `CLAUDE.md` 의
      "보류한 작업" 으로 옮긴다** — 같은 조사를 다시 하지 않기 위해서다.

→ 완료 기준: 스크롤해서 도착한 도식이 **그 자리에서** 재생되고, 모션 최소화 설정에서는 최종
모습이 즉시 보인다. Motion 은 채택 또는 보류 중 하나로 **결론이 문서에 적혀 있다.**

### [TASK-50] 유형 카드 썸네일 — 오행 모티프로 채우기 · **(S)** · ⬜ 대기

`/` 의 카드 썸네일은 지금 `--color-thumb-1..3` 단색 사각형이다. `app/page.tsx:32-41` 과
`globals.css:118-139` 이 "사진이 들어오기 전까지 쓰는 자리" 라고 적어 둔 그 자리를 채운다.

**스톡 사진(Pexels 등)은 쓰지 않기로 했다.** 이유 셋:

1. **크기가 안 맞는다.** 썸네일이 `size-14`(56×56px)다. 이 크기에서 사진은 무엇을 찍었는지
   알아볼 수 없는 색 덩어리가 된다. 사진을 살리려면 카드를 배너형으로 키워야 하는데,
   그러면 모바일에서 선택지 셋이 한 화면에 안 들어와 `/` 의 성질이 바뀐다.
2. **피사체가 이미 막아 둔 경계에 걸린다.** 사람 몸은 `내가 살이 찌는 이유` 옆에서 신체
   평가가 되고, 특정 음식 사진은 `ELEMENT_FOOD` 닫힌 목록을 **판정 코드 밖에서** 우회하며
   (프롬프트가 목록 밖 식품 이름을 금지하는 것과 같은 범주), 운동기구는 `MOVEMENT_PLAN` 이
   막는 강도·처방으로 읽힌다. 남는 피사체는 추상 질감뿐인데 그건 사진일 이유가 없다.
3. **팔레트 검사 밖이다.** `tokens.test.ts` 가 컴포넌트의 raw 색을 막는데 래스터 이미지는
   그 검사가 닿지 않는다.

**렌더한 PNG(`scripts/render-icons.mjs` 방식)도 쓰지 않는다.** 그 파이프라인이 있는 이유는
파비콘과 og:image 가 **반드시 래스터 파일이어야** 하기 때문이다(브라우저 탭·크롤러).
페이지 안의 장식에는 그 제약이 없으므로 **인라인 SVG 컴포넌트**로 만든다 — 요청이 늘지 않고,
어느 크기에서도 선명하며, `tokens.test.ts` 의 검사 목록에 넣으면 팔레트가 계속 지켜진다
(`components/charts/OhaengCycle.tsx` 가 이미 그렇게 돼 있다).

**이 순서인 이유:** 지금 화면이 틀린 값을 내고 있지 않다 — 자리는 이미 잡혀 있고 단색도
링크 카드로서 동작한다. 앞의 넷은 답할 유형이 없거나(45·48) 읽기 어려운(46·47) 문제이고,
이건 **비어 있지 않은 자리를 더 좋게** 만드는 일이라 맨 뒤다.

**TASK-45·48 뒤에 하는 편이 싸다.** 유형이 둘 늘어난 뒤에 하면 모티프를 한 번에 그린다 —
먼저 하면 새 유형이 들어올 때마다 `Record` 가 컴파일 오류로 한 칸씩 요구한다 (막히는 건
아니고, 작업이 세 번으로 쪼개질 뿐이다).

- [ ] `components/thumbnails/` — 유형별 SVG 하나씩. `components/charts/` 의 시각 언어를
      잇는다 (같은 도형 어휘를 쓰면 목록과 결과 화면이 한 서비스로 읽힌다).
      - [ ] `diet`(종합 체질) — 오각형. `OhaengCycle` 의 상생 오각형을 라벨 없이 축소한 모양.
      - [ ] `gain-cause`(원인) — 한쪽으로 치우친 막대 셋. `OhaengBars` 의 어휘.
      - [ ] `diet-method`(방법) — 순서를 나타내는 계단. 접근 순서(무엇을 먼저)를 뜻한다.
      - [ ] `general`(내부) — 목록에 안 나오지만 `Record` 라 값이 필요하다. 오각형 변형으로 둔다.
      - [ ] 위 넷은 **착수 시점의 유형**이다. TASK-45(`시기`) · 48(`운동`)이 먼저 들어갔으면
            그만큼 늘어난다 — `Record` 가 어느 칸이 비었는지 알려 준다.
- [ ] **`Record<ReadingType, …>` 로 둔다.** 지금 `THUMBNAIL_TONES` 는 배열이고 그건 맞았다
      (명도 차이일 뿐 유형과 무관했으므로). **모티프는 유형의 의미를 담으므로 배열이면
      새 유형이 조용히 남의 그림을 달고 나간다** — `buildShareCardModel` 칩이 TASK-15 에서
      그럴 뻔했던 것과 같은 함정이다. `Record` 여야 컴파일 오류로 잡힌다.
- [ ] 장식이므로 `aria-hidden` 을 유지한다. 링크의 접근 가능한 이름은 지금처럼 제목이 만든다.
      SVG 에 `focusable="false"` 도 함께 준다 (일부 브라우저에서 탭 순서에 끼어든다).
- [ ] `lib/design/tokens.test.ts` 의 `sources` 목록에 새 파일들을 추가한다. 추가하지 않으면
      SVG 의 `fill-*`·`stroke-*` 에 hex 가 새어 들어와도 아무도 모른다.
- [ ] **지울 곳 넷** — 목록은 `globals.css:118-136` 주석에 이미 있다.
      ① `--color-thumb-1..3` 토큰 ② `app/page.tsx` 의 `THUMBNAIL_TONES` 와 그 `<span>`
      ③ `tokens.test.ts` 의 `--color-thumb-*` 세 줄 ④ `docs/design-tokens.md` 의
      "유형 카드 썸네일 자리" 절 (지우지 말고 **모티프 절로 다시 쓴다**).
- [ ] `/` 가 **여전히 클라이언트 JS 없이 통째로 정적인지** 확인한다. SVG 는 서버 컴포넌트로
      두고 애니메이션을 붙이지 않는다 — 붙일 거면 `globals.css` 의 `anim-*` 규칙을 따른다
      (키프레임은 `from` 만).
- [ ] `npm run lint` · `typecheck` · `test` · `build` 통과

→ 완료 기준: 카드 셋이 서로 구분되는 모티프를 달고 있고, 새 유형을 `READING_TYPES` 에
넣으면 **썸네일을 정하라고 컴파일 오류가 난다.** `--color-thumb-*` 이 저장소에서 사라졌고
`tokens.test.ts` 가 새 SVG 파일들을 검사 목록에 담고 있다. `/` 에 클라이언트 JS 가 없다.
