# 개발 순서

1~3(내용·표현)이 4(도식화)보다 앞인 이유는 4 에서 체질·다이어트 판정을 그림으로 만들 텐데,
그리려면 내용이 먼저 굳어야 하기 때문이다.

1(다이어트 방법)과 2(음식)는 **같은 판정 모듈·같은 섹션 계약·같은 금지 어휘 검사**를 만진다.
따로 하면 `constitution.ts` 와 `SECTION_INSTRUCTION` 을 두 번 여는 셈이라 **이어서 한다.**

## 1. [TASK-24] 잘 맞는 다이어트 방법 추가 · **(O)** · ⬜ 대기

**이 순서인 이유**: 4번(도식화)에서 체질·다이어트 판정을 그림으로 만들 계획이라, 그리기 전에
내용이 굳어야 한다. 그리고 표현 가드레일 판단이 필요해 **(O)** 다.

`diet` 유형에 지금 있는 것은 `잘 맞는 식습관`·`잘 맞는 움직임` 이다. 여기에 **"어떤 방식으로
감량에 접근할 것인가"** 가 빠져 있다는 지적.

이미 재료가 있다 — `lib/saju/constitution.ts` 의 **대사 기조**(발산형/축적형)가 사실상
"쓰는 양을 늘리는 순서 vs 회복을 먼저 고정하는 순서" 를 가리키고 있다. 이걸 독립된 축으로
끌어올리는 작업이다.

- [ ] 다이어트 방식 축을 규칙표로 정의 — 대사 기조 + 한열 + 살이 붙는 패턴에서 결정론적으로.
      `constitution.ts` 의 고전/관례 구분 방식을 그대로 따를 것 (**새 축은 우리 관례**다)
- [ ] 축의 값을 정한다. 예: 활동량 우선 / 리듬 고정 우선 / 식사량 조절 우선 / 회복 우선
      — **동점 처리를 반드시 고정**한다 (안 하면 "같은 사주 = 같은 판정" 이 깨진다)
- [ ] 섹션 계약에 `## 잘 맞는 다이어트 방법` 추가 (`lib/reading/sections.ts`) +
      섹션 지침 추가 (`lib/prompt.ts` 의 `SECTION_INSTRUCTION`)
- [ ] 프롬프트 판정 블록에 새 축을 싣고 "다시 판정하지 말라" 규정 유지
- [ ] **표현 가드레일이 여기서 더 중요하다.** 감량 "방법" 은 의학·영양 조언에 가까워진다.
      금지 어휘 검사(`constitution.test.ts`)를 새 문구에도 적용하고, 단식·특정 식단 이름·
      칼로리 수치·목표 체중 같은 것을 넣지 않는다. 생활 습관 수준을 넘지 말 것
- [ ] `app/disclaimer/page.tsx` 의 "체질 판정은 명리학 오행 해석입니다" 절과 정합 확인.
      방법까지 제시하면 문구를 보강해야 할 수 있다
- [ ] 공유 카드 칩(`lib/share/card-model.ts`)에 넣을지 판단 — 넣으면 `CHIPS.diet` 수정

→ 완료 기준: 같은 사주에 항상 같은 다이어트 방식이 나오고, 금지 어휘 검사를 통과한다.

## 2. [TASK-27] 잘 맞는 음식 추가 · **(O)** · ⬜ 대기

**이 순서인 이유**: 1번과 같은 파일들을 만진다(`constitution.ts` 판정 · 섹션 계약 ·
`SECTION_INSTRUCTION` · 금지 어휘 검사). 이어서 하면 한 번만 연다. 그리고 **여기가 이
서비스에서 의학·영양 조언에 가장 가까이 가는 지점**이라 판단이 걸려 **(O)** 다.

지금 `잘 맞는 식습관`(`eating`) 섹션은 **먹는 방식**만 말한다 — 근거인 `FOCUS_GUIDE`·
`THERMAL_GUIDE` 에 식습관 문구는 있지만 **식품 이름이 하나도 없다.** "무엇을 먹으면
좋은가" 를 원한다는 요청이므로 판정에 딸린 **식품 후보 표**를 새로 만드는 작업이다.

**먼저 정할 것 — 새 섹션인가, `eating` 확장인가.** 새 섹션을 넣으면 diet 는 8절이 되고
생성 시간이 는다(현재 전체 4.2~4.4초). 방식(TASK-24)까지 더하면 9절이다. 셋을 어떻게
나눌지를 착수 시점에 한 번에 정할 것.

- [ ] 식품 후보 표를 규칙표로 정의 — 판정된 **과다·부족 오행**과 **한열**에서 결정론적으로.
      LLM 이 식품을 고르게 하지 않는다 (체질 판정과 같은 원칙)
- [ ] **고전/관례 구분을 적는다.** 오행-오미 배속(목=신맛·화=쓴맛·토=단맛·금=매운맛·수=짠맛)은
      고전이지만 **거기서 구체 식품을 고른 목록은 우리 관례**다. `docs/saju-validation.md` 에 명시
- [ ] **한의학 성미(性味) 용어를 노출하지 않는다.** 식품의 온·냉 성질표는 출처가 한의학인데
      `app/disclaimer/page.tsx` 는 "한의학 사상체질과 무관" 을 약속한다. 오행-장부 배속을
      감춘 것과 같은 이유로, 출처는 주석에 두고 노출은 생활어로 한다
      (예: "따뜻하게 조리해서" — "온성 식품" 이라고 쓰지 않는다)
- [ ] **효능을 말하지 않는다.** "○○에 좋은" · "○○를 돕는" 류 금지. 이미 `eating` 지침에
      "특정 식품을 치료제처럼 말하지 말 것" 이 있으니 그 선을 표 전체로 넓힌다
- [ ] **개인 변수를 모른다는 전제를 지킨다** — 알레르기·질환·복약·임신 여부를 입력받지 않는다.
      그래서 ① 특정 식품의 다량 섭취나 제한을 권하지 않고 ② 영양제·보조식품·상표명·
      다이어트 식단 이름을 넣지 않으며 ③ 칼로리·그램·목표 체중 수치를 쓰지 않는다.
      **"빼라" 보다 "곁들이면 좋다"** 쪽으로 쓴다
- [ ] 흔하고 구하기 쉬운 재료 범주로 한정한다 (특이 식재료는 실천 가능성도 낮다)
- [ ] 프롬프트에 후보 목록을 싣고 **"이 목록 밖의 식품 이름을 쓰지 말라"** 고 지시.
      판정과 마찬가지로 `계산 완료 · 수정 금지` 규정을 적용한다
- [ ] 금지 어휘 검사(`constitution.test.ts`)를 새 문구에 적용 + **식품 표 전용 검사 추가** —
      효능 어휘("좋다"류 포함 여부 판단) · 수치 · 상표명이 섞이지 않는지
- [ ] 섹션을 새로 만들면: `lib/reading/sections.ts` 계약 + `lib/prompt.ts` 의
      `SECTION_INSTRUCTION` + `prompt.test.ts` 의 "모든 섹션에 지침이 있는가" 검사
- [ ] `app/disclaimer/page.tsx` 문구 보강 판단 — 지금은 체질 "판정" 만 설명한다.
      먹을 것을 제시하면 영양·의학 조언이 아니라는 문장이 필요할 수 있다
- [ ] 공유 카드 칩(`lib/share/card-model.ts`)에 넣을지 판단

→ 완료 기준: 같은 사주에 항상 같은 식품 목록이 나오고, 목록 밖 식품이 본문에 등장하지
않으며, 금지 어휘·수치 검사를 통과한다.

## 3. [TASK-28] 문장 단위 줄바꿈으로 가독성 개선 · **(S)** · ⬜ 대기

**이 순서인 이유**: 본문 렌더 자체를 바꾸므로 **내용이 다 들어온 뒤**(1·2) 하는 것이 맞고,
4(도식화)이 얹힐 바탕이므로 그보다는 앞이다. 세 유형 전부에 영향을 준다.

지금 풀이 본문이 한 문단에 여러 문장이 붙어 나와 벽처럼 읽힌다. 마침표 단위로 끊어 달라는 요청.

**함정: 프롬프트만 고쳐서는 안 된다.** `react-markdown` 은 CommonMark 라 **단일 개행을
줄바꿈으로 렌더하지 않는다** (`remark-breaks` 등 플러그인 없음 — `package.json` 확인).
모델이 문장마다 개행해도 화면에서는 공백 하나로 붙는다.

- [ ] 방식 결정 — ① `remark-breaks` 추가 + 프롬프트에서 문장마다 개행 ② 렌더 직전 문자열
      후처리로 마침표 뒤 개행 삽입 ③ 빈 줄로 문단을 자주 나누라고만 지시(플러그인 불필요,
      지금도 동작하지만 문단 간격이 커진다)
- [ ] ②를 고르면 **마침표가 문장 끝이 아닌 경우**를 전부 막는다 — `3.5kg` 같은 소수점,
      `1. 항목` 순서 목록, 영문 약어. 목록 줄(`- `)과 제목 줄에는 적용하지 않는다
- [ ] **스트리밍 중에 줄이 튀지 않아야 한다.** 파서는 누적 문자열을 매 조각 다시 파싱하므로
      후처리도 매번 다시 돈다. 마지막 문장이 잘려 오는 동안 커서 앞에서 줄이 접혔다 펴지는지 확인
- [ ] **폴백 경로에도 같은 처리를 건다** — `recognized === false` 일 때 원문 마크다운을 그대로
      그리는 분기(`ReadingSections.tsx`)가 따로 있다. 한쪽만 고치면 화면이 갈린다
- [ ] `.reading p` 의 여백을 다시 본다 (`globals.css`: `line-height: 1.75`,
      `margin-bottom: 0.75rem`). 문장마다 끊으면 리듬이 달라져 지금 값이 안 맞을 수 있다
- [ ] **모바일 폭에서 실측** — 한 문장이 한 줄에 안 들어가면 문장 단위 개행이 오히려
      들쭉날쭉해 보인다. 390px 에서 확인하고 안 되면 문단 단위로 물러설 것
- [ ] 공유 카드(`lib/share/draw-card.ts`)는 캔버스에서 자체 줄바꿈을 한다 — 원문 개행이
      늘 때 카드 레이아웃이 깨지지 않는지 확인
- [ ] 섹션 제목·요약 카드는 그대로 둔다 (`.reading` 은 본문에만 붙는 규칙 유지)

→ 완료 기준: 390px·1280px 양쪽에서 문장이 시각적으로 구분되고, 스트리밍 중 줄이 튀지 않으며,
소수점·순서 목록이 깨지지 않는다.

## 4. [TASK-25] 도식화와 애니메이션 · **(O)** · ⬜ 대기

**마지막인 이유**: 위 세 개가 레이아웃과 내용을 바꾼다. 지금 그림을 얹으면 곧 고칠 것 위에
그리게 된다. 대신 **작업량이 가장 크고 사용자가 중요하다고 말한 항목**이라, 착수하면
범위를 먼저 좁혀 한 덩어리씩 낼 것.

지금 결과 화면은 숫자와 글자뿐이다. 사주는 관계(상생·상극)와 흐름(대운·세운)이 핵심인데
둘 다 그림이 훨씬 잘 전달한다.

- [ ] 범위 결정 — 후보: ① 오행 상생·상극 오각형(관계도) ② 오행 분포 차트 ③ 대운 타임라인
      ④ 한열 눈금(−2~+2) ⑤ 섹션이 도착할 때의 등장 트랜지션
      **한 번에 다 하지 말고 우선순위를 정할 것**
- [ ] 차트 라이브러리를 넣지 않고 **인라인 SVG** 로 구현하는 방향을 먼저 검토
      (번들 비용 + 색을 CSS 토큰에서 읽어야 하는 제약)
- [ ] 색은 시맨틱 토큰만 쓴다. `lib/design/tokens.test.ts` 가 컴포넌트의 raw hex 를 막으므로
      새 컴포넌트를 그 검사 목록에 추가할 것
- [ ] **애니메이션은 `prefers-reduced-motion` 을 존중한다** — `app/globals.css` 에 전역 규칙이
      이미 있으니 그것으로 꺼지는지 확인하고, 안 꺼지는 방식(JS 애니메이션)을 쓰면 직접 분기
- [ ] **스트리밍과 싸우지 않게 한다.** 섹션은 도착하는 대로 렌더된다 — 등장 애니메이션이
      매 조각마다 재생되면 글이 떨리게 보인다. 섹션이 `complete` 될 때 한 번만 재생할 것
- [ ] 공유 카드(`lib/share/draw-card.ts`)와 시각 언어를 맞춘다. 화면과 카드가 달라 보이면 어색하다
- [ ] 다크 모드는 도입하지 않는다 (확정 사항). 밝은 톤 하나만 맞추면 된다
- [ ] 실기 확인 — 모바일 폭에서 도식이 잘리지 않는지, 가로 스크롤이 생기지 않는지

→ 완료 기준: 원국과 대운을 글자 없이도 읽을 수 있고, 모션 최소화 설정에서 정지 상태로 보인다.

## 5. [TASK-26] 파비콘·앱 아이콘 추가 · **(H)** · ⬜ 대기

**요청받은 항목이 아니다** — TASK-10 배포 검증 중에 발견해 적어 둔다. 우선순위는 낮다.

`/favicon.ico`, `/icon.png`, `/apple-touch-icon.png` 가 모두 404 이고 `app/` 에 아이콘 파일이
없다. 브라우저 탭·카카오톡 공유·홈 화면 추가에서 기본 아이콘으로 뜬다.

- [ ] `app/icon.png` (또는 `icon.svg`) 추가 — Next 가 자동으로 메타 태그를 붙인다
- [ ] `app/apple-icon.png` 추가 (홈 화면 추가용)
- [ ] og 카드(`docs/og-card.html`)와 같은 시각 언어로 만들 것

→ 완료 기준: 세 경로가 404 를 내지 않고 탭에 아이콘이 보인다.
