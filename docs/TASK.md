### [TASK-46] 섹션 제목 앞에 아이콘 · **(H)** · ⬜ 대기

절이 다섯 개까지 늘면서 한 카드 안 구분선만으로는 어디서 화제가 바뀌는지 잘 안 보인다.
제목 앞에 아이콘을 하나씩 붙여 훑을 때 걸리게 한다.

**이 순서인 이유:** 아래 셋 중 가장 싸고, `SECTION_ICON` 을 `Record` 로 먼저 만들어 두면
TASK-45·48 이 새 섹션을 넣을 때 아이콘 누락이 **컴파일 오류로 잡힌다.** 뒤로 미루면 그때
가서 늘어난 섹션을 한꺼번에 훑어야 한다.

- [ ] **`title` 에 이모지를 섞지 않는다.** 제목 문자열은 프롬프트와 파서의 **단일 소스**라,
      계약을 `## 🌿 오행으로 본 체질` 로 바꾸면 모델이 그 이모지까지 글자 하나 틀리지 않게
      재현해야 파싱된다. 어긋나는 순간 그 절이 `id: null` 로 떨어져 **아이콘도 강조도 함께
      사라진다.** 아이콘은 계약이 아니라 **화면에서만** 붙인다.
- [ ] `lib/reading/sections.ts` 에 `SECTION_ICON: Record<ReadingSectionId, string>` 를 둔다.
      `ReadingSectionSpec` 의 선택 필드로 두면 새 섹션이 조용히 아이콘 없이 나간다 —
      `Record` 여야 컴파일 오류로 잡힌다 (`READING_TYPES` 를 `Record` 로 두는 이유와 같다).
- [ ] `components/ReadingSections.tsx` 의 제목 **두 곳**(요약 카드 `h2` · 절 `h2`)에 붙인다.
      아이콘은 `aria-hidden` — 스크린리더가 "나뭇잎 오행으로 본 체질" 로 읽으면 안 된다.
- [ ] 계약에 없는 제목(`id: null`)과 **원문 폴백 경로**는 아이콘 없이 그대로 둔다.
      거기서는 어느 절인지 모르므로 붙일 근거가 없다.
- [ ] 공유 카드(`lib/share/draw-card.ts`)에는 넣지 않는다. 캔버스 이모지는 OS 폰트에 따라
      두부(□)가 되고, 카드에 절 제목이 들어가지도 않는다.
- [ ] 이모지는 흑백 폴백이 있는 흔한 것만 고른다. 이형자 선택자가 필요한 문자(`⚖️` 등)는
      선택자를 붙인 채로 저장한다 — 빼면 플랫폼에 따라 글자 모양으로 나온다.
- [ ] 검사(`lib/reading/sections.test.ts`): 모든 섹션 id 에 아이콘이 있고, `SECTION_SPECS` 의
      `title` 에는 한글·공백 밖의 문자가 없다.

→ 완료 기준: 결과 화면에서 절마다 다른 아이콘이 제목 앞에 보이고, `SECTION_SPECS` 의
`title` 에는 이모지가 하나도 없다. **프롬프트로 나가는 제목 문자열이 지금과 같다.**

### [TASK-47] 판정 한 줄 콜아웃 — "많이 먹어서 찐 살" · **(S)** · ⬜ 대기

`내가 살이 찌는 이유` 는 다 읽어야 결론이 잡힌다. 판정된 결을 **한 줄 라벨**로 먼저 띄운다.

**이 순서인 이유:** TASK-48(운동 유형)의 핵심이 "종목을 콜아웃으로 알려주는 것" 이라 이
계약을 그대로 쓴다. 뒤에 하면 콜아웃이 두 벌이 된다.

- [ ] **문구는 코드가 고른다.** `lib/saju/constitution.ts` 에
      `GAIN_LABEL: Record<GainPattern, string>` 를 두고 `gainLabel` 로 내보낸다.
      `gainPattern` 은 십신 우세 그룹에서 이미 결정론적으로 나오므로 **새 동점 처리가 필요
      없다** (`MOVEMENT_PLAN`·`MEAL_PLAN` 을 1:1 파생으로 둔 것과 같은 이유).
      문안 초안 — 식욕형 `많이 먹어서 찐 살` · 정체형 `덜 움직여서 붙은 살` ·
      불규칙형 `때를 놓쳐서 붙은 살` · 스트레스형 `긴장이 부른 살` ·
      근육형 `무게가 함께 늘어난 살`. (착수 시 확정)
- [ ] **LLM 이 쓰게 하지 않는다.** 콜아웃은 `chart` 이벤트 값으로 직접 그린다. 근거 둘 —
      ① 판정은 코드가 한다는 경계 ② `chart` 는 60~70ms 에 오고 첫 글자는 1초 뒤다.
      **기다리는 동안 결론 한 줄이 먼저 떠서 볼거리가 생긴다.**
- [ ] `components/VerdictCallout.tsx` 신설. `ResultView` 가 `ReadingSections` **바로 위**에 둔다.
- [ ] 어느 유형이 무엇을 강조하는지는 `Record<ReadingType, (chart) => Callout | null>` 로
      (`prompt.ts` 의 `VERDICT_BLOCK` 과 같은 모양). 지금 값을 내는 것은 `gain-cause` 뿐이다.
      **삼항·인덱스 시그니처로 두지 말 것** — 새 유형이 조용히 남의 콜아웃을 달고 나간다.
- [ ] 콜아웃은 **라벨 + 근거 한 줄**이다. 라벨만 크게 띄우면 "당신은 많이 먹어서 찐다" 는
      확정 진술이 되어 `gain-cause` 의 표현 규칙(**원인 확정 금지**)과 정면으로 부딪힌다.
      밑줄에 판정 근거(십신 우세 그룹 · 걸리는 지점)와 "이 사주에서 읽히는 결" 이라는 범위
      문장을 함께 둔다.
- [ ] 프롬프트에도 같은 라벨을 주되 **본문에서 그 문장을 되풀이하지 말라**고 지시한다.
      화면 위아래에 같은 말이 두 번 나오면 안 된다 (`prompt.test.ts` 가 지시 존재를 확인).
- [ ] `constitution.test.ts` 의 금지 어휘·숫자 검사에 `GAIN_LABEL` 을 넣는다 — 사용자에게
      그대로 나가는 문구다. 단정 어투(`때문에`)도 함께 본다.
- [ ] 색은 시맨틱 토큰만 쓴다. `lib/design/tokens.test.ts` 의 raw 색상 검사 목록에 새
      컴포넌트를 추가한다.

→ 완료 기준: `/reading/gain-cause` 에서 원국이 도착하는 즉시 라벨 콜아웃이 뜨고, 같은 사주면
항상 같은 라벨이 나오며, 풀이 본문이 그 문장을 그대로 반복하지 않는다.

### [TASK-48] 새 유형 `나에게 맞는 운동` · **(O)** · ⬜ 대기

`diet-method` 가 **무엇을 어떤 순서로** 를 다루는 데 비해, 이 유형은 **어떤 운동을** 하나로
좁혀 콜아웃으로 보여준다.

**이 순서인 이유:** 콜아웃 계약(TASK-47)이 선행이다. 그리고 판정 축을 어떻게 만드느냐가 이
태스크의 대부분이라 **(O)** 다 — 잘못 만들면 같은 사주에 다른 종목이 나온다.
**TASK-45 와 동시에 진행하지 말 것** — 둘 다 `Record<ReadingType, …>` 를 전부 건드린다.

착수 전에 읽을 것: `CLAUDE.md` 의 "체질 판정" · "리딩 유형을 늘릴 때".

**판정 설계**

- [ ] **종목은 새 판정 축이 아니라 `MOVEMENT_PLAN` 의 필드로 붙인다.** `movementKind` 는
      `dietApproach`(2×2)에서 1:1 로 나와 이미 결정론적이므로, 칸에 `primary`(대표 종목) ·
      `alternatives` 를 더하면 **새 동점 처리가 필요 없다.**
- [ ] 콜아웃 문장은 **두 층을 각자의 표에서 가져와 합친다.**
      종목 = `MOVEMENT_PLAN`(접근 순서 층) · 실행 조건(시간대·온도) = `THERMAL_GUIDE`(한열 층).
      4 × 5 = 20가지 문장이 나오면서도 층은 섞이지 않는다.
- [ ] **종목 선택에 한열을 넣지 말 것.** `APPROACH_TABLE` 이 같은 이유로 한열을 빼 뒀다 —
      넣으면 칸이 20개가 되어 각 칸의 근거를 설명할 수 없다. 한열은 "언제·어떤 온도로" 다.
- [ ] 검토했다가 접은 안: 부족 오행(`BODY_AXIS`)으로 종목을 가르기. 부족 오행이 여럿이거나
      아예 없을 수 있어 **동점 처리를 새로 만들어야 하고** 표가 24칸이 된다. 되살리려면
      동점 규칙(오행 고정 순서 등)을 먼저 정하고 `docs/saju-validation.md` 에 "우리 관례" 로
      적을 것.
- [ ] 표현 경계는 (B) 일부 개방 그대로 — **종목 이름과 강도의 결까지 열고, 수치는 계속
      막는다**(횟수·세트·분·심박수·기간). `MOVEMENT_PLAN.how` 가 이미 걷기·계단 오르기·
      스트레칭을 쓰고 있으므로 종목 이름 자체는 새로 여는 것이 아니다.

**유형 배선**

- [ ] id `exercise` · 라벨 `나에게 맞는 운동` · 공개. `READING_TYPES` 순서(=UI 순서)는
      결 → 원인 → 방법 → **운동** (TASK-45 가 먼저 들어가 있으면 그 뒤).
- [ ] 섹션 id 를 `diet-method` 와 **공유하지 않는다.** `SECTION_INSTRUCTION` 이 id 로 매기므로
      공유하면 맥락이 다른 두 유형이 한 지시문을 떠안는다.
      안: `exercise-pick`(왜 이 운동인가) · `exercise-how`(어떤 결로 움직일까) ·
      `exercise-when`(언제 하면 좋을까) · `exercise-avoid`(무리가 되는 지점) ·
      `exercise-start`(이번 주에 시작할 한 가지).
- [ ] **`diet-method` 의 `movement` 절은 떼어 오지 않는다.** TASK-44 에서 `diet` 의
      `gain-pattern` 을 남긴 것과 같은 판단이다 — 방법 유형에서 움직임을 빼면 "무엇을
      어떻게" 가 반쪽이 된다. 대신 **두 지침이 서로 다른 것을 요구하게** 한다:
      `diet-method` 는 종류(결)까지, `exercise` 는 종목·강도·시간대·주의까지.
      `prompt.test.ts` 가 두 지침을 대조한다.

### [TASK-49] 결과 화면 즐길거리 — 스크롤 등장과 Motion 도입 판단 · **(S)** · ⬜ 대기

**이 순서인 이유:** 사용자가 먼저 꺼낸 항목이지만 **유일하게 도입 여부가 안 정해진 것**이라

**지금 깨져 있는 것 (이 태스크의 실제 동기)**

- [ ] `anim-*` 은 **mount 시점**에 재생된다. 결과 화면은 원국 → 도식 넷 → 풀이 순으로 길어서
      대운 타임라인은 스크롤해야 보이는데, 도착했을 땐 애니메이션이 이미 끝나 있다.
      **지금 도식 애니메이션의 절반은 아무도 못 본다.**

**먼저 CSS 로 되는 것부터 (라이브러리 없이)**

- [ ] `animation-timeline: view()` 로 뷰포트 진입 시 재생. **우리 키프레임이 `from` 만 쓰기
      때문에 미지원 브라우저에서는 그냥 최종 모습이 남는다** — 점진 향상이 공짜로 된다.
      `@supports` 로 감싸면 미지원 브라우저는 지금 동작 그대로다.
      - 지원 (2026-08): Chromium 115+ · Safari 26+ · **Firefox 는 아직 기본 비활성**(플래그).
        전역 약 84%. 착수 시 caniuse 로 다시 확인할 것.
- [ ] 스크롤 진행 바(`animation-timeline: scroll()`)도 같은 방식으로 CSS 만 있으면 된다.
      다만 `ProgressNote` 가 이미 몇/몇 을 알려주므로 **없어도 되는 축**이다.
- [ ] 여기까지로 위 항목이 해결되면 **Motion 없이 끝난다.** 아래는 CSS 로 안 되는 것만 남긴다.

**Motion 조사 결과 (motion.dev)**

Framer Motion 의 후속. MIT, React/JS/Vue. 진입점이 둘로 갈린다 (문서가 밝힌 Rollup 기준
수치이며, webpack 은 트리셰이킹이 약해 조금 더 커진다고 문서가 덧붙인다).

| 진입점 | 크기 | 하는 것 |
| --- | --- | --- |
| `motion/mini` 의 `animate` | **2.3kb** | tween·spring. 네이티브 브라우저 API 사용 |
| `animate` 하이브리드 | 18kb | 독립 transform, SVG path, 타임라인, CSS 변수 |
| `motion/react` 의 `motion` | **34kb** | 전부 |
| `m` + `LazyMotion` | 4.6kb + `domAnimation` 15kb (`domMax` 25kb) | 기능을 지연 로드 |

우리에게 값이 있는 것과 없는 것:

| 기능 | 판단 |
| --- | --- |
| `inView` · `whileInView` | **CSS `view()` 로 대체 가능** — 위쪽을 먼저 시도 |
| `AnimatePresence`(exit) | **CSS 로 불가.** 폼 접힘/펼침("수정"), 에러 배너, 결과 뒤 링크 |
| `layout`(높이 전환) | **CSS 로 사실상 불가.** 폼이 접힐 때 높이가 튄다 |
| `press`/`hover` 스프링 | 유형 선택 카드 눌림 — 다만 아래 `/` 제약에 걸린다 |
| `stagger` | 이득 없음 — 인라인 `animationDelay` 로 이미 하고 있다 |
| `useMotionValue` 카운트업 | 오행 **개수**(사실)에만. 점수는 우리 관례라 숫자로 내지 않는다 |

**도입한다면 지킬 것**

- [ ] **`/` 에는 쓰지 않는다.** 유형 선택 화면을 통째로 정적으로 두는 성질이 깨진다 —
      `SiteFooter` 를 클라이언트 컴포넌트로 만들지 않기로 한 것과 같은 판단이고, 이미
      테스트가 막고 있다.
- [ ] **`prefers-reduced-motion` 보장이 구조에서 설정으로 내려간다는 것을 알고 할 것.**
      지금은 CSS 한 규칙이 전역으로 막지만 Motion 은 `<MotionConfig reducedMotion="user">`
      를 씌워야 하고, 빠뜨리면 조용히 깨진다. 씌웠는지를 `lib/design/motion.test.ts` 가
      소스에서 검사한다.
- [ ] `motion/react` 전면 전환을 하지 않는다. 필요한 화면에서 `m` + `LazyMotion` 또는
      `motion/mini` 로 시작한다.
- [ ] 채택하면 `CLAUDE.md` "도식과 애니메이션" 절에 "차트 라이브러리는 안 넣지만 애니메이션
      라이브러리는 여기까지" 를 적는다. **채택하지 않으면 이 조사 결과를 `CLAUDE.md` 의
      "보류한 작업" 으로 옮긴다** — 같은 조사를 다시 하지 않기 위해서다.

→ 완료 기준: 스크롤해서 도착한 도식이 **그 자리에서** 재생되고, 모션 최소화 설정에서는 최종
모습이 즉시 보인다. Motion 은 채택 또는 보류 중 하나로 **결론이 문서에 적혀 있다.**

**조회수를 어디서 세는가 — 서버에서 세면 프리렌더가 죽는다**

- [ ] **서버 렌더 중에 증가시키지 않는다.** `/reading/[type]` 은 `generateStaticParams` 로 네
      유형이 전부 프리렌더돼 있다. 렌더 경로에서 저장소를 건드리면 그 페이지가 통째로 동적이
      되어 **모든 방문이 함수 실행**이 된다 — 조회수 하나 세려고 페이지 성질을 바꾸는 셈이다.
- [ ] **클라이언트 마운트 시 비콘**을 보낸다 (`POST /api/views`). `/reading/*` 에는 이미
      클라이언트 컴포넌트가 있으므로(`SajuForm` · `FirstVisitNotice`) 새로 깨지는 성질이 없다.
      **`/` 는 그대로 손대지 않는다.**
- [ ] 부작용이 하나 이득이다 — **크롤러는 JS 를 돌리지 않으므로 세어지지 않는다.** 서버에서
      셌다면 봇 트래픽이 그대로 숫자에 섞였을 것이다.
- [ ] **개발 중 이중 마운트를 막는다.** React StrictMode 가 이펙트를 두 번 실행하므로
      `useRef` 가드가 없으면 로컬에서 2씩 오른다.
- [ ] 새로고침·재방문은 각각 1회로 센다(조회수의 통상적 뜻). 유형 간 이동
      (`OtherReadingLinks`)도 실제 열람이므로 센다. **중복 제거를 위해 저장소에 신원을 두지
      않는다** — 아래 좋아요와 같은 이유다.
- [ ] **비콘에 기존 레이트 리밋을 그대로 걸지 않는다.** `lib/rate-limit.ts` 의 분당 5회는
      풀이 생성 기준이라, 유형을 훑어보는 정상 사용자가 걸린다. 별도 한도를 두거나 걸지 않되
      **정한 이유를 코드 주석에 남긴다.**
- [ ] `POST /api/views` 는 유형 이름만 받는다. 생년월일·입력값은 **한 글자도 싣지 않는다.**
      `next.config.ts` 가 `/api/*` 에 `no-store` 를 이미 건다.

**세는 단위는 유형뿐이다 — 결과별로 세지 않는다**

- [ ] 키는 `ReadingType` 넷이 전부다. 결과별로 세려면 결과에 id 가 있어야 하고 그건 결과를
      서버에 두는 것이라 **처리방침의 "저장하지 않습니다" 가 죽는다** (`CLAUDE.md` 의
      "결과 영구 링크(`/r/[id]`)는 도입하지 않았다" 와 같은 벽이다).
- [ ] **생년월일에서 파생된 어떤 값도 키에 넣지 않는다.** 해시도 안 된다 — 입력 공간이 작아
      전수 대조가 되므로 가명화까지다 (근거는 `CLAUDE.md` "결과 캐싱" 절).

**저장소**

- [ ] **인메모리 `Map` 은 안 된다.** 인스턴스마다 다른 수가 보이고 콜드 스타트마다 0으로
      돌아간다 — `lib/rate-limit.ts` 가 지금 겪고 있는 것과 같은 문제다. 조회수는 **틀린 값이
      화면에 그대로 나가는** 값이라 더 나쁘다.
- [ ] 필요한 연산은 **원자적 증가**(`INCR`)다. 읽기 캐시(`unstable_cache` 등)로 대체할 수 없다.
      → `CLAUDE.md` "보류한 작업 · 레이트 리밋 영속화" 가 필요하다고 적어 둔 **바로 그
      저장소**다. 한 번 붙이면 그쪽도 함께 풀리므로 착수 시 묶을지 판단한다.
- [x] **Vercel KV 는 그 이름으로 남아 있지 않다** — Upstash 마켓플레이스 연동으로 바뀌었다.
      **다만 주입하는 변수 이름은 옛 이름(`KV_REST_API_*`)을 그대로 쓴다.** 여기서 한 번
      헛돌았다.
- [x] **저장소가 죽어도 서비스는 죽지 않는다** (읽기 경로 완료). 숫자를 못 읽으면 그 자리를
      숨긴다. 쓰기 경로도 같은 원칙으로 붙일 것 — 증가에 실패해도 풀이 생성은 그대로 간다.
      `lib/observability.ts` 의 "계측이 요청을 깨뜨리지 않는다" 와 같다.

**로그인 없이 좋아요 — 중복을 무엇으로 막는가**

- [ ] **서버에 신원을 만들지 않는 쪽을 권고한다.** IP 해시를 저장하면 처리방침 3항
      **"IP 주소: 최대 1분"** 을 고쳐야 한다 — 지금 IP 는 메모리에 1분 두는 것이 전부이고,
      그 한 줄이 이 서비스의 성격을 말하는 문장 중 하나다.
- [ ] 권고안: **`localStorage` 플래그 + 서버는 누가 눌렀는지 모른다.** 무르지만(개발자 도구로
      풀 수 있다) 좋아요는 정확한 수가 필요한 값이 아니다. 남용은 **기존 `lib/rate-limit.ts`**
      (IP·메모리 1분)로 막는다 — 새 신원 저장소를 만들지 않는다.
- [ ] 그래도 처리방침 5항의 **"첫 방문 안내 닫힘 여부만 localStorage"** 가 틀려지므로 같은
      커밋에서 고친다. `lib/form/birth-input.test.ts` 의 저장소 금지 검사는 폼 경로만 보므로
      걸리지 않지만, **생년월일 입력 경로에는 여전히 한 글자도 넣지 않는다.**
- [ ] 취소를 허용할지 정한다. 허용하면 서버에서 **하한 0** 을 강제한다 (플래그가 지워진
      브라우저에서 취소만 눌리면 음수가 된다).

**표시 위치 — `/` 의 정적 성질을 깨지 않는다**

- [ ] `/` 는 **클라이언트 JS 가 없고 통째로 정적**이다. TASK-42(`SiteFooter`) · TASK-50 이 전부
      이 성질을 지키려고 내린 결정이고 테스트가 막는다. 조회수를 카드에 띄우겠다고
      클라이언트 fetch 를 넣으면 그게 깨진다.
- [ ] 대신 **`revalidate` 로 주기적 재생성.** 서버에서 읽어 렌더하므로 클라이언트 JS 가 0 인
      채로 숫자가 들어간다. 수치는 N초 늦지만 조회수가 실시간일 이유가 없다.
- [ ] **좋아요 버튼은 `/` 에 두지 않는다.** 버튼은 클라이언트 컴포넌트다. 결과 화면
      (`/reading/[type]`) 아래 `OtherReadingLinks` 근처에 둔다.
- [ ] **스트리밍 중에는 내지 않는다** — 지금 쓰이고 있는 글을 끊는다 (`OtherReadingLinks` 를
      스트리밍 중에 내지 않는 것과 같은 이유).
- [ ] 색은 시맨틱 토큰만 쓰고 새 컴포넌트를 `lib/design/tokens.test.ts` 의 검사 목록에 넣는다.

**내부 유형**
