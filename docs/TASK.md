### [TASK-36] 유형 선택 카드 썸네일을 사진으로 교체 · **(S)** · ⬜ 대기 · 🔒 사진 또는 스톡 API 키 필요

**자리는 만들어져 있다** (2026-08-14). 카드마다 56px 단색 블록이 붙어 있고
`app/page.tsx` 의 `THUMBNAIL_TONES` 가 `--color-thumb-1/2/3` 을 순서대로 돌려 쓴다.
남은 것은 그 단색을 **사진으로 바꾸는 것**뿐이다.

바꿀 때 함께 지울 것: `THUMBNAIL_TONES` 배열, `globals.css` 의 `--color-thumb-*` 셋,
`lib/design/tokens.test.ts` 의 해당 토큰 세 줄, `docs/design-tokens.md` 의 "유형 카드
썸네일 자리" 절.

#### 막힌 지점 — 사진을 자동으로 고를 수 없다 (2026-08-14 확인)

에이전트가 Unsplash 에서 사진을 **찾을 수 없다.** 실측한 것:

| 대상 | 결과 |
| --- | --- |
| `unsplash.com/*` (검색·사진 페이지) | **401** — 봇 차단 페이지("Making sure you're not a bot!") |
| `api.unsplash.com` | **401** — access key 필요 |
| `source.unsplash.com` | 503 (서비스 종료) |
| `images.unsplash.com/photo-<id>` | **200** — CDN 은 열려 있다 |
| Openverse API | 200이지만 **Unsplash 를 색인하지 않는다** (flickr·wikimedia·stocksnap·nappy·rawpixel 등) |

CDN 이 열려 있으니 **사진 id 만 알면 내려받을 수는 있다.** 그런데 검색을 못 하므로 id 를
기억에 의존해 찍어야 하고, 그러면 ⓐ 무엇이 찍힌 사진인지 확인하지 못한 채 제품에 넣게 되고
ⓑ **촬영자와 원본 URL 을 확인할 수 없어** 아래 출처 기록 조건을 지킬 수 없다. 그래서
자동으로 진행하지 않는다.

#### 이미지 생성(Gemini/Imagen)도 지금 키로는 안 된다 (2026-08-14 실측)

`.env.local` 의 실제 키로 확인했다. 모델 목록에는 `gemini-3.1-flash-lite-image` ·
`gemini-2.5-flash-image` · `gemini-3-pro-image` · `imagen-4.0-*` 가 다 보인다. 그런데:

| 호출 | 결과 |
| --- | --- |
| `gemini-3.1-flash-lite-image:generateContent` | **429** RESOURCE_EXHAUSTED (재시도도 429) |
| `gemini-2.5-flash-image:generateContent` | **429** |
| `imagen-4.0-fast-generate-001:predict` | **404** — 키로 접근 자체가 안 됨 |
| `gemini-3.5-flash-lite:generateContent` (텍스트) | **200** ← 같은 키, 같은 시각 |

텍스트는 200인데 이미지만 429라는 것이 핵심이다 — 프로젝트 쿼터가 소진된 것이 아니라
**무료 등급에 이미지 생성 쿼터가 없다.** `quotaId` 가
`GenerateRequestsPerDayPerProjectPerModel-FreeTier` 로 나온다. Imagen 은 404 라 유료 전용이다.
→ **결제 활성화가 필요하다.** 이는 `CLAUDE.md` 의 미확정 결정사항(수익화 여부)과 얽힌다.

**착수하려면 넷 중 하나가 필요하다.**

1. **사용자가 사진 3장을 고르고 URL(또는 파일)을 준다** — 가장 간단하다. CDN 이 열려 있어
   URL 만 있으면 내려받아 변환·적용까지 자동으로 된다.
2. **Pexels 무료 API 키** — 가입 1분. 라이선스 확인함: 무료·상업적 사용 가능·**출처 표기
   의무 없음**·수정 가능. 금지 항목(미변경 사본 판매, 타 스톡 플랫폼 재배포, 상표 사용,
   식별 가능한 인물을 부정적으로 묘사)은 이 용도와 무관하다. `api.pexels.com` 도달 확인.
3. **Unsplash 개발자 access key** (무료) — 공식 API 로 검색·attribution 을 받는다.
   웹은 봇 차단이라 키 없이는 검색이 안 된다.
4. **Gemini 결제 활성화 후 생성** — 세 장의 톤·구도를 팔레트에 맞춰 통일할 수 있고
   사람 얼굴·몸 회피를 프롬프트로 통제할 수 있어 품질은 이쪽이 낫다.

키는 **이 작업에서만 쓰는 것**이라 서버 환경변수로 올리지 않는다.

#### 실행 시점은 빌드 타임이다 — 런타임으로 만들지 말 것

어느 경로로 가든 `scripts/` 에서 한 번 만들어 `public/` 에 커밋한다
(`render-icons.mjs` · og 카드와 같은 방식). 런타임으로 두면 안 되는 이유가 두 가지다.

- **런타임 생성**: 무료 500 RPD 를 풀이와 나눠 쓰게 된다. 첫 화면 한 번에 카드가 셋이므로
  방문당 3콜이다.
- **런타임 스톡 핫링크**: 제3자가 늘어 아래 "반드시 지킬 것" 이 그대로 걸린다.

**자동 폴백 체인(생성 실패 → 스톡)을 넣지 않는다.** 어느 날 조용히 출처가 섞여 세 장의
시각 언어가 깨진다 — 공유 카드와 화면의 시각 언어를 맞추라는 규칙과 같은 이유다.
스크립트는 `--source` 인자로 둘 다 지원하되 **어느 쪽을 쓸지는 사람이 정한다.**

#### 반드시 지킬 것 — 이미지를 **내려받아 저장소에 둔다**

**Unsplash URL 을 그대로 `src` 에 넣지 말 것.** 핫링크하면 방문자 브라우저가 Unsplash 로
직접 요청을 보내고, 그 순간 **IP·User-Agent 가 새 제3자에게 전달된다.**
`app/privacy/page.tsx` 4항(제3자 전송)에는 Google·Vercel 둘만 적혀 있으므로 사업자가 하나
느는 것이고, 5항의 "방문자 분석 도구를 전혀 쓰지 않습니다" 와도 결이 어긋난다
(Unsplash 는 이미지 요청으로 조회를 집계한다). **파일로 받아 커밋하면 제3자가 늘지 않아
처리방침을 손대지 않아도 된다.** 파비콘·og 카드와 같은 방식이다.

- `next.config.ts` 에 `images.remotePatterns` 를 추가하지 않는다 — 그게 필요해졌다면
  핫링크하고 있다는 뜻이다.
- 지금 저장소에 **`public/` 이 없다.** 이 태스크에서 처음 만들게 되므로 `README.md` 의
  구조 그림에도 함께 넣는다.

#### 작업

- [ ] 유형마다 한 장씩 고른다. **사람이 크게 나오는 사진을 피한다** — 특정 인물이 서비스의
      얼굴처럼 읽히고, 체질·다이어트 카드에 몸이 나오면 체형 규범으로 읽힌다.
      정물·자연·질감 쪽이 안전하다.
- [ ] Unsplash 라이선스는 출처 표기가 의무가 아니지만 **사진마다 촬영자와 원본 URL 을
      `docs/` 에 기록한다.** 교체할 때 어디서 왔는지 모르면 다시 못 찾는다.
- [ ] `public/` 에 넣고 **webp 로 변환**한다. 카드 폭이 최대 672px(`max-w-2xl`)이므로 2배인
      1344px 이면 충분하다. og 카드 45KB 를 기준선 삼아 **장당 100KB 를 넘기지 않는다** —
      첫 화면이 정적이라는 이점을 사진 셋으로 날리지 말 것.
- [ ] `next/image` 로 넣고 `width`·`height` 를 주어 레이아웃 이동(CLS)을 막는다.
      **`priority` 는 첫 카드에만** 준다 (셋 다 주면 우선순위가 없는 것과 같다).
- [ ] `alt` 에 유형 라벨을 되풀이하지 않는다 — 바로 옆에 제목이 있어 스크린리더가 같은 말을
      두 번 읽는다. 사진이 정보를 나르지 않으면 `alt=""` 로 장식임을 밝힌다.
- [ ] **사진 위에 글자를 얹지 않는다.** 얹으려면 대비 4.5:1 을 사진마다 따로 재야 하는데
      `lib/design/tokens.test.ts` 의 대비 검사는 **사진 위 글자를 잴 수 없다.**
      제목·설명은 지금처럼 사진 옆이나 아래의 단색 면에 둔다.

#### 손대지 않을 것

- **og:image 는 그대로 둔다** (`app/opengraph-image.png`). 사진으로 바꾸려면
  `docs/og-card.html` 원본과 팔레트 검사까지 함께 손봐야 하고, 지금 카드는 서비스 소개용으로
  이미 자리를 잡았다.
- **결과 화면에는 사진을 넣지 않는다.** 거기 그림 넷은 데이터 도식이고(TASK-25),
  장식 사진이 섞이면 어느 것이 근거인지 흐려진다.

→ 완료 기준: 카드 3장이 서로 다른 이미지를 달고 나오며 셋 다 `public/` 에서 나간다.
`next.config.ts` 에 원격 이미지 설정이 없고 네트워크 요청에 외부 이미지 호스트가 없다.
장당 100KB 이하이며 출처(촬영자·원본 URL 또는 생성 프롬프트·모델)가 `docs/` 에 적혀 있다.
**임시 단색 토큰(`--color-thumb-*`)이 제거돼 있다.** 검증 4종 통과.

### [TASK-33] 삼합·방합을 세력 판정에 반영 · **(O)** · ⏸ 보류

TASK-32 와 같은 사례에서 확인된 두 번째 누락. `1999-12-09 22:12` 은 지지가
**해(亥) · 묘(卯) · 미(未)** 로 **삼합 목국(木局)** 을 온전히 이룬다 — 지지 4개 중
3개이고 왕지 묘까지 갖췄다. 삼합을 보는 앱에서는 이 세 글자가 묶여 목으로 작동하므로
일간 을목이 자기 오행 덩어리 위에 앉은 형국이 되고, 신약이 나올 수가 없다.
지금 코드에는 합충 로직이 **전혀 없다.**

**보류 이유**: 성립 조건을 우리가 정해야 해서 "우리 관례" 가 크게 는다 — 합화(合化)
인정 여부, 글자 사이 거리, 반합 처리, 쟁합·투합, 그리고 월령이 국의 오행이 아닐 때
(이 사례가 그렇다 — 월지가 자수다) 화(化)를 어디까지 볼 것인가. `CLAUDE.md` 의
"고전 규칙과 우리 관례를 섞지 말 것" 에 정면으로 걸린다.

**TASK-32(통근)로 이 사례는 해결됐다** — `1999-12-09 22:12` 이 `약간 신강` 으로 나온다.
그 뒤에도 실측에서 어긋나는 사주가 남는지 보고 착수 여부를 판단한다. 근거 없이 관례를
늘리지 않기 위한 순서다.

→ 완료 기준: 착수 시 정한다. 최소한 위 조건 목록 각각에 대해 어느 쪽을 택했는지와
그것이 고전인지 우리 관례인지를 `docs/saju-validation.md` 가 밝혀야 한다.
