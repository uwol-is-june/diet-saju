# 카드뉴스

이 저장소는 웹 서비스 말고 **인스타그램 카드뉴스**(1080×1350 PNG + 캡션)도 만든다.
앱 코드와 섞이지 않는다 — `docs/` 아래에만 있고 빌드·테스트·배포에 들어가지 않는다.

**이 파일은 카드뉴스 작업에만 적용된다.** 앱 규칙은 저장소 루트의 `CLAUDE.md` 에 있고
**서로 옮기지 않는다** (맨 아래 "앱의 표현 규칙과 서로 옮기지 않는다").

## 명령어

```powershell
node docs\cardnews\render.mjs docs\cardnews_0819\cards.json
node docs\cardnews\render.mjs docs\cardnews_b_0820\cards.json
node --env-file=.env.local docs\cardnews\fetch-photos.mjs --count=6 docs\cardnews_0819\cards.json
```

**렌더는 일반 터미널(PowerShell/cmd)에서 돌린다.** 파일 접근이 제한된 셸에서는 크로미움이
뜨지 않는다.

## 규칙의 단일 소스는 README.md 다

**[README.md](README.md) 가 단일 소스다.** 고친 사례 표와 치수는 전부 거기 있고,
여기에는 **어기면 되돌리기 비싼 것**만 적는다. 스크립트 목록(`generate-photos.mjs` 가
무료 등급에서 막혀 있는 것 포함)과 B_style 실측표도 그쪽이다.

레퍼런스는 `docs/card_ref/` 다 — `ref_origin/` 은 A_style 레이아웃을 가져온 "다시," 카드
4종, `card_3/` 은 **B_style** 을 가져온 인스타 7장 캡처이고, `card_1/` · `card_2/` 와
그것을 옮겨 적은 `reference-text.md` 는 **서술 방식만** 가져온 `LIVE WELL ALL AROUND`
두 편이다.

**`card_3/` 은 커밋하지 않는다** (2026-08-20 확정 · `.gitignore`). 캡처 7장이 30MB 라
저장소 히스토리가 두 배가 되는데, 거기서 뽑아낸 것은 이미 README 의 **"B_style 실측표"**
로 옮겨 적혀 있어 원본 해상도를 다시 볼 일이 없다. **그래서 그 표가 없어지면 근거가
통째로 사라진다** — 치수를 고칠 때 표를 같은 커밋에서 갱신하라는 규칙이 여기에 걸려 있다.

## 형식과 폴더

- **형식이 두 벌이고 `cards.json` 의 `style` 이 고른다** (없으면 `"a"` · TASK-95).
  A_style(`card.css`)은 흰 바탕에 사진 한 조각을 얹는 다섯 장, B_style(`card-b.css`)은
  **일곱 장 전부 전면 사진 + 흰 글씨**다. 레이아웃 이름이 겹치지 않으므로(`b-` 접두사)
  데이터만 봐도 어느 쪽인지 안다. **한 세트에서 섞지 말 것** — 스타일시트는 한 벌만
  실리므로 다른 쪽 카드가 스타일 없이 나온다.
  - **B_style 은 본문이 32px 다** (A_style 은 44px). "44px 하한" 을 어긴 것이 아니라 다른
    형식에서 다시 잰 값이고, 부족한 크기를 **어두운 사진의 대비로 메운다.** 그래서
    **밝은 사진을 고르면 이 형식은 무너진다** — 사진 고르기가 여기서는 디자인 결정이다.
  - **B_style 은 줄바꿈을 코드가 만들지 않는다.** `clauseBreaks` 없이 `\n` 만 쓴다 —
    레퍼런스가 절 중간에서도 끊기 때문이다. 문구를 고치면 줄을 다시 봐야 한다.
  - **B_style 의 치수는 레퍼런스 캡처 실측이다** (README 의 "B_style 실측표").
    눈대중으로 고치지 말고, 고치면 그 표도 같은 커밋에서 갱신한다.
  - **레퍼런스와 일부러 다르게 한 것 셋** — ① 출처 한 줄을 넣었다(카드만 퍼가도 근거가
    붙어 있어야 한다). **그래서 그 위 덩어리(팁 · 세 칸)를 실측보다 80px 올렸다** — 실측
    자리에 두면 간격이 25~29px 이라 본문 줄 간격(32px)보다 좁아 출처가 같은 묶음의 다음
    줄처럼 읽힌다. **출처를 더 내려서 벌리지 말 것**, 밑변 26px 이 하한이다.
    **그리고 유형 카드의 위 덩어리(눈썹 + 제목)를 같은 80px 만큼 내렸다** — 아래만 올리면
    위 덩어리가 카드 끝에 홀로 남아 "눈이 너무 위로 올라간다"가 된다(같은 날 사용자 지적).
    **둘은 같이 움직인다.** 가운데 묶음은 카드 높이 가운데 고정이라 손대지 않는다.
    ② 마크는 별표가 아니라 우리 로고다. ③ **표지 제목이 좌하단 왼쪽
    정렬이고 로고는 일곱 장 모두 우상단이다** (2026-08-20 사용자 확정). 레퍼런스 표지는
    가운데 정렬 제목 + 그 아래 가운데 마크인데, 그러면 **넘길 때 마크가 표지에서만 튀어
    다니고**, 제목 길이가 바뀔 때마다 두 줄의 시작점이 함께 움직여 **사진의 빈 자리를 미리
    못 잡는다.** 밑변 196px 는 A_style 표지와 같은 값이고 근거도 같다(인스타 하단 UI).
    스크림도 따라간다 — 표지는 아래를 깊게·위를 조금 덮고, 방사형은 마지막 장에만 남는다.
    표지에는 **부제 한 줄(`sub`)** 도 더했다(A_style 표지와 같은 판단). 36px 이다 —
    제목이 78px 이라 A_style 의 42px 을 그대로 쓰면 둘이 같은 위계로 보인다.
    유형 카드 셋의 골격("세 유형 중 하나 + 유형별 값 하나")은 그대로 받았다.
- **주제마다 폴더 하나이고 형식은 복사하지 않는다.** `docs/cardnews_<MMDD>/`
  (B_style 은 `docs/cardnews_b_<MMDD>/`)에는 `cards.json` · `assets/` · `out/` · `.gitignore`
  만 둔다. `render.mjs` · `fetch-photos.mjs` · `card.css` · `card-b.css` · `fonts/` · 로고 ·
  느낌표는 `docs/cardnews/` 것을 그대로 쓰고 **json 경로만 넘긴다** (두 스크립트가 데이터
  폴더를 기준으로 사진과 출력물을 찾는다 — `DATA_DIR`).
  복사하면 두 벌이 되어 한쪽만 고쳐지고, 세트끼리 톤이 갈리는 순간 한 계정의 콘텐츠로
  안 읽힌다.
- **`card.css` 는 모든 A_style 편이 공유한다** (B_style 은 `card-b.css`). 표지 타이포(무게
  **800** · 밑변 **196px** · 좌우 **96px**)를 건드리면 **기존 편들까지 렌더해 확인한다** —
  좌우 96px 이면 글 칸이 888px 이고 알룰로스 편의 `설탕 대신 알룰로스,` 가 그 폭에서 가장
  아슬아슬한 줄이다. 무게를 낮출 때 **크기(94px)는 그대로 둔다** — 표지는 피드에서 제일
  먼저 읽히는 글자다.

## 글

- **AI 티가 나는 것을 세 이름으로 잡아 뒀다.** 사용자가 세 번 지적했고 셋 다 원인이 다르다.
  ① **줄표(`—`)를 카드 글에 쓰지 않는다** (`note` · `thesis` · `captionNote` 같은 작업용
  메모와 README 에는 써도 된다). ② **짧게 만들려고 문장 성분을 빼지 않는다** — 목적어를
  비유(`칸` · `자리` · `닿다` · `담다`)로 메우지 말고, 줄이려면 문장 수를 줄인다.
  ③ **과잉 친절한 설명조를 쓰지 않는다** — 완충 어미(`~해 보면` · `~정도예요`)를 한 문장에
  겹치지 않고, 낱말은 독자가 매대 앞에서 쓰는 것으로 고른다(`포장 표시` → `영양성분표`).
- **서술 골격은 레퍼런스에서 왔다** (2026-08-19 채택). 본문 제목은 **반직관 선언문**이고
  질문형은 표지 몫이다. 본문은 ① 흔한 행동 → ② **`하지만 몸은 …`** 반전 → ③ 굵은 결론
  세 문단이다. **이 반전이 사실 나열과 갈리는 지점이다.** 수치와 전문 용어는 쉽게 바꿔
  말하지 말고 그대로 낸다 — 바꿔 말하려다 위 ③의 설명조로 되돌아간다.
- **표지는 감성 구어체, 본문 카드는 `-습니다`체다.** 표지 제목은 정보가 아니라 감정으로
  연다(`아침마다 왜 / 자꾸 부을까ㅠㅠ`). 본문은 근거를 대는 자리라 단정한다. `sub` 는
  표지 제목이 감정일 때 **무엇을 하러 들어가는지**를 잡아 준다.
- **다섯 장은 한 편의 글이다.** 한 문장짜리 논지를 `cards.json` 의 `thesis` 에 적고 다섯 장을
  그 논지에 이르는 단계로 쪼갠다 — 각 카드가 앞 카드의 말이나 숫자를 받아서 연다.
  **순서를 바꿔도 읽힌다는 것이 곧 흐름이 없다는 신호다.** 레이아웃 순서를 편마다 고정하지
  않는다 — 목록이 들어가는 칸은 글 폭이 넓은 `plain` 이어야 한다.
- **줄바꿈은 구(句) 경계에서 손으로 끊는다** (`body` 의 `\n` → `<br>`). 문장 사이는
  `clauseBreaks` 에 맡기고 그 자리에 `\n` 을 넣지 않는다. **굵은 강조는 줄을 넘지 못한다** —
  `**…**` 안에 `\n` 이 들어가면 강조가 아예 적용되지 않으므로 `**앞줄**\n**뒷줄**` 로 쪼갠다.
  대가는 문구를 고칠 때마다 줄을 다시 봐야 하는 것이라 **렌더 결과를 눈으로 확인한다.**
- **캡션은 다섯 덩어리 · 10~12줄이고 카드의 요약이지 복사가 아니다.** 음식별 수치 같은 카드
  안의 세부를 캡션에 옮기면 카드를 넘겨볼 이유가 사라진다. **마지막 사인오프는 자리 · 길이 ·
  꼴 · 이모지만 고정하고 문장은 편마다 새로 쓴다** (2026-08-19 수정) — 두 편이 글자까지 같아서
  나온 규칙이라, 새 편을 쓰기 전에 기존 편들의 마지막 줄을 먼저 읽는다.

## 사진

**사람 없는 정물이고 주제의 실물 형태를 보여야 한다** (보충제 편은 결국 가루다).
손·팔만 나오는 것도, 브랜드가 찍힌 통·봉지도 거른다. 후보는 `fetch-photos.mjs --count` 로
받아 컨택트시트로 한 번에 보고 고른다 — **가진 사진을 재배치하는 것이 억지 검색보다
빠를 수 있다.**

## 앱의 표현 규칙과 서로 옮기지 않는다

카드뉴스는 사주 풀이가 아니라 별도 콘텐츠라 수치·식품 이름 금지
(`lib/saju/constitution.ts` · `lib/prompt.ts`)가 걸리지 않는다 — 대신 카드마다 `source` 로
근거를 단다. 반대로 표지의 구어체·`ㅠㅠ` 를 앱 쪽으로 가져오지 말 것.
