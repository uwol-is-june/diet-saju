# 카드뉴스 렌더러

성분·궁금증 콘텐츠를 SNS 카드뉴스(1080×1350 PNG)로 뽑는다.

```powershell
node docs\cardnews\render.mjs                                     # cards.json → out/*.png + caption.txt
node docs\cardnews\render.mjs docs\cardnews_0818\cards.json       # 다른 주제 폴더 (A_style)
node docs\cardnews\render.mjs docs\cardnews_b_0820\cards.json     # B_style
```

## 형식이 두 벌이다 — A_style · B_style

`cards.json` 의 **`style`** 이 고른다 (없으면 `"a"`). 레이아웃 이름이 서로 겹치지 않으므로
데이터만 봐도 어느 형식인지 안다.

| | A_style (`"a"` · 기본) | B_style (`"b"`) |
| --- | --- | --- |
| 레퍼런스 | [`card_ref/ref_origin/`](../card_ref/ref_origin/) "다시," 카드 4종 | [`card_ref/card_3/`](../card_ref/card_3/) 인스타 7장 캡처 |
| 스타일시트 | `card.css` | `card-b.css` |
| 바탕 | 흰 면 + 사진 한 조각 | **일곱 장 전부 전면 사진 + 흰 글씨** |
| 레이아웃 | `cover` `stack` `split` `plain` `notice` | `b-cover` `b-intro` `b-type` `b-summary` `b-outro` |
| 본문 크기 | 44px | **32px** (아래 "B_style 쓰는 법") |
| 줄바꿈 | `clauseBreaks` 가 만든다 | **전부 손으로 넣는다** |
| 장수 | 다섯 | 일곱 |

**한 세트 안에서 형식을 섞지 말 것.** 스타일시트는 한 벌만 실리므로 다른 쪽 레이아웃을
쓴 카드는 스타일 없이 나온다. 새 주제는 어느 쪽인지부터 정한다.

**공유하는 것과 갈리는 것.** `fonts/` · `assets/logo.png` · `render.mjs` · `fetch-photos.mjs` ·
캡션 규칙 · 서술 규칙(줄표 금지 · 설명조 금지 · 여러 장이 한 편의 글)은 **두 형식이 함께
쓴다.** 갈리는 것은 위 표의 것들뿐이다.

> **일반 터미널(PowerShell/cmd)에서 실행할 것.** 파일 접근이 제한된 셸에서 돌리면
> 브라우저가 임시 HTML 을 읽지 못해 오류 화면이 그대로 PNG 로 찍힌다.
> 그런 경우 렌더러가 "스크린샷이 생성되지 않았습니다" 로 멈춘다.

## 읽히는 곳이 인스타그램이라는 것

이 카드는 **피드에서 폭 400px 안팎으로 축소되어** 읽힌다. 설계가 여기서 갈린다.

- **본문 44px 가 하한이다.** 1080px 기준 34px 는 화면에서 12px 남짓이라 본문으로 못 쓴다.
  44px 가 화면에서 16px 정도가 되는 값이다. 좁아 보인다고 글자를 줄이지 말고 **문장을 줄일 것.**
- **한 카드에 한 가지만 담는다.** 손가락으로 넘기며 보는 포맷이라, 카드를 꽉 채우면 넘겨버린다.
- **어절 단위로 줄바꿈한다** (`word-break: keep-all`). 기본값으로 두면 "못합니다."가
  "못합" / "니다." 로 갈라져 고아 음절이 남는다. 줄이 짧을수록 자주 생긴다.
- **마침표·쉼표 뒤에서 줄을 바꾼다** (`clauseBreaks`, render.mjs). 브라우저에 맡기면 줄이
  꽉 찼을 때 아무 어절에서나 끊겨 문장이 어중간하게 잘린다. 절 끝에서 끊으면 한 줄이 뜻의
  단위가 되어 읽는 리듬이 산다 — 풀이 본문에서 문장 묶음마다 문단을 나누는 것
  ([lib/reading/line-breaks.ts](../../lib/reading/line-breaks.ts))과 같은 이유다.
  `0.5g` 이나 `1,000` 은 **뒤에 공백이 없어서** 애초에 걸리지 않는다 (예외 목록 불필요).
  이 때문에 글이 길어지므로 `stack` 의 사진 높이를 레퍼런스보다 낮춰 뒀다.
- **표지는 자간을 덜 조이고 행간을 더 준다.** 큰 글씨에 본문과 같은 자간(-0.055em)을 쓰면
  글자가 뭉친다. 지금은 -0.035em · 행간 1.3 이다.
- **표지 제목은 800(ExtraBold)이고 밑변에서 196px 띄운다.** 900(Heavy)은 94px 에서 획이
  붙어 덩어리로 보이고, 사진 위 흰 글씨라 더 두꺼워 보인다. 무게를 낮출 때 **크기는 그대로
  둔다** — 표지는 피드에서 제일 먼저 읽히는 글자다. 밑변 여백도 같은 이유다: 인스타는 카드
  아래에 아이디·좋아요 UI 가 붙어서 140px 로는 제목이 그 줄에 닿아 보였다.
- **표지 제목의 좌우 여백은 96px 이다** (본문 카드의 `--pad` 는 68px). 값을 맞추지 않는
  이유는 표지 글자가 훨씬 커서 같은 여백이면 더 좁아 보이기 때문이다. 대신 글 칸이
  888px 로 줄었으므로 **표지 제목을 고치면 기존 편들까지 렌더해 한 줄이 넘치는지 볼 것** —
  `card.css` 는 모든 A_style 주제 폴더가 공유한다. 알룰로스 편의 `설탕 대신 알룰로스,` 가 이
  폭에서 가장 아슬아슬한 줄이다.
- **사진 출처를 카드에 찍지 않는다.** 다섯 장마다 같은 줄이 들어가면 읽는 데 방해가 된다.
  `out/caption.txt` 로 모아 인스타그램 본문에 한 번 붙인다 (아래 참조).
  **정보 출처(`source`)는 반대로 카드에 찍는다** — 둘은 다른 것이다 (아래 "출처 표기와 캡션").

## 왜 이 구조인가

**형식은 코드가 만들고 내용만 사람이(또는 LLM 이) 채운다.** 이 저장소가 사주 계산과
해석을 가른 것과 같은 이유다 — 이미지 생성 모델에 레이아웃을 맡기면 한글이 깨지고
카드마다 톤이 달라져서, 한 세트로 묶이지 않는다.

| 파일 | 역할 |
| --- | --- |
| `card.css` | A_style 디자인. 팔레트·치수·글자 크기의 단일 소스 |
| `card-b.css` | B_style 디자인(전면 사진 + 흰 글씨). 같은 성격의 단일 소스 |
| `cards.json` | 카드별 내용 (제목·본문·사진 경로·해시태그) |
| `render.mjs` | 데이터 + CSS → HTML → PNG + caption.txt |
| `fetch-photos.mjs` | Pexels 에서 후보 사진 받기 → 고른 것만 확정 |
| `extract-parts.mjs` | 레퍼런스에서 로고·느낌표 잘라내기 (한 번만) |
| `generate-photos.mjs` | Gemini 이미지 생성 (**무료 등급에서는 못 쓴다**, 아래 참조) |
| `fonts/` | 나눔스퀘어 네오 woff2 4종 |

브라우저는 **시스템에 깔린 Edge 를 헤드리스로** 쓴다. playwright 를 의존성으로 들이지
않기 위해서이며 [`scripts/render-icons.mjs`](../../scripts/render-icons.mjs) 와 같은 판단이다.
다른 크로미움을 쓰려면 `EDGE_PATH` 환경변수로 경로를 넘긴다.

## 폰트

**나눔스퀘어 네오로 고정한다.** `fonts/` 의 woff2 4종(Regular 400 · Bold 700 ·
ExtraBold 800 · Heavy 900)을 `@font-face` 로 물린다. 네이버 배포 폰트이고 상업적 사용이
자유롭다.

- `card.css` 의 `%FONTS%` 를 `render.mjs` 가 절대 경로로 바꿔 넣는다. HTML 이 임시 폴더에
  쓰이므로 상대 경로로 두면 폰트를 못 찾는다.
- 렌더 시 `--allow-file-access-from-files` 를 준다. `@font-face` 는 이미지와 달리 교차 출처
  검사를 받아서 이 플래그가 없으면 **조용히 폴백 폰트로 그려진다** — 오류가 안 나므로
  자간이 미묘하게 다른 결과물이 나올 때까지 모른다.
- `fonts/` 를 지우면 폴백으로 떨어져 크기·자간이 달라진다. 지우지 말 것.

## 레퍼런스에서 잘라낸 조각 (로고 · 느낌표)

**도형으로 다시 그리지 않고 레퍼런스에서 잘라낸 이미지를 그대로 쓴다.** 그리는 순간
변형이 되기 때문이다. 느낌표도 같다 — 원본은 하이라이트와 그림자가 들어간 입체 그림이라
CSS 도형으로는 납작한 다른 물건이 나온다.

```powershell
node docs\cardnews\extract-parts.mjs        # 둘 다 (한 번만)
node docs\cardnews\extract-parts.mjs bang   # 하나만
```

| 조각 | 파일 | 원본 |
| --- | --- | --- |
| "다시," 로고 | `assets/logo.png` (124×40) | `ref_origin/ref2.png` 우상단 |
| 빨간 느낌표 | `assets/bang.png` (158×224) | `ref_origin/ref4.png` 우하단 (`notice` 카드) |

좌표는 `extract-parts.mjs` 의 `PARTS` 에 실측값으로 있다. 캔버스가 레퍼런스와 같은
1080×1350 이라 **거기서 잰 위치가 곧 카드에서 쓸 위치**다 (`card.css` 의 배치도 같은 값).

잘라낸 것은 **흰 바탕 위의 그림** 한 장씩이다. 카드 바탕이 흰색이 아니어도 CSS 가
`mix-blend-mode: multiply` 로 합성해 흰 바탕만 사라진다 — 느낌표의 옅은 그림자는 그래서
사각형 없이 카드 바탕 위에 얹힌다. 어두운 사진 위에 밝은 로고가 필요한 커버는 CSS 가
뒤집어 쓴다 (`filter: invert(1)` + `mix-blend-mode: screen`). 두 벌을 만들면 나중에
한쪽만 바뀐다.

- **`.logo` 에 `z-index` 를 주지 말 것.** 스태킹 컨텍스트가 생기면 `mix-blend-mode` 가 그
  상자 안에서만 합성되어 흰 바탕이 그대로 남는다 (실제로 커버에 검은 박스가 나왔다).
  로고는 DOM 에서 사진·스크림보다 뒤에 오므로 z-index 없이도 위에 그려진다.
- 원본 벡터 파일을 받으면 그 조각을 `PARTS` 에서 지우고 받은 파일로 교체한다.

## 짧게 만들려고 문장 성분을 빼지 않는다

**한 카드에 한 가지만 담는다**(위)는 문장을 짧게 쓰라는 말이 아니다. 단백질 편 초안이
그 둘을 혼동해서, 문장을 줄이려고 목적어를 빼고 그 자리를 비유로 메웠다. 사용자 평가는
**"물흐르듯 읽히긴 하지만 무슨 말을 하고 싶은지는 모르겠는"** 이었다.

| 고친 것 | 왜 |
| --- | --- |
| 이 숫자를 먼저 **잡아야** | 숫자를 잡는다는 말이 없다 |
| 대부분 **닿는** 양이에요 | 무엇이 무엇에 닿는지가 없다 → `50g은 대부분 채워집니다` |
| **남는 칸**이 있는지부터 | 불필요한 비유 → `지금 얼마나 먹고 있는지부터` |
| 거기가 프로틴 **자리**예요 | 비유 + `거기가` 가 군더더기 |
| **한 포는** 그냥 추가 열량 | 한 포가 무엇인지, 무엇이 올라가는지가 없다 |
| 끼니에 나눠 **담는** | 담는 것은 그릇이다 → `나눠 먹는` |
| 유당을 걸러낸 **WPI**도 | 설명 없이 튀어나온 용어 |

- **비유를 쓰지 않는다.** `칸` · `자리` · `닿다` · `담다` 처럼 원래 뜻이 다른 낱말을
  빌려 오면 글자 수는 줄지만 읽는 사람이 한 번 옮겨 생각해야 한다. 피드에서 몇 초 보는
  글에서 그 한 번이 곧 이탈이다.
- **무엇이 얼마나 늘어나는지, 무엇을 먹는지를 문장 안에 적는다.** `열량만 더하는 음료` ·
  `우유에 타면 우유 열량이 더해집니다` 처럼 주어와 목적어를 남긴다.
- **용어는 쓰지 않거나 풀어 쓴다.** WPI 는 한 줄로 설명할 자리가 없어서 뺐다. 아까워서
  약어만 남기면 그 카드에서 독자가 멈춘다.
- **줄이고 싶으면 문장 성분이 아니라 문장 수를 줄인다.** 카드마다 글 칸의 높이가 정해져
  있으므로(`stack` 은 사진 위 4줄, 출처 줄이 y≈679) 넣을 문장 수를 먼저 세고 쓴다.
- **목록 항목의 어투를 섞지 않는다.** `notice` 의 `warn` 은 `~하기 / ~않기` 로 맞추고,
  조건은 `~있다면` 으로 둔다. 하나만 서술문이면 그 줄이 튄다.

### 과잉 친절한 설명조도 AI 티다 (2026-08-19 · 나트륨 편)

비유를 걷어내도 **가르치려는 어투**가 남으면 같은 인상을 준다. 사용자 지적은 두 번째였다 —
"불필요한 비유나 **너무 쉽게 설명하려고 하는 듯한 모습**에서 AI 느낌이 난다".

| 고친 것 | 왜 |
| --- | --- |
| 앞에서 본 2,000mg을 **음식으로 바꿔 보면** 이렇습니다 | 독자를 데리고 가는 어투 → `앞의 2,000mg을 음식으로 보면` |
| 소금으로 **바꾸면** 하루 5g, 티스푼 한 개 **정도예요** | 완충 어미가 겹친다 → `소금으로는 하루 5g, 티스푼 한 개입니다` |
| 하루 나트륨부터 **세어 보기** | `세다` 가 어색하다 → `계산해 보기` (단백질 편도 이미 이 낱말이다) |
| **포장 표시** 확인하기 | 무엇을 보라는 건지 안 잡힌다 → `영양성분표 확인하기` |
| 하루 종일 **따라다니는** 나트륨 (캡션) | 의인화도 비유다 → `어디에나 들어 있는` |

- **완충 어미를 겹치지 않는다.** `~해 보면` · `~정도예요` · `~인 편이에요` 를 한 문장에
  두 개 이상 쓰면 확신 없는 설명문이 된다. 근거(`source`)를 단 문장은 단정해도 된다.
- **낱말은 독자가 실제로 쓰는 것으로 고른다.** `포장 표시` 는 우리 쪽 말이고 매대 앞에서
  찾는 것은 `영양성분표` 다. 기존 편에 같은 자리가 있으면 **그 낱말을 먼저 본다.**

#### 표지 제목은 정보가 아니라 감정으로 연다

`아침마다 붓는 얼굴, 물 때문일까?` 는 정확하지만 남의 이야기로 읽힌다. 지금은
**`아침마다 왜 / 자꾸 부을까ㅠㅠ`** 다. 사용자가 `왜 붓는 거지?` · `왜 자꾸 부을까ㅠㅠ` 를
직접 예로 들며 "이런 감성이 더 좋겠다"고 했다.

- **구어체와 `ㅠㅠ` 를 표지에 쓴다.** 피드에서 스치는 한 줄이라 정확한 설명보다 자기
  이야기로 읽히는 쪽이 이긴다. **본문 카드는 그대로 `-습니다`체다** — 근거를 대는 자리다.
- 물음표 대신 `ㅠㅠ` 를 쓰면 질문 형식은 유지되면서 감정이 남는다.
- 다만 **`sub` 는 행동을 말한다** (`하루 나트륨부터 계산해 보기`). 표지 제목이 감정이면
  그 아래 한 줄이 무엇을 하러 들어가는지 잡아 줘야 한다.

## 레퍼런스의 서술 골격 (2026-08-19 채택)

옮겨 적은 원문은 [`../card_ref/reference-text.md`](../card_ref/reference-text.md) 에 있다
(`LIVE WELL ALL AROUND` 두 편). **레이아웃이 아니라 서술 방식만 가져왔다** — 그쪽은 번호
뱃지·연노랑 하이라이트 제목·박스 안 사진+목록을 쓰는데 우리 다섯 레이아웃에는 없다.

| 자리 | 레퍼런스가 하는 것 |
| --- | --- |
| 표지 제목 | **상황절 + 질문절** (`운동하고 식단까지 하는데 / 왜 몸은 그대로일까?`) |
| 표지 부제 | 이 편에서 **얻어 갈 것** (`요요 없이 체중 관리하는 진짜 다이어트 TIP 3`) |
| 본문 제목 | **반직관 선언문** (`적게 먹을수록 / 살은 더 많이, 빨리 찐다`) |
| 본문 | ① 흔한 행동 → ② **`하지만 몸은 이를 ~가 아니라 ~로 받아들여요`** → ③ 굵은 결론 |
| 목록 | 목록 위에 **소제목**을 단다 (`극단적 다이어트의 위험성` · `다이어트 원칙 3가지`) |
| 마지막 | **조건절 + 지시** (`붓기가 신경 쓰인다면 물부터 충분히 마셔보세요`) |

- **핵심은 ②의 반전이다.** 두 편 여덟 장에서 같은 구문이 반복된다 — 독자가 하는 행동을
  먼저 적고, `하지만 몸은` 으로 그 행동의 결과를 뒤집는다. 사실을 나열하는 것과 이것이
  다르다. 나트륨 편에서 세 장에 넣었다 (`직접 넣는 소금만 세면 넉넉해 보입니다.` /
  `나트륨을 줄이려고 반찬부터 덜어내는 사람이 많습니다.` / `짜게 먹은 다음 날 체중계
  숫자가 올라갑니다.` 뒤에 각각 `하지만` 절).
- **제목을 질문형으로만 채우지 않는다.** 질문은 표지 몫이고 본문 제목은 단정한다.
  `하루에 얼마나 괜찮을까?` 보다 `하루 2,000mg, 티스푼 한 개` 가 그 자리의 말이다.
- **수치와 전문 용어를 그대로 낸다.** 레퍼런스는 렙틴·그렐린·글리코겐·BMR 을 괄호 풀이만
  달고 쓴다. 쉽게 바꿔 말하려다 [위](#과잉-친절한-설명조도-ai-티다-2026-08-19--나트륨-편)의
  설명조로 되돌아가는 것보다 낫다.
- **가져오지 않은 것** — 밑줄 강조(우리 렌더러에는 `**굵게**` 한 종류뿐이다), 인물 사진
  (사람 없는 정물 규칙), `source` 없이 내보내는 것(우리는 카드마다 근거를 단다).
- **분량은 우리 칸이 정한다.** 레퍼런스는 한 장에 세 문단이 들어가지만 `stack` 은 사진 위
  **4줄이 한계**라 그대로 옮기면 출처 줄을 밀고 넘친다(실제로 한 번 넘쳤다).
  세 문단이 필요한 카드는 `plain` 이나 `split` 으로 보낸다.

## 다섯 장은 한 편의 글이다

**주제를 정하는 것과 흐름을 정하는 것은 다른 일이다.** 카드 다섯 장에 그 주제의 알 만한
사실을 하나씩 담으면 다섯 편의 짧은 글이 되고, 넘길 이유가 없어진다. 실제로 단백질 편
초안이 그랬다 — 분량 · 법적 분류 · 제품 종류(WPC/WPI) · 주의사항이 각각 다른 강의였다.

먼저 **한 문장짜리 논지**를 정하고, 다섯 장을 그 논지에 이르는 단계로 쪼갠다.

| 칸 | 하는 일 | 단백질 편 |
| --- | --- | --- |
| 1 · 표지 | 질문을 던진다 | 프로틴, 나에게도 필요할까? |
| 2 | **기준**을 세운다 | 하루 필요량 — 60kg이면 50g |
| 3 | **지금**을 확인한다 | 세 끼로 이미 얼마나 채워지나 |
| 4 | 둘의 **차이**가 답이다 | 남는 칸을 채우는 도구 |
| 5 | 그래서 어떻게 하나 | 쓸 때는 이렇게 |

- **각 카드는 앞 카드의 말이나 숫자를 받아서 시작한다.** 3번이 `앞의 50g을 음식으로
  옮기면` 으로 열고, 4번이 3번의 `남는 칸` 을 그대로 받는다. 이 이음말이 없으면 순서를
  바꿔도 읽히는데, 순서를 바꿔도 읽힌다는 것은 흐름이 없다는 뜻이다.
- **논지를 `cards.json` 의 `thesis` 에 적어 둔다.** 렌더에 쓰이지 않는 메모지만, 카드를
  고칠 때 무엇을 지켜야 하는지가 파일 안에 있어야 한다.
- **사슬을 끊는 곁가지는 뺀다.** 아까우면 마지막 카드의 한 줄로 접는다 — WPC/WPI 는
  본문 한 장을 차지하고 있었지만 지금은 `우유가 안 받는다면 → 유당을 걸러낸 WPI도 있어요`
  한 줄이다. 사실은 남고 흐름은 안 끊긴다.
- **마지막 카드 제목도 흐름의 일부다.** `먹기 전 알아둘 점` 은 어느 편에나 붙는 말이라
  네 번째 칸과 이어지지 않는다. 앞 장을 받는 제목(`쓸 때는 이렇게`)이어야 다섯 번째 칸이
  된다. 빨간 제목과 느낌표는 그대로 두어도 do/don't 목록으로 읽힌다.
- **레이아웃은 내용이 고른다.** 목록이 들어가는 칸은 글 폭이 넓은 `plain` 이어야 한다
  (`split` 은 604px 뿐이라 한 줄에 두세 어절이다). 그래서 단백질 편은 3번이 `plain`,
  4번이 `split` 으로 알룰로스 편과 순서가 다르다 — **레이아웃 순서를 고정하지 말 것.**

## cards.json 쓰는 법 (A_style)

레이아웃은 다섯 가지이고 각각 레퍼런스 한 장에 대응한다.

| `layout` | 모양 | 레퍼런스 (`card_ref/ref_origin/`) |
| --- | --- | --- |
| `cover` | 풀블리드 사진 + 하단 큰 제목 | `ref1.png` |
| `stack` | 상단 텍스트 + 하단 사진 | `ref2.png` |
| `split` | 좌 사진 + 우 텍스트 | `ref3.png` |
| `plain` | 텍스트 전면 | — |
| `notice` | 주의사항 목록 + 느낌표 | `ref4.png` |

표기는 둘뿐이다.

- 제목의 `{중괄호}` → 그 부분만 어두운 잉크 (`알룰로스{란?}`)
- 본문의 `**별표**` → 굵은 강조. 빈 줄은 문단 구분

**줄은 구(句) 경계에서 끊는다.** 문장 사이는 `clauseBreaks` 가 알아서 끊지만(마침표·쉼표 뒤),
한 문장이 두 줄을 넘길 때는 어디서 갈릴지를 **손으로 정한다** — `\n` 을 넣으면 `<br>` 이 된다.
브라우저에 맡기면 줄이 꽉 찬 지점에서 끊겨 한 덩어리가 갈라진다.

```
✗ 성인이 하루에 필요한 단백질은 체중 1kg당    ← 줄이 꽉 차서 여기서 끊긴다
  0.8~1g입니다.

✓ 성인이 하루에 필요한 단백질은
  체중 1kg당 0.8~1g입니다.
```

끊는 자리는 대개 **주어부·부사절이 끝나는 지점**이고, 강조(`**…**`)가 시작되기 바로 앞인 경우가
많다. 강조는 그 문장에서 새로 말하려는 부분이라 구가 거기서 갈리기 때문이다.

- **굵은 강조는 줄을 넘지 못한다.** `richText` 의 `\\*\\*(.+?)\\*\\*` 에서 `.` 이 개행에
  걸리지 않아서 `\n` 을 품은 `**…**` 는 **강조가 아예 적용되지 않는다.** 한 문장을 두 줄로
  끊으면서 전체를 강조하려면 `**앞줄**\n**뒷줄**` 처럼 두 벌로 적는다.
- **문구를 고치면 줄도 다시 본다.** 이게 손으로 끊는 대가다 — 글자 수가 바뀌면 예전 자리가
  더는 구 경계가 아니게 된다. 렌더 결과를 눈으로 확인하지 않고 문구만 고치지 말 것.
- 마침표·쉼표가 있는 자리에는 `\n` 을 넣지 않는다. `clauseBreaks` 가 이미 끊으므로 겹친다.

**카드에 나가는 글에는 줄표(`—`)를 쓰지 않는다.** 문장 뒤에 설명을 덧붙이는 그 부호가
사람이 쓴 글에서는 잘 안 보여서 **AI 가 쓴 티로 읽힌다** (사용자 지적). 줄표를 쓰고 싶어지는
자리는 대개 한 문장에 두 가지를 담고 있는 자리다 — 문장을 둘로 끊거나 어미로 잇는다.

```
✗ 그래서 볼 것은 하나입니다 — 남는 칸이 있는지.
✓ 그러니 남는 칸이 있는지부터 보세요.
```

`note` · `thesis` · `captionNote` 같은 **작업용 메모 필드에는 써도 된다** — 화면에 나가지
않는 글이다. 이 README 도 마찬가지다.

**줄을 갈라야 하면 쉼표나 마침표를 쓴다.** `clauseBreaks`(render.mjs)가 그 뒤에서 끊으므로
`<br>` 을 손으로 넣지 않아도 되고, 문구를 고쳐도 줄이 저절로 따라온다.

### `source` — 그 카드에 적은 사실의 근거

표지를 뺀 네 레이아웃이 받는다. 값이 없으면 아무것도 그리지 않는다 — **댈 근거가 없는
카드에 억지로 붙이지 말 것.** `출처 ·` 라벨은 렌더러가 붙이므로 내용만 적는다.

```json
"source": "식약처 「식품등의 표시기준」 · 건강기능식품 기능성 원료 목록"
```

- **한 줄에 들어가야 한다.** 넘치면 두 줄로 접히는데 `word-break: keep-all` 때문에
  어절 단위로 갈라져 `· 2형` / `당뇨 대상` 처럼 어중간하게 끊긴다 (실제로 그랬다).
  `split` 은 글 칸이 604px 뿐이라 특히 짧아야 한다 — 대략 20자 안쪽.
- **논문 서지사항을 적는 자리가 아니다.** 어디서 나온 얘기인지 알아볼 단서까지다.
  긴 인용이 필요하면 캡션(`out/caption.txt`)에 손으로 덧붙이는 편이 낫다.
- 위치는 카드 밑변이 아니라 **글 칸의 밑변**이다 — `stack` 은 아래가 사진, `split` 은
  왼쪽이 사진, `notice` 는 우하단이 느낌표라 밑변에 고정하면 그림 위로 올라간다.
  `stack` 의 자리는 사진 높이(596px)에 묶여 있으므로 사진을 키우면 함께 내린다.

## B_style 쓰는 법

`"style": "b"` 를 넣고 아래 다섯 레이아웃을 쓴다. 레퍼런스는 [`card_ref/card_3/`](../card_ref/card_3/)
의 일곱 장이고, **일곱 장이 한 편의 글**이라는 점은 A_style 과 같다.

| `layout` | 모양 | 받는 필드 |
| --- | --- | --- |
| `b-cover` | 전면 사진 + 가운데 두 줄 제목 + 아래 마크 | `title` |
| `b-intro` | 제목 + 본문 + 아래 세 칸(유형 미리보기) | `title` `body` `columns[{head,name}]` `source` |
| `b-type` | 눈썹·제목(위) · 라벨·값·본문(가운데) · 팁(아래) | `eyebrow` `title` `label` `value` `body` `tip` `tipLabel` `source` |
| `b-summary` | 제목 + 본문, 세로 가운데 | `title` `body` `source` |
| `b-outro` | 사진 + 가운데 마크 (글자 없음) | — |

세 장을 `b-type` 으로 두는 것이 이 형식의 골격이다 — **"당신은 세 유형 중 하나이고, 각
유형은 이 값을 쓴다"**. `value` 가 카드마다 한 눈에 바뀌는 숫자·시각이어야 카드를 넘길
이유가 생긴다. 유형이 셋이 아닌 주제라면 이 형식이 맞지 않는다.

### 줄바꿈은 전부 손으로 넣는다

**A_style 과 갈리는 가장 큰 지점이다.** A_style 은 마침표·쉼표 뒤에서 코드가 끊지만
(`clauseBreaks`), B_style 레퍼런스는 절 중간에서도 끊는다 — `연구를 종합하면 특정 시간대의
운동이` / `모든 사람에게 압도적으로 우월하다고 보기는 어려워요.` 자동 규칙으로는 그 자리를
못 맞추므로 `richTextB` 는 `clauseBreaks` 를 쓰지 않는다.

대가는 **문구를 고칠 때마다 줄을 다시 봐야 하는 것**이다. 상한은 이렇다 (32px · 글 칸 928px).

| 자리 | 한 줄 상한 |
| --- | --- |
| 본문(`body`) | **28자** |
| 팁(`tip`) | 26자 (라벨 칸 63px 을 뺀다) |
| 세 칸의 `head` | 8자 (셋을 합쳐 한 줄에 들어가야 한다) |
| 출처(`source`) | 24px 이므로 넉넉하지만 두 줄로 접히면 팁과 겹친다 |

굵은 강조(`**…**`)가 줄을 넘지 못하는 것은 A_style 과 같다 — `**앞줄**\n**뒷줄**` 로 쪼갠다.

### 본문이 32px 인 이유 (레퍼런스 실측)

A_style 은 "본문 44px 이 하한" 이라고 못 박아 뒀는데 **B_style 은 32px 이다.** 규칙을 어긴
것이 아니라 **다른 형식이라 다른 값을 잰 것**이다. 이 형식은 한 장에 눈썹·제목·라벨·값·
본문·팁을 다 담으므로 44px 로는 들어가지 않고, 대신 **사진을 어둡게 깔아 대비로 메운다.**
그래서 **밝은 사진을 고르면 이 형식은 무너진다** (아래 "사진").

아래는 레퍼런스 캡처(1179×2556 스마트폰 · 카드 영역 y 570~2043)를 1080 좌표계로 환산해
잉크 높이와 줄 간격을 잰 값이고, `card-b.css` 의 치수가 여기서 나왔다.

| 요소 | 잉크 높이 | 줄 간격 | 왼쪽 | 잉크 위쪽 |
| --- | --- | --- | --- | --- |
| 표지 제목 | 71 | 105 | 가운데 | 505 |
| 절 제목(`title`) | 52 | 74 | 76 | 141 (유형) · 334 (도입) |
| 눈썹(`eyebrow`) | 27 | — | 76 | 76 |
| 라벨(`label`) | 27 | — | **100** | 가운데 묶음 |
| 값(`value`) | 31 | — | **100** | 라벨 + 59 |
| 본문(`body`) | 30 | 62 | 76 / **100**(유형) | 값 + 103 |
| 팁(`tip`) | 30 | 50 | 76(라벨) · 139(글) | 1194 |
| 세 칸 라벨 | 30 | — | — | 1171 |
| 세 칸 이름 | 28 | — | — | 1238 |
| 칸 사이 세로선 | 96 높이 · 2px | — | 334 · 695 | 1167 |

- **유형 카드의 가운데 묶음은 세로 가운데다.** 레퍼런스 세 장의 본문 줄 수가 4·4·5 로
  다른데 묶음의 중심이 675±8px 로 일정했다. 위에 붙이면 줄 수에 따라 아래 여백이
  들쭉날쭉해진다. `b-summary` 도 같은 이유로 가운데다(실측 중심 674px).
- **가운데 묶음만 왼쪽이 100px 이다.** 눈썹·제목·팁은 76px 인데 이 묶음만 한 단 들어간다.
  실측값이고 이유는 모르지만 그대로 옮겼다.
- **칸 사이 세로선은 칸의 테두리가 아니다.** 레퍼런스의 선 위치가 균등 3분할이 아니었고
  (334 · 695) 선 좌우 여백이 46/41px 로 거의 같았다 — 칸은 글 길이만큼, 선은 두 칸 사이
  가운데다. 테두리로 만들면 남는 폭이 칸 사이로 몰릴 때 선이 오른쪽 칸에 붙는다.
  그래서 `render.mjs` 가 칸 사이에 `<i>` 를 끼우고 `1fr` 칸 안에서 가운데 정렬한다.

### 레퍼런스와 일부러 다르게 한 것

- **출처 한 줄(`source`)을 넣었다.** 레퍼런스에는 없다. 그런데도 두는 이유는 카드뉴스
  규칙이 "수치를 쓰는 대신 카드마다 근거를 단다" 이기 때문이다 — 카드만 캡처해 퍼가면
  캡션의 근거는 떨어져 나간다. 대신 **레이아웃을 흔들지 않는 크기·자리**로 넣었다
  (24px · 카드 밑변에서 26px). 표지와 마지막 장에는 붙이지 않는다.
- **마크는 우리 로고다.** 레퍼런스는 별표 문양 하나를 쓰지만 브랜드를 두 벌 만들 이유가
  없다. 자리(안쪽 장은 우상단, 표지·마지막 장은 가운데)는 레퍼런스 그대로다.
- **`transform` 으로 마크를 가운데 맞추지 말 것.** `transform` 이 스태킹 컨텍스트를 만들어
  로고의 `mix-blend-mode: screen` 이 이 상자 안에서만 합성되고, **뒤집힌 검정 사각형이
  그대로 남는다.** 어두운 사진에서는 안 보이므로 밝은 사진에서 처음 드러난다.
  좌우를 0 으로 펴고 img 를 `margin: 0 auto` 로 놓는다.

### `photoPosition` — 피사체가 글자 자리에 걸릴 때

B_style 은 글이 사진 위에 얹히므로 **피사체가 글자 자리에 걸리면 사진을 옮기는 것이 사진을
바꾸는 것보다 먼저다.** `photoPosition` 은 CSS `background-position` 그대로다.

```json
"photoPosition": "center 0%"
```

`center 0%` 는 사진의 위쪽을 보여주므로 피사체가 아래로 내려간다. 표지에서 실제로 이걸
썼다 — 마크(제목 아래 762px 자리)가 컵 테두리의 반사광 위에 얹혀 읽히지 않았고, 사진을
위로 당기니 마크가 어두운 창틀 위로 왔다. **원본이 4:5 에 가까우면 옮길 여지가 거의 없다** —
그때는 사진을 바꾼다.

## 사진

`photo` 에 이 폴더 기준 상대경로를 넣으면 그 파일이 들어간다. 비워 두면 `tone` 두 색으로
그라데이션 자리표시가 나오고 `photoHint` 문구가 하단에 찍힌다.

### Pexels 로 받기 (지금 쓰는 방법)

`.env.local` 에 `PEXELS_API_KEY` 를 넣고 두 단계로 쓴다.

```powershell
# 1) 카드마다 후보 여러 장 → assets/candidates/
node --env-file=.env.local docs\cardnews\fetch-photos.mjs --count=6

# 2) 눈으로 보고 고르기 (카드번호:후보번호)
node --env-file=.env.local docs\cardnews\fetch-photos.mjs --pick=1:2,2:1,3:2
```

**첫 장을 자동으로 물리지 않는 게 핵심이다.** 스톡 검색은 결과가 들쭉날쭉해서 —
`sugar cubes` 는 줄자·주사기 같은 당뇨 스톡 클리셰를, `coffee and cake` 는 원색이 강한
디저트를 끌어온다 — 자동으로 첫 장을 쓰면 세트 톤이 깨진 채 렌더까지 가버린다.
후보를 늘어놓고 **같은 조명·같은 배경색 계열로 셋을 고르는 것**이 이 방식의 요점이다.

검색어(`photoQuery`)가 결과를 거의 결정한다. 마음에 안 들면 검색어부터 바꿀 것.
레이아웃에 맞는 방향(portrait/landscape)은 자동으로 걸린다 (B_style 은 다섯 레이아웃 전부
세로다 — 카드를 통째로 덮는 4:5 슬롯이라 가로 사진은 위아래가 잘린다).

**한 카드만 다시 받을 때는 그 카드의 옛 후보를 먼저 지운다.** `--pick` 은 `<slug>-NN-cN--`
접두사로 파일을 찾는데, 다시 받으면 같은 접두사(`caffeine-04-c1--`)를 가진 옛 후보가 남아
**어느 쪽이 걸릴지 순서에 달린다.** 검색어를 바꿔 다시 받았는데 옛 사진이 확정되는 일이
실제로 생길 수 있다. `photo` 를 `null` 로 비우면 그 카드만 다시 받아지므로(나머지는
"이미 photo 있음" 으로 건너뛴다), 그때 `assets/candidates/<slug>-NN-*` 를 함께 지운다.

**B_style 은 어두운 정물만 쓴다.** 사진이 카드를 통째로 덮고 그 위에 32px 흰 글씨가
얹히므로, 밝은 사진을 고르면 형식 자체가 무너진다. 고를 때 보는 것은 예쁨이 아니라
**글자가 놓이는 자리가 비어 있고 어두운지**다 — 유형 카드라면 왼쪽 위(제목) · 왼쪽 가운데
(값·본문) · 왼쪽 아래(팁) 세 자리다. 세트 안에서 조명 계열도 맞춘다(이번 편은 전부
따뜻한 어둠으로 골랐고, 파란 조명 후보는 톤이 튀어 버렸다).

### 이미지 생성은 무료 등급에서 막혀 있다

`generate-photos.mjs` 는 붙여 뒀지만 **Gemini API 무료 등급은 이미지 모델의 일일 허용량이
0 이다.** 갓 발급한 키가 첫 호출부터 429 를 낸다 (2026-08 실측, `gemini-3.1-flash-lite-image`
· `gemini-3.1-flash-image` · `gemini-2.5-flash-image` · `gemini-3-pro-image` 모두 동일,
`imagen-4.0-*` 는 신규 키에 404). 소비자용 Gemini 앱/AI Studio 웹 UI 는 무료로 되므로
급하면 거기서 뽑아 `assets/` 에 넣으면 된다.

자동 생성이 필요해지면 그 프로젝트에만 결제를 붙이거나, Cloudflare Workers AI
(하루 10,000 Neurons 무료, 카드 불필요) 를 붙이는 쪽을 검토할 것.

## 출처 표기와 캡션

**출처는 두 종류이고 가는 곳이 다르다.**

| | 어디서 왔나 | 어디에 찍히나 |
| --- | --- | --- |
| 정보 출처 (`source`) | 카드에 적은 **사실**의 근거 | **카드 하단**에 작게 (표지 제외) |
| 사진 출처 (`photoCredit`) | 스톡 사진 촬영자 | `out/caption.txt` |

정보 출처를 캡션으로 내리지 않는 이유는 **카드만 캡처해 퍼가는 경우 근거가 떨어져
나가기 때문**이다. 성분 이야기는 숫자와 기준이 섞여 있어서 근거 없이 돌면 그 자체가
잘못된 정보가 된다. 사진 출처는 반대로 표기 의무가 없고(Pexels 라이선스) 다섯 장마다
같은 줄이 들어가면 읽는 데 방해가 되므로 캡션에 모은다.

렌더하면 `out/caption.txt` 가 함께 나온다. 본문 문구 · 사진 출처 · Pexels 링크 ·
해시태그(`cards.json` 의 `hashtags`)가 들어 있다. **인스타그램 본문에 그대로 붙이면 된다.**

### `caption` — 본문 문구

`cards.json` 의 `caption` 이 캡션 맨 위에 그대로 올라간다. 비워 두면 표지 제목만 올라가므로
**카드를 먼저 만들고 캡션은 나중에 붙여도 렌더가 멈추지 않는다.**

- **카드에 없는 사실을 캡션에서 새로 말하지 않는다.** 카드는 `source` 로 근거를 달지만
  캡션에는 그 자리가 없다. 캡션은 카드에 있는 이야기를 풀어 쓰고 넘겨보게 만드는 데까지다.
- **첫 덩어리가 곧 후킹이다.** 피드에서는 두어 줄 뒤가 `... 더 보기` 로 접힌다.
- 줄바꿈은 손으로 넣는다 (카드 본문과 반대다). 인스타그램은 폭이 좁고 자동 줄바꿈이
  어절을 아무 데서나 끊으므로, 뜻의 단위로 끊어 두는 편이 읽힌다.

#### 양식과 길이 (2026-08-18 확정)

**다섯 덩어리 · 전체 10~12줄**로 고정한다. 그 전에는 카드 다섯 장을 캡션에서 한 번 더
설명해서 15줄이 넘었고, `더 보기` 를 눌러야 할 이유가 사라졌다 — **캡션은 카드의 요약이
아니라 카드를 열게 하는 문 앞의 한 마디다.**

| 덩어리 | 내용 | 이모지 |
| --- | --- | --- |
| 1 | 후킹 — 표지 제목을 한 줄로 (`OO, 진짜 ~일까?`) | 👀 |
| 2 | 한 줄 소개 — 어디서 흔히 보이는 것인지 | 🌿 |
| 3 | 핵심 사실 서너 줄 — 숫자 하나는 `!` 로 끝내 리듬을 준다 | — |
| 4 | `다만` 으로 여는 주의 두어 줄 | — |
| 5 | 마무리 한 줄 — `OO, ~하면 ~할 수 있어요.` 꼴 (💡 로 끝) | 💡 |

- **덩어리 사이는 빈 줄로 띄운다.** 이모지는 덩어리 끝에만 붙이고 문장 중간에 뿌리지 않는다.
- **마지막 줄은 브랜드 사인오프이되 편마다 문장을 갈아 끼운다** (2026-08-19 수정). 자리·길이·
  `주제, ~하면 ~할 수 있어요. 💡` 꼴·이모지는 고정이고 **문장은 매번 새로 쓴다.**
  - 알룰로스·단백질 편이 `OO, 알고 먹으면 더 현명하게 활용할 수 있어요.` 로 **글자까지 같아서**
    사용자가 "저번이랑 아예 똑같이 가는 건 별로" 라고 했다. 예전 규칙은 "주제 이름만
    갈아끼우고 문형은 그대로" 였는데, **세 편째부터는 그게 복사로 읽힌다.**
  - 나트륨 편은 `나트륨, 어디에 많은지만 알아도 훨씬 줄일 수 있어요. 💡` 다.
  - 새 편을 쓸 때 **기존 편들의 마지막 줄을 먼저 읽고** 겹치지 않게 쓴다.
- 위 표대로 쓴 예가 알룰로스 편([`cards.json`](cards.json))과 단백질 보충제 편
  ([`../cardnews_0818/cards.json`](../cardnews_0818/cards.json))의 `caption` 이다.

Pexels 라이선스는 출처 표기를 요구하지 않는다. 그래서 카드에서 뺐다. 다만 API 가이드라인이
링크백을 권하고 신청서에도 그렇게 적었으므로, **캡션의 Pexels 링크는 지우지 말 것.**

생성 이미지를 쓰게 되면 `photoCredit` 이 `이미지: AI 생성` 으로 채워진다. 그때는 카드에
표기가 필요한지 다시 판단할 것 — 국내 AI 생성물 표시 의무를 확인해야 한다.

## 주제가 늘면 폴더를 나눈다

`docs/cardnews_0818/` 처럼 **주제마다 폴더 하나**다. 한 폴더에 `cards.json` · `assets/` ·
`out/` 이 들어가고, 렌더러에 그 json 경로를 넘기면 된다.

**B_style 편은 `cardnews_b_<MMDD>/` 다.** 폴더 이름만 보고 어느 형식인지 알 수 있어야
후보 사진을 고르는 기준(어두운 정물인지)이 폴더를 열기 전에 정해진다.

```powershell
node docs\cardnews\render.mjs docs\cardnews_0818\cards.json
node --env-file=.env.local docs\cardnews\fetch-photos.mjs --count=6 docs\cardnews_0818\cards.json
```

**형식은 복사하지 않는다.** `render.mjs` · `fetch-photos.mjs` · `card.css` · `card-b.css` ·
`fonts/` · `assets/logo.png` · `assets/bang.png` 는 이 폴더 것을 그대로 쓰고, 새 폴더에는 **내용물만**
둔다 (`cards.json` 과 그 주제의 사진). 형식을 복사하면 두 벌이 되어 한쪽만 고쳐지고,
세트끼리 톤이 갈리는 순간 한 계정의 콘텐츠로 안 읽힌다.

- 두 스크립트는 **데이터(json)가 있는 폴더**를 기준으로 사진과 출력물을 찾는다
  (`render.mjs` 의 `DATA_DIR`). 인자를 생략하면 예전처럼 이 폴더의 `cards.json` 이다.
- 새 폴더에 `.gitignore` 를 함께 둔다 — `assets/candidates/` 를 거르는 용도이며 이 폴더
  것을 그대로 복사하면 된다.
