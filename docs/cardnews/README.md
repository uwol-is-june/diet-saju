# 카드뉴스 렌더러

성분·궁금증 콘텐츠를 SNS 카드뉴스(1080×1350 PNG)로 뽑는다.
레퍼런스는 [`docs/card_ref/`](../card_ref/) 의 "다시," 카드 4종이다.

```powershell
node docs\cardnews\render.mjs                    # cards.json → out/*.png + caption.txt
node docs\cardnews\render.mjs docs\cardnews\다른주제.json
```

> **일반 터미널(PowerShell/cmd)에서 실행할 것.** 파일 접근이 제한된 셸에서 돌리면
> 브라우저가 임시 HTML 을 읽지 못해 오류 화면이 그대로 PNG 로 찍힌다.
> 그런 경우 렌더러가 "스크린샷이 생성되지 않았습니다" 로 멈춘다.

## 읽히는 곳이 인스타그램이라는 것

이 카드는 **피드에서 폭 400px 안팎으로 축소되어** 읽힌다. 설계가 여기서 갈린다.

- **본문 44px 가 하한이다.** 1080px 기준 34px 는 화면에서 12px 남짓이라 본문으로 못 쓴다.
  44px 가 화면에서 16px 정도가 되는 값이다. 좁아 보인다고 글자를 줄이지 말고 **문장을 줄일 것.**
- **한 카드에 한 가지만 담는다.** 손가락으로 넘기며 보는 포맷이라, 카드를 꽉 채우면 넘겨버린다.
- **어절 단위로 줄바꿈한다** (`word-break: keep-all`). 기본값으로 두면 "못합니다."가
  "못합" / "니다." 로 갈라져 고아 음절이 남는다. 줄이 짧을수록 자주 생긴다.
- **마침표·쉼표 뒤에서 줄을 바꾼다** (`clauseBreaks`, render.mjs). 브라우저에 맡기면 줄이
  꽉 찼을 때 아무 어절에서나 끊겨 문장이 어중간하게 잘린다. 절 끝에서 끊으면 한 줄이 뜻의
  단위가 되어 읽는 리듬이 산다 — 풀이 본문에서 문장마다 문단을 나누는 것
  ([lib/reading/line-breaks.ts](../../lib/reading/line-breaks.ts))과 같은 이유다.
  `0.5g` 이나 `1,000` 은 **뒤에 공백이 없어서** 애초에 걸리지 않는다 (예외 목록 불필요).
  이 때문에 글이 길어지므로 `stack` 의 사진 높이를 레퍼런스보다 낮춰 뒀다.
- **표지는 자간을 덜 조이고 행간을 더 준다.** 큰 글씨에 본문과 같은 자간(-0.055em)을 쓰면
  글자가 뭉친다. 지금은 -0.035em · 행간 1.3 이다.
- **사진 출처를 카드에 찍지 않는다.** 다섯 장마다 같은 줄이 들어가면 읽는 데 방해가 된다.
  `out/caption.txt` 로 모아 인스타그램 본문에 한 번 붙인다 (아래 참조).

## 왜 이 구조인가

**형식은 코드가 만들고 내용만 사람이(또는 LLM 이) 채운다.** 이 저장소가 사주 계산과
해석을 가른 것과 같은 이유다 — 이미지 생성 모델에 레이아웃을 맡기면 한글이 깨지고
카드마다 톤이 달라져서, 한 세트로 묶이지 않는다.

| 파일 | 역할 |
| --- | --- |
| `card.css` | 레퍼런스를 옮긴 디자인. 팔레트·치수·글자 크기의 단일 소스 |
| `cards.json` | 카드별 내용 (제목·본문·사진 경로·해시태그) |
| `render.mjs` | 데이터 + CSS → HTML → PNG + caption.txt |
| `fetch-photos.mjs` | Pexels 에서 후보 사진 받기 → 고른 것만 확정 |
| `extract-logo.mjs` | 레퍼런스에서 로고 잘라내기 (한 번만) |
| `generate-photos.mjs` | Gemini 이미지 생성 (**무료 등급에서는 못 쓴다**, 아래 참조) |
| `fonts/` | 나눔스퀘어 네오 woff2 4종 |

브라우저는 **시스템에 깔린 Edge 를 헤드리스로** 쓴다. playwright 를 의존성으로 들이지
않기 위해서이며 [`scripts/render-icons.mjs`](../../scripts/render-icons.mjs) 와 같은 판단이다.
다른 크로미움을 쓰려면 `EDGE_PATH` 환경변수로 경로를 넘긴다.

## 폰트

**나눔스퀘어 네오로 고정한다.** `fonts/` 의 woff2 4종(Regular 400 · Bold 700 ·
ExtraBold 800 · Heavy 900)을 `@font-face` 로 물린다. 네이버 배포 폰트이고 상업적 사용이
자유롭다.

- `card.css` 의 `%FONTS%` 를 `render.mjs` 가 절대 경로로 바꿔 넣는다. HTML 이 임시 폴더에
  쓰이므로 상대 경로로 두면 폰트를 못 찾는다.
- 렌더 시 `--allow-file-access-from-files` 를 준다. `@font-face` 는 이미지와 달리 교차 출처
  검사를 받아서 이 플래그가 없으면 **조용히 폴백 폰트로 그려진다** — 오류가 안 나므로
  자간이 미묘하게 다른 결과물이 나올 때까지 모른다.
- `fonts/` 를 지우면 폴백으로 떨어져 크기·자간이 달라진다. 지우지 말 것.

## 로고

**레퍼런스에서 잘라낸 이미지를 그대로 쓴다** (`assets/logo.png`, 124×40).
도형으로 다시 그리면 그 순간 변형이 되므로 SVG 로 흉내내지 않는다.

```powershell
node docs\cardnews\extract-logo.mjs   # ref2.png → assets/logo.png (한 번만)
```

잘라낸 것은 **흰 바탕 위의 회색 로고 한 장**뿐이다. 어두운 사진 위에 밝은 로고가 필요한
커버는 CSS 가 뒤집어 쓴다 (`filter: invert(1)` + `mix-blend-mode: screen`). 두 벌을 만들면
나중에 한쪽만 바뀐다.

- **`.logo` 에 `z-index` 를 주지 말 것.** 스태킹 컨텍스트가 생기면 `mix-blend-mode` 가 그
  상자 안에서만 합성되어 흰 바탕이 그대로 남는다 (실제로 커버에 검은 박스가 나왔다).
  로고는 DOM 에서 사진·스크림보다 뒤에 오므로 z-index 없이도 위에 그려진다.
- 원본 벡터 파일을 받으면 `extract-logo.mjs` 를 지우고 그 파일로 교체한다.

## cards.json 쓰는 법

레이아웃은 다섯 가지이고 각각 레퍼런스 한 장에 대응한다.

| `layout` | 모양 | 레퍼런스 |
| --- | --- | --- |
| `cover` | 풀블리드 사진 + 하단 큰 제목 | `ref1.png` |
| `stack` | 상단 텍스트 + 하단 사진 | `ref2.png` |
| `split` | 좌 사진 + 우 텍스트 | `ref3.png` |
| `plain` | 텍스트 전면 | — |
| `notice` | 주의사항 목록 + 느낌표 | `ref4.png` |

표기는 둘뿐이다.

- 제목의 `{중괄호}` → 그 부분만 어두운 잉크 (`알룰로스{란?}`)
- 본문의 `**별표**` → 굵은 강조. 빈 줄은 문단 구분

**본문 줄바꿈은 자동에 맡긴다.** 손으로 `\n` 을 넣으면 문구를 고칠 때마다 줄이 넘쳐서
다시 맞춰야 한다. `notice` 의 `detail` 처럼 짧고 모양이 고정된 곳에서만 쓴다.

## 사진

`photo` 에 이 폴더 기준 상대경로를 넣으면 그 파일이 들어간다. 비워 두면 `tone` 두 색으로
그라데이션 자리표시가 나오고 `photoHint` 문구가 하단에 찍힌다.

### Pexels 로 받기 (지금 쓰는 방법)

`.env.local` 에 `PEXELS_API_KEY` 를 넣고 두 단계로 쓴다.

```powershell
# 1) 카드마다 후보 여러 장 → assets/candidates/
node --env-file=.env.local docs\cardnews\fetch-photos.mjs --count=6

# 2) 눈으로 보고 고르기 (카드번호:후보번호)
node --env-file=.env.local docs\cardnews\fetch-photos.mjs --pick=1:2,2:1,3:2
```

**첫 장을 자동으로 물리지 않는 게 핵심이다.** 스톡 검색은 결과가 들쭉날쭉해서 —
`sugar cubes` 는 줄자·주사기 같은 당뇨 스톡 클리셰를, `coffee and cake` 는 원색이 강한
디저트를 끌어온다 — 자동으로 첫 장을 쓰면 세트 톤이 깨진 채 렌더까지 가버린다.
후보를 늘어놓고 **같은 조명·같은 배경색 계열로 셋을 고르는 것**이 이 방식의 요점이다.

검색어(`photoQuery`)가 결과를 거의 결정한다. 마음에 안 들면 검색어부터 바꿀 것.
레이아웃에 맞는 방향(portrait/landscape)은 자동으로 걸린다.

### 이미지 생성은 무료 등급에서 막혀 있다

`generate-photos.mjs` 는 붙여 뒀지만 **Gemini API 무료 등급은 이미지 모델의 일일 허용량이
0 이다.** 갓 발급한 키가 첫 호출부터 429 를 낸다 (2026-08 실측, `gemini-3.1-flash-lite-image`
· `gemini-3.1-flash-image` · `gemini-2.5-flash-image` · `gemini-3-pro-image` 모두 동일,
`imagen-4.0-*` 는 신규 키에 404). 소비자용 Gemini 앱/AI Studio 웹 UI 는 무료로 되므로
급하면 거기서 뽑아 `assets/` 에 넣으면 된다.

자동 생성이 필요해지면 그 프로젝트에만 결제를 붙이거나, Cloudflare Workers AI
(하루 10,000 Neurons 무료, 카드 불필요) 를 붙이는 쪽을 검토할 것.

## 출처 표기와 캡션

렌더하면 `out/caption.txt` 가 함께 나온다. 커버 제목 · 사진 출처 · Pexels 링크 ·
해시태그(`cards.json` 의 `hashtags`)가 들어 있다. **인스타그램 본문에 그대로 붙이면 된다.**

Pexels 라이선스는 출처 표기를 요구하지 않는다. 그래서 카드에서 뺐다. 다만 API 가이드라인이
링크백을 권하고 신청서에도 그렇게 적었으므로, **캡션의 Pexels 링크는 지우지 말 것.**

생성 이미지를 쓰게 되면 `photoCredit` 이 `이미지: AI 생성` 으로 채워진다. 그때는 카드에
표기가 필요한지 다시 판단할 것 — 국내 AI 생성물 표시 의무를 확인해야 한다.

## 남은 것

- `out/` 은 렌더 결과물이다. 주제가 늘어나면 `out/<slug>/` 로 나누는 편이 낫다.
