# 디자인 토큰 — 컬러 팔레트와 부품 규격

팔레트와 부품 규격의 **출처와 선택 근거**를 남긴 문서다. 적용된 값의 기준은 `app/globals.css` 이고,
대비비는 `lib/design/tokens.test.ts` 가 그 파일을 파싱해 검증한다.
색을 바꿀 때는 globals.css 1층(`--raw-*`)을 고치고 이 문서의 근거도 갱신한다.

## 출처

[web.dasii.kr](https://web.dasii.kr/) — "다시 · 다이어트 보조제 성분 분석 및 후기 서비스".
Next.js + Tailwind v4 앱이라 CSS 번들(`/_next/static/chunks/*.css`)의 `@theme` 토큰을
그대로 읽었다. 추출 시점: 2026-08-12. 스크린샷 샘플링이 아니라 원본 토큰값이다.

## dasii 에서 무엇을 가져오고 무엇을 버렸나 (TASK-75 · 2026-08-19)

**"색만 가져왔다" 는 이제 사실이 아니다.** 저쪽 CSS 번들과 실제 마크업을 다시 뜯어 보니
층이 셋이고, **둘을 가져오고 하나를 버렸다.**

| 층 | 무엇 | 판단 |
| --- | --- | --- |
| ① 브랜드 팔레트 | `green50/100/500/600` · `gray50~900` · `gray-box` · `blue500` · `red` · `star-yellow` | **이미 우리 `--raw-*` 와 값이 같다.** 아래 "브랜드 토큰" 이 그것이다 — 할 일이 없었다 |
| ② 타이포·부품 규격 | `title-lg/md/sm` × 굵기 · 높이 48px · radius 12px · 누를 때 1px | **가져왔다** (아래) |
| ③ shadcn/ui 시맨틱 층 | `--background`·`--foreground`·`--primary`·`--muted`·`--ring`·`--radius` + `.dark` | **버렸다** (아래) |

### ③ shadcn 시맨틱 층을 버린 이유 셋

1. **토큰 이름이 세 번째 체계가 된다.** 우리는 `--raw-*`(무슨 색) → `--color-*`(어디에)
   2층이고 `lib/design/tokens.test.ts` 가 `globals.css` 를 **파싱해서** 검증한다.
   `--background`·`--muted`·`--ring` 이 들어오면 같은 뜻의 이름이 두 벌이 된다.
2. **다크모드 한 벌이 딸려 온다.** "다크 모드는 도입하지 않는다" 확정과 부딪힌다.
3. **포커스 링이 우리 접근성 기준에 미달한다.** 저쪽은 `--ring: #a1a1a1` 이고
   **흰 배경 대비 2.58:1** 이다 (WCAG 1.4.11 은 3:1). 우리 전역 `:focus-visible` 은
   green600 으로 **3.10:1** 이라 이미 통과한다. **링 색은 우리 것을 유지한다.**

**저쪽 클래스 문자열을 그대로 복사하지 말 것** — `bg-muted`·`text-foreground`·`border-input`
은 전부 이 버린 층의 이름이다. 규격(높이·radius·굵기·상태)만 옮기고 색은 우리 시맨틱 토큰으로 쓴다.

### 회색이 두 벌인 것에 속지 말 것

저쪽 코드에는 Tailwind 기본 `gray-200`(`#e5e7eb`)과 브랜드 `gray200`(`#c9cccf`)이
**함께** 살아 있다 (`gray-500` #6a7282 vs `gray500` #6d676c 도 마찬가지). 클래스 이름
한 글자(하이픈) 차이다. **우리는 브랜드 쪽만 쓴다.**

## 부품 규격 — 단일 소스는 `components/ui/`

색만 규율하고 높이·radius 는 파일마다 달랐다. 지금은 규격도 한 곳에 있다.

| 부품 | 값 | 사는 곳 |
| --- | --- | --- |
| 주 버튼 | h-12(48px) · rounded-xl(12px) · font-semibold · 누를 때 `translate-y-px` | `components/ui/Button.tsx` |
| 보조 버튼 | 같은 규격 · `variant="outline"` / `"ghost"` | 같은 파일 |
| 작은 버튼 | `size="compact"`(40px) · 아이콘은 `size="icon"`(36px) | 같은 파일 |
| 입력 | min-h-12(48px) · rounded-xl · px-4 | `components/ui/field.ts` (`FIELD_BASE`) |

- **입력 높이가 44 → 48px 로 커졌다.** `min-h-11` 은 **터치 타깃 최소 크기**라 올리는 것은
  안전하다. 대신 `SajuForm` 은 드롭다운이 여섯 줄이라 **폼 전체가 세로로 길어진다** —
  390px 전체 높이 1,890px 로 확인했다. 줄일 때 44px 아래로 내려가지 않는지 볼 것.
- **`SelectShell` 을 부품으로 흡수하지 않았다.** 화살표 규칙은 `globals.css` 의
  `.select-shell` 하나이고 `birth-input.test.ts` 가 `<select` 개수와 껍데기 개수를
  **대조한다.** 새 껍데기를 만들면 그 검사가 세는 대상이 갈린다.
- **`LikeButton` 은 부품을 쓰지 않는다.** 켜짐/꺼짐이 있는 **칩**이라 variant 축이 다르다
  (`aria-pressed`). 필 모양인 것도 `/reading/[type]` 의 유형 줄 칩과 같은 계열이다.

### 주 버튼을 검정으로 바꿨다 (TASK-71 뒤집기)

TASK-71 은 필 모양 + `brand-solid`(초록)였다. 이유는 "레퍼런스의 검정 필을 쓰려면 새 토큰과
대비 검증이 필요하다" 였는데, **재보니 그 유보 사유가 사라졌다.**

| | 값 |
| --- | --- |
| 면 `--color-ink-solid` = `--raw-gray-900`(#181a1b) | 저쪽 #171717 과 **채널당 1~4 차이** — 새 원시값을 만들지 않았다 |
| 흰 글씨 대비 | **17.46:1** |
| hover `--raw-gray-700`(#363a3d) | **11.48:1** |

- **hover 가 밝은 쪽으로 간다.** 검정 면은 더 어두워질 자리가 없다 — 초록 버튼과 방향이
  반대인 것이 의도이고 `tokens.test.ts` 가 그 방향까지 검사한다.
- **비활성은 저쪽을 따르지 않는다.** 저쪽은 회색 면(3.91:1)인데 우리는 **면을 비운다** —
  근거는 아래 "채운 버튼의 사각지대" 절이다. 검정이든 초록이든 비활성 처리는 하나다.
- **브랜드가 초록인 것과 충돌하지 않는다.** dasii 자신이 초록 브랜드에 검정 버튼이다.
  초록은 연한 강조 면·칩·링·포커스 링으로 계속 산다.
- 모양도 `rounded-full` → **`rounded-xl`** 이다. 필은 목업(`docs/ui_ref/*.png`) 쪽 모양이고
  저쪽 실물은 12px 사각 필이다.

### 타이포 스케일과 제목 전용 웹폰트

`title-lg/md/sm`(24/30 · 20/24 · 18/24px) × `title-bold/extrabold`(700·800)이고
`globals.css` 의 `@layer utilities` 에 있다.

- **굵기 800 은 폰트가 있어야 뜻이 있다.** 시스템 한글 폰트에 800 이 없어 700 으로 떨어진다.
  그래서 **나눔스퀘어 네오 ExtraBold 한 벌**을 제목 자리에만 받았다 — 예산 게이트
  (한 벌 300KB)를 **112KB** 로 통과했다. 원본·라이선스(SIL OFL 1.1)·서브셋 방법·실측표는
  `public/fonts/README.md` 에 있다.
- **본문은 시스템 폰트 그대로다.** 본문까지 얹으면 2,000자 스트리밍이 폰트 로드에 묶인다
  (TASK-71 이 웹폰트를 뺀 이유가 그것이다).
- **`title-sm`(18px)과 `.reading h2`(18px)는 같은 값이지만 이름을 합치지 않았다.** 전자는
  화면 부품의 제목, 후자는 **모델이 돌려준 마크다운**의 제목이라 사는 곳이 다르다
  (`.reading h2` 는 `@layer` 밖이라 유틸리티를 이기도록 일부러 그렇게 둔 규칙이다).
  **크기·행간·폰트를 같은 값으로 맞춰 뒀으니 한쪽을 바꾸면 다른 쪽도 같이 볼 것** —
  어긋나면 계약이 깨져 원문 폴백으로 갈 때만 제목이 달라 보인다 (TASK-67 이 겪은 그 버그다).

## 브랜드 토큰

Tailwind 기본 스케일과 이름이 다른(하이픈 없는 `green500` 형태) 것들이 이 서비스가
직접 정의한 값이다. 키컬러는 **그린**이고, 블루는 링크/보조, 레드는 에러 전용이다.

### 그린 (primary)

| 토큰 | HEX | 용도 (사이트 관찰) |
| --- | --- | --- |
| `green50` | `#EAFAF2` | 배지·강조 블록 배경 |
| `green100` | `#D5F6E4` | 테두리, 연한 구분선 |
| `green500` | `#50D88F` | 키컬러. 버튼·활성 상태 |
| `green600` | `#25A762` | hover/press, 그린 위 텍스트 |

`green500` 은 밝아서 흰 텍스트 대비가 부족하다(대비비 약 1.9:1).
버튼 라벨은 `green600` 배경이나 어두운 잉크색을 써야 WCAG AA 를 넘긴다.

거의 흰색이라 단색으로 대체해도 시각차가 거의 없다. 히어로 영역에만 쓰는 것을 권장.

## 적용 결과 (TASK-16 완료, 2026-08-13)

서비스 정체성이 "두 유형 유지 + 브랜드는 그린"으로 확정되어 이 팔레트를 도입했다.
기존 보라색(`#7c3aed`) + 종이질감 뉴트럴은 제거됐다.

### 원본을 그대로 쓸 수 없었던 이유

**출처 팔레트에 접근성 문제가 있었다.** 실측한 대비비:

| 조합 | 대비비 | AA(4.5:1) |
| --- | --- | --- |
| `green500` + 흰 텍스트 | 1.82:1 | ❌ |
| `green600` + 흰 텍스트 | 3.10:1 | ❌ |
| `green600` 텍스트 on 흰 배경 | 3.10:1 | ❌ |
| `blue500`(링크) on 흰 배경 | 3.54:1 | ❌ |
| `red`(에러) on 흰 배경 | 3.53:1 | ❌ |
| `green600` on `green50` (배지) | 2.87:1 | ❌ |

이 문서 초안은 "버튼 라벨은 `green600` 배경을 쓰면 AA 를 넘는다"고 적었지만,
실제로는 3.10:1 로 **넘지 못한다.** 계산해 보고 정정했다.

### 두 가지 대응

**1. 연한 그린 면은 어두운 잉크와 짝짓는다**

`green500` 을 어둡게 바꾸는 대신 텍스트를 어둡게 했다. 키컬러의 밝은 인상을 살리면서
`#181A1B` 조합으로 **9.61:1** 을 얻는다. hover(`green600`)도 5.64:1 로 통과한다.

> 이 조합은 **채운 버튼에서는 2026-08-13 에 교체됐다** (아래 "채운 버튼의 사각지대").
> `--color-brand` 계열은 이제 연한 강조 면·스트리밍 커서·선택 링에만 쓴다.

**2. 텍스트용 파생 shade 추가**

원본에 없던 값이다. 각각 흰 배경(또는 해당 연한 배경)에서 4.5:1 을 겨우 넘는
가장 밝은 값으로 잡았다 — 필요 이상으로 어둡게 만들지 않기 위해.

| 파생 토큰 | HEX | 유래 | 용도 |
| --- | --- | --- | --- |
| `--raw-green-700` | `#1C7D4A` | green600 을 어둡게 | 연한 배경 위 브랜드 텍스트, 목(木) 배지, 채운 버튼 배경 |
| `--raw-green-800` | `#166237` | green700 을 더 어둡게 | 채운 버튼 hover |
| `--raw-blue-700` | `#296ACC` | blue500 | 링크, 수(水) 배지 |
| `--raw-red-700` | `#C92E3A` | red | 에러 텍스트, 화(火) 배지 |
| `--raw-yellow-700` | `#8A6F18` | starYellow | 경고 텍스트, 토(土) 배지 |
| `--raw-gray-450` | `#8F959A` | gray400 | 폼 컨트롤 경계 (3:1 확보) |
| `--raw-red-100` / `yellow-100` | `#FFE7E9` / `#FEF8E6` | 각 색 + 흰색 88% | 상태 배경 |

`gray600` 은 여전히 정의하지 않았다. 쓸 자리가 없었다.

### 오행 배지

전통 색 대응(목=녹, 화=적, 토=황, 금=백, 수=흑/청)을 팔레트 안에서 표현했다.
각 색을 흰색과 88% 섞어 배경을 만들고, 그 배경에서 4.5:1 을 넘는 전경을 계산했다.

| 오행 | 배경 | 전경 | 대비비 |
| --- | --- | --- | --- |
| 목 | `#E5F4EC` | `#1C7D4A` | 4.53:1 |
| 화 | `#FFE7E9` | `#C92E3A` | 4.54:1 |
| 토 | `#FEF8E6` | `#8A6F18` | 4.53:1 |
| 금 | `#EDEDED` | `#6D676C` | 4.71:1 |
| 수 | `#E7F0FF` | `#296ACC` | 4.54:1 |

TASK-10 의 OG 이미지도 이 토큰을 쓴다. 브랜드 그린과 목(木) 배지가 같은 계열이므로,
**진한 그린 채움(`bg-brand-solid`)은 주 액션에만** 쓰고 배지는 연한 톤으로 유지한다.

### 채운 버튼의 사각지대 (TASK-21, 2026-08-13)

`사주 풀이 받기` 버튼이 **초록 배경 + 검은 글씨**라 눈에 안 들어온다는 지적이 있었다.
이 조합은 실수가 아니라 위의 접근성 대응이었지만, 주 액션이 주 액션으로 안 보이면
접근성을 지키고 사용성을 잃은 것이다.

**"흰 글씨로 바꾸기" 만으로는 안 되고, "조금만 어둡게" 는 더 나쁘다.** 실측:

| 배경 | 흰 글씨 | 어두운 잉크 `#181A1B` | 통과 |
| --- | --- | --- | --- |
| `green500` `#50D88F` (기존) | 1.82 | 9.61 | 잉크만 |
| `green600` `#25A762` | 3.10 | 5.64 | 잉크만 |
| `#1F9155` (중간값) | 4.01 | 4.36 | **둘 다 미달** |
| **`green700` `#1C7D4A`** | **5.14** | 3.39 | **흰 글씨만** |
| `green800` `#166237` (hover) | 7.40 | 2.67 | 흰 글씨만 |

밝은 쪽에서 어두운 쪽으로 내려오는 동안 **어느 글씨색도 통과하지 않는 구간**을 지난다.
잉크가 4.5 아래로 떨어지는 지점(`#25A762` 부근 아래)과 흰 글씨가 4.5를 넘는 지점
(`#1C7D4A` 부근 위) 사이가 그것이다. 그래서 타협값은 존재하지 않고, 연한 면(잉크)이나
충분히 어두운 면(흰 글씨) 둘 중 하나를 골라야 한다.

**결론: 채운 버튼용 토큰을 따로 만들었다.**

| 토큰 | 값 | 흰 글씨 대비 |
| --- | --- | --- |
| `--color-brand-solid` | `green700` | 5.14:1 |
| `--color-brand-solid-hover` | `green800` | 7.40:1 |
| `--color-on-brand-solid` | `#FFFFFF` | — |

**비활성 상태는 회색으로 채우지 않는다.** 여기에도 같은 사각지대가 있다. 흰 글씨를 유지하려면
회색이 4.5:1 을 넘을 만큼(≈`#70767B` 이상) 어두워야 하는데, 그러면 `green700` 과 명도가
거의 같아져(`gray500` 대 `green700` = **1.07:1**) "누를 수 없음" 이 초록↔회색이라는 **색상
차이로만** 남는다. 색각 이상에서는 두 상태가 같아 보인다. 기존 `line-strong` `#8F959A` 도
흰 글씨 3.03:1 로 애초에 불가능했다.

→ 면을 비우는 쪽으로 간다: `--color-brand-solid-disabled` = `gray50` `#F1F2F3` +
`--color-on-brand-solid-disabled` = `gray500` `#6D676C` (4.7:1). 활성 버튼과 명도차가
크게 벌어져 색을 못 봐도 구분된다. 토큰 테스트가 이 명도차(3:1)를 고정한다.

기존 `--color-brand` / `--color-on-brand` 는 **그대로 둔다.** 연한 강조 면
(`FirstVisitNotice` 배경, 선택된 유형 칩, 스트리밍 커서, 현재 대운 링)에는 여전히 맞다.
그래서 토큰 테스트의 "흰 텍스트는 브랜드 면에서 쓸 수 없다" 단정도 유지한다.

### 유형 카드 모티프 (TASK-50)

`/` 의 유형 선택 카드 썸네일은 **인라인 SVG 모티프**다
(`components/thumbnails/ReadingThumbnail.tsx`). 예전 `--color-thumb-1/2/3` 단색 자리를
대체했고 **그 토큰 셋은 지웠다.**

**새 토큰을 만들지 않았다.** 면은 `bg-brand`(연한 강조 면), 도형은 `on-brand`(그 위 어두운
잉크)다 — 둘은 이미 짝으로 검증된 조합이고(9.61:1), 도형에 쓰면 **작은 크기에서도 형태가
읽힌다.** `--color-ohaeng-*` 을 끌어 쓰지 않은 이유는 그것이 오행을 **인코딩하는 값**이기
때문이다(막대·오각형·공유 카드가 공유한다). 장식이 같은 색을 쓰면 "이 카드는 목(木)인가?"
로 읽힌다.

**모티프는 유형의 의미를 담으므로 `Record<ReadingType, …>` 다.** 예전 단색은 배열이 맞았다 —
명도 차이일 뿐 유형과 무관했으므로 돌려 쓰면 됐다. 지금은 배열이면 **새 유형이 조용히 남의
그림을 달고 나간다.**

| 유형 | 모티프 | 어디서 온 어휘인가 |
| --- | --- | --- |
| `diet` | 오각형 | `OhaengCycle` 의 상생 오각형 (라벨 없이 축소) |
| `gain-cause` | 치우친 막대 셋 | `OhaengBars` |
| `diet-method` | 계단 | 접근 순서 — 무엇을 먼저 고정하는가 |
| `exercise` | 오르는 화살 | 강도의 결 |
| `decade` | 눈금 다섯 칸 중 한 칸 | `DaeunTimeline` 의 "지금 어디쯤인가" |
| `general` | 오각형 + 중심점 | 내부 유형이라 목록에 없지만 `Record` 라 값이 필요하다 |

**사진을 쓰지 않기로 한 이유 셋**(크기·피사체·팔레트 검사 밖)은 그 파일 주석에 있다.
**래스터로 렌더하지도 않는다** — `scripts/render-icons.mjs` 파이프라인이 있는 이유는
파비콘·og:image 가 반드시 파일이어야 하기 때문이고, 페이지 안의 장식에는 그 제약이 없다.

`tokens.test.ts` 의 raw 색 검사 목록에 이 파일이 들어 있다. SVG 는 `fill-*`·`stroke-*` 에
hex 가 새기 쉬운 자리라 빠뜨리면 아무도 모른다.

### 다크 모드는 도입하지 않았다

팔레트가 밝은 톤(거의 흰 배경, 밝은 키컬러) 전제로 설계됐고, 지금 단계에서 두 벌을
유지·검증할 이유가 없다. `color-scheme: light` 로 고정해 폼 컨트롤 반전을 막았다.
필요해지면 시맨틱 토큰만 다시 정의하면 되도록 2층 구조를 열어 뒀다.
(TASK-11 의 중복 항목은 이 결정으로 삭제했다.)

### 쓰지 않은 값

- **페이지 배경 그라디언트** — `--raw-white-warm: #FDFFFB` 단색만 썼다. 원본도 거의 흰색이라
  그라디언트의 시각 효과가 거의 없었다. 히어로 영역을 만들 때 다시 고려한다.
- `blue500`, `red`, `starYellow` 원본값 — 아이콘·채움용으로 남겨 뒀고 텍스트에는 파생값을 쓴다.
