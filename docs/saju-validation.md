## 1. 라이브러리에서 발견한 문제 3가지

`lunar-javascript` 를 그대로 쓰면 한국 사주 관행과 어긋난다. 실측으로 확인한 내용이다.

### 1-1. 절기를 베이징 시간(UTC+8)으로 계산한다

```
2024 입춘 — 라이브러리: 2024-02-04 16:27
             공표(KST):  2024-02-04 17:27   ← 정확히 1시간 차이
```

한국 벽시계 시각을 그대로 넣으면 **월주(月柱) 경계가 1시간 어긋난다.** 절입 시각 전후 1시간
안에 태어난 사람의 월주가 틀리게 나온다.

→ **조치**: 년주·월주는 출생 시각을 **베이징 벽시계로 변환해서** 넣는다. 절기 비교가 같은
좌표계에서 이뤄지므로 경계 판정이 맞는다. (`lib/saju/pillars.ts` 의 `instant.beijingClock`)

### 1-2. `sect` 설정이 일주에만 적용되어 학파가 섞인다

`EightChar` 에는 야자시 학파를 정하는 `sect` 가 있고 기본값은 2(자정 기준)다.
그런데 시주 천간은 라이브러리 내부(`lunar.js` 의 `_computeTime`)에서 **항상 23시 기준 일간**으로
계산되며 `sect` 를 보지 않는다.

```
2024-01-01 23:30  일주=甲子(자정 기준)  시주=丙子(乙일 자시 = 23시 기준)
                  → 甲일인데 시주가 乙일 기준. 두 학파가 한 사주에 섞였다.
```

→ **조치**: 시주를 우리가 직접 계산한다. 오서둔(五鼠遁)으로 `시간 = f(일간, 시지)` 를 적용해
어느 학파를 골라도 일주와 시주가 항상 정합한다. (`lib/saju/ganji.ts` 의 `hourGanIndex`)

### 1-3. 진태양시·서머타임·표준자오선 변경 개념이 없다

→ **조치**: `lib/saju/time-correction.ts` 에서 보정한 지방시를 일주·시주 계산에 넣는다.

## 2. 시간 보정 설계

### 2-1. 서머타임과 표준자오선 이력은 tz 데이터베이스에서 가져온다

연도별 서머타임 날짜를 손으로 옮기는 대신 **Node 내장 IANA tz 데이터**(`Asia/Seoul`)를 쓴다.
실측으로 문헌과 전부 일치함을 확인했다.

| 시점 | tz 오프셋 | 문헌 |
| --- | --- | --- |
| 1905-06 | UTC+8:28 | 서울 지방 평균시 |
| 1910-06 | UTC+8:30 | 대한제국 동경 127.5° |
| 1930-06 | UTC+9:00 | 일제 동경 135° |
| 1948~51 여름 | UTC+10:00 | 서머타임 (135° + 1h) |
| 1954-03-15 → 04-15 | +9:00 → +8:30 | **1954-03-21 자오선 변경** |
| 1955~60 여름 | UTC+9:30 | 서머타임 (127.5° + 1h) |
| 1961-07 → 09 | +8:30 → +9:00 | **1961-08-10 자오선 복귀** |
| 1987~88 여름 | UTC+10:00 | 서머타임 부활 |
| 1989 이후 여름 | UTC+9:00 | 서머타임 폐지 |

전 구간(1900~2100, 402개 표본)에서 `실제 오프셋 − 표준자오선 오프셋` 이 **0분 또는 60분**
뿐임을 확인했다. 자오선 이력 표(`MERIDIAN_HISTORY`)와 tz 가 어긋나면 이 검사가 깨진다.

하드코딩 대신 tz 를 쓰는 이유: 정확하고, tzdata 갱신을 자동으로 따라가고, 검증 가능하다.

### 2-2. 보정 방식 3가지

| 모드 | 내용 | 서울 보정량(1990년 기준) |
| --- | --- | --- |
| `standard` | 보정 없음 | 0분 |
| `longitude` **(기본)** | 경도 보정만 (지방 평균태양시) | −32분 |
| `true` | 경도 + 균시차 | −32분 ± 최대 17분 |

기본값을 `longitude` 로 둔 이유: 한국 만세력 다수 관행이 경도 보정만 적용한다.
균시차까지 넣는 엄밀한 진태양시는 옵션으로 뒀다.

보정량은 시기에 따라 달라진다 — 검증기가 확인한 값:

| 조건 | 보정량 |
| --- | --- |
| 1990-05-17 (동경 135°) | −32분 |
| 1958-03-10 (동경 127.5°) | **−2분** ← 당시 표준시가 이미 한반도 중앙 기준 |
| 1988-07-15 (135° + 서머타임) | **−92분** |

### 2-3. 시각 미상일 때는 보정하지 않는다

출생시각을 모르면 정오를 임시로 쓰므로 보정에 의미가 없다. `solarTimeMode` 를 `standard` 로
강제하고 시주를 제외한다. 임의 시각을 채워 넣지 않는다.

### 2-3-1. 시각 입력은 **분 단위**로 받는다 — 12지시 선택을 넣지 않은 이유 (TASK-23)

UI 는 시(0~23)·분(0~59) 드롭다운 두 개다. 분을 5·10분 단위로 줄이지 않았고,
"자시~해시" 12지시만 고르는 방식도 넣지 않았다. 둘 다 **보정 때문에** 안 된다.

시지(時支) 경계는 시계시의 정시에 있지 않다. 경도 보정이 −32분이면 자시(23:00~01:00)의
끝은 시계시 **01:32** 로 밀린다. 그래서 같은 "1시대" 안에서도 앞뒤가 시진이 갈린다.

실측 (1990-05-17 · 서울 · `solarTimeMode: "longitude"` · 보정 −32분):

| 시계시 | 보정 후 | 시주 | 시지 |
| --- | --- | --- | --- |
| 01:30 | 00:58 | 경자 | 자(子) |
| 01:31 | 00:59 | 경자 | 자(子) |
| **01:32** | 01:00 | **신축** | **축(丑)** |
| 01:35 | 01:03 | 신축 | 축(丑) |

- **5분 단위로 줄이면** 경계가 선택지 사이(30 과 35)에 끼어 01:31~01:34 출생자를 표현할 수
  없다. 어느 쪽으로 반올림해도 절반은 시주가 틀린다. 1분 단위여야 한다.
- **12지시만 고르게 하면** 그 시진의 대표 시각을 우리가 정해 채워야 한다. 그것은 2-3 절의
  "임의 시각을 채워 넣지 않는다" 와 정면으로 충돌하고, 더구나 사용자가 고른 시진과 보정 후
  시진이 어긋날 수 있다 (사용자는 시계시로 "축시" 라고 생각하는데 보정하면 자시가 된다).
  모르면 채우지 말고 **시주를 제외**한다.

선택지 표와 이 규칙은 `lib/form/birth-time.ts` 에 있고 `birth-time.test.ts` 가 고정한다.

### 2-4. 자시(子時) 학파

23:00~23:59 출생자의 일주를 어느 날로 볼지에 대한 학파 차이다. 둘 다 지원한다.

| 옵션 | 일주 경계 | 예: 2024-01-01 23:30 |
| --- | --- | --- |
| `yajasi` **(기본)** | 자정 | 일주 갑자 + 시주 **갑자** |
| `jasi` | 23:00 | 일주 을축 + 시주 **병자** |

기본값을 `yajasi` 로 둔 이유: 한국 만세력 다수 관행이 야자시·조자시를 구분한다.
어느 쪽을 골라도 오서둔으로 시주를 다시 계산하므로 **일주와 시주가 항상 같은 학파**다.

## 3. 검증 항목과 결과

### A. 일주 — 율리우스일 기반 60갑자 연속성 (7,236건 · 불일치 0)

일주는 절기와 무관하게 60일 주기로 끊기지 않고 흐른다. 이 성질로 독립 검증했다.

앵커 두 개가 서로 정합함을 먼저 확인했다.

```
1900-01-01 = 갑술일 (60갑자 10번)
2000-01-01 = 무오일 (60갑자 54번)
두 날짜 간격 36,524일 → (10 + 36524) mod 60 = 54 ✅
```

1900~2100 각 달 1·11·21일에 대해 `(10 + 경과일수) mod 60` 과 대조했다.

### B. 년주 — (연도 − 4) mod 60, 입춘 기준 (402건 · 불일치 0)

입춘을 확실히 지난 3/15 는 당해 간지, 입춘 전인 1/15 는 전년 간지여야 한다.
1900~2100 전 연도에서 확인했다.

### C. 월주 — 오호둔 (2,412건 · 불일치 0)

`인월 천간 = (년간 % 5) × 2 + 2` 에서 월지만큼 순행하는 규칙과 대조했다.
갑기년→병인월, 을경년→무인월, 병신년→경인월, 정임년→임인월, 무계년→갑인월.

### D. 시주 — 오서둔 (720건 · 불일치 0)

60일 연속 × 12시진 전수. `시간 = (일간 % 5) × 2 + 시지` 규칙과 대조했다.
시진 경계(자시가 23:00 시작, 01:00 종료)도 확인했다.

### E. 시간 보정 (문헌 대조 · 전건 일치)

2-1 의 표가 그 결과다. 자오선 전환 4개 시점, 서머타임 시행 12개 연도,
비시행 6개 연도, 보정량 4개 케이스, 균시차 범위를 확인했다.

### F. 절기 — 한국천문연구원 공표값 대조 (6건 · 전건 2분 이내)

라이브러리 출력(베이징 시간)을 절대 시각으로 바꾼 뒤, 공표값을 **그 시기 한국 표준시로
해석해** 비교했다. 1958년은 표준시가 UTC+8:30 이었으므로 +9 로 고정 환산하면 30분 어긋난다.

| 연도 | 절기 | 계산(KST) | 공표(KST) | 차 |
| --- | --- | --- | --- | --- |
| 2024 | 입춘 | 17:27 | 17:27 | 0분 |
| 2024 | 우수 | 13:13 | 13:13 | 0분 |
| 2000 | 입춘 | 21:40 | 21:40 | 0분 |
| 1990 | 입춘 | 11:14 | 11:14 | 0분 |
| 1988 | 입춘 | 23:42 | 23:43 | 1분 |
| 1958 | 입춘 | 16:19 | 16:20 | 1분 ← UTC+8:30 시기 |

> 최초 작성 시 2000년 입춘 공표값을 20:40 으로 잘못 적어 검증이 실패했고, 출처 확인 결과
> **21:40 이 맞고 라이브러리가 옳았다.** 검증기의 기대값도 틀릴 수 있다는 사례로 남긴다.

### G. 경계 케이스 (전건 통과)

- 자시 학파 두 방식의 일주가 하루 차이로 갈리는지
- 두 학파 모두 시주 천간이 자기 일간과 오서둔으로 정합한지 (1-2 재발 방지)
- 윤달: 음력 2020-04-15 → 양력 2020-05-07 / 음력 **윤**4-15 → 양력 2020-06-06
- 윤달 표기에 "윤" 이 붙고 평달에는 붙지 않는지
- 시각 미상: 시주 `null`, 보정 비활성, 오행 합 6 (3기둥 × 2)
- 시각 있음: 오행 합 8 (4기둥 × 2)
- 지원 범위 끝단(1900-01-01, 2100-12-31) 이 예외 없이 계산되는지
- 보정으로 날짜가 넘어가는 케이스: 1990-05-17 00:10 → 05-16 23:38 → **전날 일주**
- 60갑자 인덱스 왕복 일치

## 3-2. 파생 근거 검증 (TASK-04)

해석 근거를 늘리면서 **고전 규칙으로 확정되는 것**과 **우리가 정한 관례**를 나눠 담았다.
관례를 사실처럼 내보내면 안 되기 때문이다.

| 항목 | 성격 | 근거 |
| --- | --- | --- |
| 지지 십신 | 고전 | 지장간 본기(정기) 천간을 일간과 비교 |
| 지장간 표 | 고전 | 12지지 × 여기·중기·정기 (판본 차이는 아래 표에 명시) |
| 왕상휴수사 | 고전 | 당령자 왕 / 왕이 생하는 것 상 / 왕을 생하는 것 휴 / 왕을 극하는 것 수 / 왕이 극하는 것 사 |
| 신강·신약 3기준 | 고전 | 득령(월지 본기)·득지(일지 통근)·득세(나머지, 통근 포함) |
| 대운 순행·역행 | 고전 | 양남·음녀 순행 / 음남·양녀 역행 |
| 대운 간지 | 고전 | 월주에서 순행 또는 역행 |
| 세운 간지 | 고전 | (연도 − 4) mod 60 |
| **오행 점수 배수** | **우리 관례** | 왕 1.5 / 상 1.2 / 휴 1.0 / 수 0.8 / 사 0.6 |
| **신강·신약 4단계** | **우리 관례** | 3기준 충족 개수 → 신강 / 약간 신강 / 약간 신약 / 신약 |
| **대운수 반올림** | **우리 관례** | 일수 ÷ 3 반올림, 최소 1세 (나머지를 개월로 환산하지 않음) |

관례에 해당하는 값은 `lib/saju/analysis.ts` 의 상수(`SEASONAL_MULTIPLIER` 등)로 모아 뒀다.
바꾸려면 그 상수만 고치면 된다.

프롬프트에는 점수를 **숫자로 인용하지 말라**고 명시했다. 우리가 정한 배수에서 나온 값이라
절대적 수치가 아니기 때문이다. 샘플 5건 모두에서 숫자 인용이 없었다.

| 진(辰) | 을 | 계 | 무 | | 술(戌) | 신 | 정 | 무 |
| 사(巳) | 무 | 경 | 병 | | 해(亥) | 무 | 갑 | 임 |

**판본 차이가 있는 자리와 채택한 쪽** — 아래 셋은 유파마다 빠지거나 다르게 적힌다.

| 자리 | 판본 차이 | 채택 |
| --- | --- | --- |
| 오(午)의 중기 | 기(己)를 넣지 않는 판본이 있다 | **넣는다** |
| 해(亥)의 여기 | 무(戊)를 넣지 않는 판본이 있다 | **넣는다** |
| 신(申)의 여기 | 무(戊) / 기(己) 로 갈린다 | **무(戊)** |

**일수 가중치(여기 7일·중기 3일 …)를 쓰지 않는다.** 일수 배분은 유파마다 다르지만
"어느 천간이 들었는가" 는 이견이 거의 없다. **있나 없나만** 보면 우리 관례를 늘리지 않고
고전 규칙 안에 머문다. 가중치를 넣는 순간 `SEASONAL_MULTIPLIER` 같은 관례가 하나 더 생긴다.

**통근을 쓰는 곳은 신강·신약 판정뿐이다.** 화면과 프롬프트의 지지 십신(`jiSipsin`)은
그대로 본기 기준이다. 표시까지 바꾸면 근거 표시가 흔들린다.

##### 득령은 왜 본기 그대로인가

세 기준 중 **득지·득세만** 지장간까지 연다. 월령(月令)은 "그 달을 지배하는 기운" 이라
숨어 있는 글자가 아니고, 여기까지 열면 세 기준이 전부 통근 검사가 되어 판정이 신강 쪽으로
쏠린다. 격자 표본 194,400건(년·월·일·시 간지를 훑음)으로 실측한 분포:

| 기준 | 신강 | 약간 신강 | 약간 신약 | 신약 | 신강 계열 |
| --- | --- | --- | --- | --- | --- |
| 본기만 (변경 전) | 5.6% | 26.2% | 43.0% | 25.2% | **31.8%** |
| **득지·득세만 통근 (현재)** | 15.6% | 43.1% | 33.4% | 8.0% | **58.6%** |
| 3기준 모두 통근 | 30.2% | 43.2% | 22.6% | 4.0% | 73.4% |

`strength.verdict` 는 `constitution.ts` 의 대사 기조(발산형/축적형) 입력이므로 이 분포가
그대로 다이어트 접근 순서의 분포가 된다. 세 기준을 모두 열면 73%가 발산형이 되어 2분법이
사실상 죽는다.

##### 실측 사례

`1999-12-09 22:12` (기묘 · 병자 · **을미** · 정해, 일간 을목)

  **약간 신약**이 나왔고, 다른 만세력 앱은 신강으로 냈다.
- 중기 을목이 일간과 같은 글자이므로 통근이 선다 → 득지 ○ → **약간 신강**.
- 같은 사주의 오행 점수는 이미 일간 편 66%(목 2.4 + 수 3.0 vs 화 1.2 + 토 1.6 + 금 0)를

## 3-3. 체질 판정 (TASK-14)

`lib/saju/constitution.ts` — `diet` 유형의 체질 판정을 **코드가** 정한다. LLM 은 서술만 한다.
원국을 코드가 계산하는 것과 같은 이유다: 판정을 매번 즉흥으로 내면 같은 사주에 다른 답이 나온다.

판정 축은 다섯이고, 전부 이미 검증된 근거(오행 점수·왕상휴수사·신강신약·십신)에서 파생된다.

| 축 | 값 | 근거 | 성격 |
| --- | --- | --- | --- |
| 오행 균형 | 과다 / 적정 / 부족 | 오행 점수가 평균의 몇 배인가 | **우리 관례**(임계값) |
| 한열(조후) | 한·서늘·중화·따뜻·열 | 계절의 한난 + 원국 화·수 세력 | 고전(순서) + **우리 관례**(눈금) |
| 대사 기조 | 발산형 / 축적형 | 신강 계열 / 신약 계열 | **우리 관례**(2분법) |
| 살이 붙는 패턴 | 근육·식욕·불규칙·스트레스·정체형 | 십신 우세 그룹 | 고전(십신 5분류) + **우리 관례**(대응표) |
| 다이어트 접근 순서 | 활동량·식사량 조절·리듬 고정·회복 우선 | 대사 기조 × 걸리는 지점 | **전부 우리 관례**(2×2 대응표) |
| 움직임 종류 (TASK-40) | 유산소·근력·이완 중심 / 저강도 지속 | 접근 순서 (1:1) | **전부 우리 관례**(파생표) |
| 식사 순서 (TASK-40) | 순서·시각 규칙 5가지 | 살이 붙는 패턴 (1:1) | **전부 우리 관례**(파생표) |

| 관례 값 | 상수 | 현재 값 |
| --- | --- | --- |
| 과다 임계 | `EXCESS_RATIO` | 평균 점수의 1.5배 이상 |
| 부족 임계 | `DEFICIENT_RATIO` | 평균 점수의 0.5배 이하 |
| 한열 눈금 | `SEASON_TILT` + 화·수 비교 | 각각 −1·0·+1, 합 −2~+2 를 5단계로 |
| 십신 동점 | `SIPSIN_GROUPS` 순서 | 비겁→식상→재성→관성→인성 중 앞선 쪽 |
| 걸리는 지점 | `SITE_OF_PATTERN` | 근육·정체형 → 움직임 / 식욕·불규칙·스트레스형 → 먹는 것 |
| 접근 순서 | `APPROACH_TABLE` | 아래 2×2 표 |
| 움직임 종류 | `MOVEMENT_PLAN` | 활동량→유산소 / 식사량→근력 / 회복→이완 / 리듬→저강도 지속 |
| 식사 순서 | `MEAL_PLAN` | 패턴 5가지에 순서·시각 규칙 하나씩 |

절대 개수가 아니라 **평균 대비 비율**로 자르는 이유: 시각 미상이면 글자가 6개뿐이라 같은
"2개" 의 무게가 다르다. 비율로 두면 기둥 수와 무관하게 같은 뜻이 된다.

조후를 넣은 이유: 오행 개수만으로는 "여름에 태어난 화 많은 사주" 와 "겨울에 태어난 화 많은
사주" 가 같아진다. 계절의 한난을 먼저 보고 원국 세력으로 보정하는 것이 고전 조후의 순서다.

#### 다이어트 접근 순서 — 2×2 대응표 (TASK-24)

"무엇을 먼저 고정하는가" 를 정하는 축이다. **전부 우리 관례다** — 고전에 대응물이 없다.
`METABOLISM_NOTE` 가 이미 순서를 가리키고 있었던 것을 독립된 축으로 끌어올렸다
(발산형 = "쓰는 양을 늘리는 순서", 축적형 = "수면과 끼니를 먼저 고정하고 강도는 나중에").

|  | 걸리는 지점 = **움직임** | 걸리는 지점 = **먹는 것** |
| --- | --- | --- |
| **발산형** (신강 계열) | 활동량 우선 | 식사량 조절 우선 |
| **축적형** (신약 계열) | 회복 우선 | 리듬 고정 우선 |

걸리는 지점은 살이 붙는 패턴에서 나온다 — 근육형(비겁)·정체형(인성)은 활동량이 줄면 붙는
결이고, 식욕형(식상)·불규칙형(재성)·스트레스형(관성)은 먹는 양·시각·상황에서 붙는 결이다.

**동점이 없다.** 두 입력이 각각 이미 결정론적이므로(대사 기조는 신강신약의 4단계를 2분한 것,
패턴은 십신 우세 그룹이고 그쪽 동점은 고전 십신 순서로 이미 고정) 2×2 의 어느 칸에 떨어지는지가
유일하게 정해진다. 축을 더 넣을 때는 동점 처리를 반드시 함께 고정할 것.

**한열을 이 축에 넣지 않았다.** 한열은 "무엇을 먼저 고정하는가" 와 다른 층이다 — 같은 순서를
어느 온도·시간대에 실행하느냐를 정한다. 섞으면 값이 20가지가 되면서 각 칸의 근거를 설명할 수
없게 된다. 한열은 `THERMAL_GUIDE` 의 식습관·움직임 항목으로 실행 조건에 붙는다.
테스트가 "같은 대사 기조·같은 패턴이면 한열이 달라도 방식이 같다" 를 확인한다.

#### 실행 방법 — 움직임 종류와 식사 순서 (TASK-40)

`나에게 맞는 다이어트 방법`(`diet-method`) 유형이 쓰는 축이다. **경계를 (B) 일부 개방으로
넓혔다** — 방법은 구체적으로 쓰고 수치는 계속 막는다. 금지의 근거 넷 중 셋(입력이
생년월일시뿐이라 근거가 없다 · 코드가 못 정하면 LLM 이 즉흥으로 낸다 · 안전)은 **수치에만**
걸리고, 방법 자체는 판정에서 코드가 고를 수 있는 값이다.

| 층 | 정하는 것 | 근거 축 | 상수 |
| --- | --- | --- | --- |
| 무엇을 먼저 고정하는가 | 접근 순서 | 대사 기조 × 걸리는 지점 | `APPROACH_TABLE` |
| **어떤 종류로 움직이는가** | 움직임 종류·강도의 결 | ← 접근 순서 (1:1) | `MOVEMENT_PLAN` |
| **어떤 순서로 먹는가** | 식사 순서·시각 규칙 | ← 살이 붙는 패턴 (1:1) | `MEAL_PLAN` |
| 언제·어떤 온도로 실행하는가 | 시간대·조리·음식 온도 | 한열 | `THERMAL_GUIDE` |

**새 동점이 없다.** 두 표 모두 이미 결정론적인 축에서 1:1 로 파생되므로 판정이 새로 필요
없다. 테스트가 60개 원국을 훑어 "같은 접근 순서면 항상 같은 움직임 종류" 를 확인한다.

**시간대와 온도를 이 표에 넣지 않았다.** `APPROACH_TABLE` 이 한열을 뺀 것과 같은 이유이며,
테스트가 `MOVEMENT_PLAN`·`MEAL_PLAN` 문구에 온도·성미 어휘(온성·냉성·따뜻하게 …)가
들어오지 않는지 확인한다. 들어오면 층이 무너진다.

**식품 이름도 이 표에 없다.** 무엇을 먹을지는 `ELEMENT_FOOD` 가 정하고 이 표는 순서와
시각의 규칙만 정한다. 테스트가 `MEAL_PLAN` 에 `ELEMENT_FOOD` 의 재료 이름이 섞이지 않는지
본다 — 섞이면 목록 밖 식품이 이 경로로 새어 나간다.

검사는 두 갈래다. 막는 것(처방 어휘 · 문구에 숫자)과 **여는 것**(종류 네 가지가 전부 쓰이는지,
`how`·`caution` 이 실제로 구체적인지). 후자가 없으면 나중에 규칙을 조이면서 조용히 다시
닫아 버려도 아무도 모른다. `app/disclaimer/page.tsx` 가 이 경계를 그대로 서술한다.

#### 재료 범주 (TASK-27)

"무엇을 먹으면 좋은가" 도 **코드가 고른다.** 식품 이름을 LLM 이 고르게 하면 같은 사주에 다른
목록이 나오고 그때그때 효능이 붙는다. 체질 판정과 같은 원칙이다.

| | 근거 | 성격 |
| --- | --- | --- |
| 오행 → 오미 (목=신맛·화=쓴맛·토=단맛·금=매운맛·수=짠맛) | 고전 배속 | **고전** |
| 오행 → 오색 (목=청·화=적·토=황·금=백·수=흑) | 고전 배속 | **고전** |
| 그 배속에서 고른 **구체 재료 목록** (`ELEMENT_FOOD`) | 한국에서 흔히 구하는 것 | **우리 관례** |
| 부족은 곁들이기 / 과다는 더 늘리지 않기 (`FOOD_HOW`) | 개인 변수를 모르므로 | **우리 관례** |

**섹션을 새로 만들지 않았다.** 재료는 기존 `잘 맞는 식습관` 절 안에서 말한다 (diet 는
TASK-24 로 이미 8절이고 더 늘리면 생성 시간이 는다). 구현도 새 구조를 만들지 않고
**기존 `focus` 배열에 얹었다** — `focus` 는 이미 과다·부족 오행마다 한 줄씩 갖고 있어
결정론과 `even` 처리(항목 없음)를 그대로 물려받는다.

**한열이 재료를 고르지 않는다.** 재료는 오행이, 조리·온도는 한열이 정한다. 식품의 온·냉
성질표는 출처가 한의학인데 면책 고지가 "한의학과 무관" 을 약속하므로, 성미(性味) 용어를
쓰지 않고 조리·온도는 기존 `THERMAL_GUIDE` 의 생활어 문구에 맡겼다. 표를 하나만 두어
두 곳이 어긋날 여지도 없앴다. 테스트가 성미 용어(온성·냉성 등)를 막는다.

`even`(과다·부족이 하나도 없음)은 표본 408건 중 5건(1.2%)이다. 이 경우 재료도 없다 —
없는 근거로 식품을 지어내지 않고, 프롬프트가 한열·대사 기조 위주로 쓰라고 지시한다.

## 3-4. 올해 세운 판정 (TASK-15 · TASK-39)

`lib/saju/yearly.ts` — 코드가 정한다. 축은 둘이지만 **밖으로 나가는 것은 하나뿐이다.**

| 축 | 값 | 근거 | 성격 | 프롬프트로 나가나 |
| --- | --- | --- | --- | --- |
| 작용 | 보완 / 가중 / 중립 | 세운 오행이 원국의 부족을 채우는가, 과다에 더하는가 | 고전(견주는 방식) + **우리 관례**(3단계) | **예** (`diet`) |

채우는 개수와 더하는 개수를 비교해 같으면(둘 다 0 포함) 중립이다.

### 왜 작용만 내보내는가 (TASK-39 결정 ①)

`yearly` 유형이 없어지면서 이 판정은 `diet` 의 "올해의 몸 흐름" 섹션으로 옮겨갔다.
두 축의 성격이 다르다.

- **작용은 원래 몸 쪽 값이다.** `analyzeYearly` 가 `constitution.deficient`/`excess` 를 받아
  계산한다 — 즉 체질 판정에서 나온 값이고, 운세 유형에만 흘려보내던 쪽이 이상했다.
  옮기는 데 새로 정할 것이 없다.
- **주제는 생활 영역 어휘다.** `책임과 압박` 을 몸 이야기로 옮기려면 십신→몸 대응표를

  면책 고지가 막는 의학적 주장에 닿는다. **넘기지 않으면 그 문제가 생기지 않는다.**

계산은 남겨 뒀다. 십신 그룹 판정 자체는 고전이고, 생활 영역을 다루는 유형이 다시 생기면
그대로 쓸 수 있다. 되살릴 때 필요한 것은 표가 아니라 **어느 맥락에 쓸지의 판단**이다.

## 3-5. 출생지 경도 (TASK-37)

`longitude` 는 API 가 원래 받고 있었는데 UI 가 없어 **전국이 서울(126.9784°) 고정**이었다.
그 상태에서 무엇이 틀렸는지 실측하고, 목록 단위를 정한 근거를 남긴다.

### 무엇이 흔들리는가

**년주·월주는 영향이 없다.** 절기 판정은 절대 시각(UTC)으로 하므로 출생지가 바꿀 수 없다
(`beijingClock` 이 `utcMs` 에서 나온다). 3개 날짜 × 3개 시각 × 7개 지역 = **84건 검사, 차이 0**.
흔들리는 것은 보정된 지방시를 쓰는 **일주·시주**뿐이다.

| 출생지 | 보정량 | 시주가 갈리는 비율 | 일주가 갈리는 비율 |
| --- | --- | --- | --- |
| 서울 (기본값) | −32분 | — | — |
| 인천 | −33분 | 0.8% | 0.07% |
| 대전 | −30분 | 1.7% | 0.14% |
| 대구 | −26분 | 5.0% | 0.42% |
| 부산 | −24분 | **6.7%** | 0.56% |
| 울릉도 | −16분 | 13.3% | 1.11% |

하루 1440분을 1분 단위로 훑어 서울 기본값과 대조한 값이다. 비율은 시주 쪽이 크지만
**일주가 갈리는 쪽이 더 아프다** — 일간이 바뀌면 십신·신강신약·체질 판정이 통째로 달라진다.

### 목록 단위 — 시/군 + 광역시는 구만 통째 (168개)

광역 안에서 동서 끝이 벌어지는 폭을 재고 정했다.

| 구역 | 경도 폭 | 시각차 |
| --- | --- | --- |
| 서울 (구 전체) | 0.32° | 1.3분 |
| 부산 (구만) | 0.26° | 1.0분 |
| **인천 (군 포함)** | **1.25°** | **5.0분** |
| 인천 (구만) | 0.25° | 1.0분 |
| 경기도 (김포~가평) | 0.80° | 3.2분 |
| 경상북도 (울릉 제외) | 1.24° | 5.0분 |
| 강원도 (철원~강릉) | 1.59° | 6.4분 |

- **구까지 나누지 않는다.** 광역시의 구를 구분해 얻는 것은 0.8%p 뿐이다.
- **시/도 17개만으로도 안 된다.** 강원을 한 덩어리로 두면 5.8% 가 남아, 고치려던 문제
  (부산 6.7%)와 거의 같은 크기다.
- **단, 광역시의 군(郡)은 뗀다.** 인천은 옹진군이 백령도(124.7°)까지 품어 군을 합치면
  폭이 1.25°(5.0분)로 벌어진다. 군을 떼면 0.25°로 다른 광역시와 같아진다.
  같은 규칙으로 기장군·달성군·강화군·옹진군·울주군이 따로 선다.
- 제주는 광역이지만 섬 동서 폭이 0.75°(3분)라 **제주시·서귀포시로 나눈다.**

결과적으로 잔차가 어디서나 **1% 안쪽**이다.

### 표의 출처

`lib/form/birthplaces.ts` 는 **자동 생성 파일**이다 (`node scripts/build-birthplaces.mjs`).
결과물을 커밋하므로 배포에 스크립트가 필요 없다 — 아이콘과 같은 방식이다.

| | |
| --- | --- |
| 자료 | 통계청(KOSTAT) **센서스용 행정구역경계 2013** |
| 경유 | `github.com/southkorea/southkorea-maps` `kostat/2013/json/skorea_municipalities_geo_simple.json` (시군구 251개) |
| 라이선스 | KOSTAT 부분은 "Free to share or remix" |
| 경도 산출 | 행정구역 경계의 **면적가중 중심점**(신발끈 공식), 소수 둘째 자리 |

**시청 좌표를 손으로 옮기지 않았다** — 그것이 곧 눈대중이고, 경계에서 계산하면 168개
전부를 출처 하나로 설명할 수 있다. 소수 둘째 자리에서 끊는 이유는 0.01° = 0.04분이고
보정이 분 단위로 반올림되기 때문이다. 그 아래는 없는 정확도를 있는 척하는 것이다.
시/도 표시 이름은 스크립트가 들고 있으며(좌표가 아니라 이름이다), 자료의 코드 집합과
어긋나면 생성이 실패한다.

- 시/도 17개, 모든 시/도에 항목 1개 이상, 시/도+시/군 조합 유일(`고성군` 이 강원·경남에 둘)

### 개인정보

- **지역 이름은 서버로 보내지 않는다.** 계산에 필요한 것은 경도뿐이라 요청에는 숫자만
  실린다. 결과 화면의 지역 표시는 폼이 들고 있는 값으로 그린다.
- **쓰이지 않을 값은 아예 보내지 않는다.** 시각 미상이거나 보정 없음을 고르면 서버가
  경도를 버리므로 요청에서 뺀다. 폼도 같은 조건으로 선택을 잠근다.
- `app/privacy/page.tsx` 1항(처리하는 정보)·3항(보관 기간)에 태어난 지역을 넣었고,
  **4항에 보정량으로 대략의 지역이 짐작될 수 있다**고 밝혔다 — 프롬프트가 이미
  `correctionMinutes` 를 보내므로 지역 이름을 빼도 이 사실은 그대로다.

## 4. 남은 한계

고칠 계획이 없거나, 다른 태스크로 넘긴 것들.

1. **절기 시각 오차 1~2분** — 라이브러리가 근사 알고리즘을 쓴다. 절입 시각 2분 안에 태어난
   경우 월주가 갈릴 수 있다. 정밀 천문 계산으로 바꾸려면 별도 작업이 필요하다.
2. **한국 음력 vs 중국 음력** — 라이브러리는 중국 기준으로 음력을 계산한다. 한국천문연구원
   음력과 드물게 하루 차이가 난다(삭 시각이 자정 근처일 때). 음력 입력자에게만 영향.
3. **해외 출생 미지원** — 국내 출생지는 TASK-37 에서 열었다(아래 3-4 절). 다만 스키마가
   경도를 124~132°(한반도)로 제한하고 `wallClockToUtc` 가 `Asia/Seoul` 고정이라,
   해외 출생자가 현지 시계시를 넣으면 한국 시각으로 취급돼 결과가 크게 틀린다.
   경도 하나로 안 되고 시간대 이력이 필요하다.
4. **균시차 근사** — NOAA 근사식으로 오차 약 0.1분. 실용상 무해하다.
5. **테스트로 고정되지 않음** — 지금은 일회성 스크립트다. Vitest 로 옮기는 것은 TASK-05.
6. **세운은 절입 경계를 따지지 않는다** — 연 단위 표시가 목적이라 해당 연도 간지를 그대로
   쓴다. 입춘 이전 며칠은 엄밀히 전년도 간지다. 일별 운세를 낼 때 다시 봐야 한다.
7. **세는나이 기준** — 대운·세운 나이는 세는나이(출생년=1세)다. 한국 만세력 다수 관행이지만
   만 나이를 쓰는 유파도 있다.
8. **지장간을 오행 점수에는 반영하지 않는다** — 신강·신약의 득지·득세는 지장간 전체를
   보지만(3-2 절), **오행 점수와 지지 십신은 여전히 본기만** 본다. 점수에 넣으려면 여기·중기·
   정기의 일수 배분을 정해야 하는데 그 배분이 학파마다 다르다. 통근은 "있나 없나" 만 보므로
   그 문제를 피해 간다.
9. **체질 판정의 임계값에 외부 근거가 없다** — 1.5배·0.5배는 표본을 보고 정한 우리 관례이지
   문헌값이나 임상 근거가 아니다. 판정이 **재현 가능**하다는 것과 **맞다**는 것은 다르다.
   이 서비스가 보증하는 것은 앞쪽뿐이며, 면책 고지에도 그렇게 적었다.
10. **합·충·형·파 미반영** — 지지 사이의 관계(삼합·육합·충 등)는 오행 세력을 바꾸는 유파가
   많으나, 판정 기준이 학파마다 갈려 체질 판정에 넣지 않았다. 오행 점수는 글자 수와
   계절 기세만 본다. 올해 운세도 같다 — **세운과 원국 사이의 충(沖)·합(合)을 보지 않는다.**
   세운 오행이 과부족에 닿는지만 본다.
11. **월별 운세 없음** — 올해 운세는 연 단위다. 월운을 내려면 절입 경계로 월지를 잡아야 하고
   (한계 6번의 세운 문제와 같은 뿌리), 프롬프트에서 월 특정을 금지해 두었다.
12. **올해 운세의 기준 연도는 서버 시각의 연도다** — 입춘 이전 며칠은 엄밀히 전년도 간지이지만
   (한계 6번) 연 단위 표시가 목적이라 그대로 쓴다. 1~2월 초 이용자에게는 한 해 앞선 판정이
   나갈 수 있다.
