## 1. 라이브러리에서 발견한 문제 3가지

`lunar-javascript` 를 그대로 쓰면 한국 사주 관행과 어긋난다. 실측으로 확인한 내용이다.

### 1-1. 절기를 베이징 시간(UTC+8)으로 계산한다

```
2024 입춘 — 라이브러리: 2024-02-04 16:27
             공표(KST):  2024-02-04 17:27   ← 정확히 1시간 차이
```

한국 벽시계 시각을 그대로 넣으면 **월주(月柱) 경계가 1시간 어긋난다.** 절입 시각 전후 1시간
안에 태어난 사람의 월주가 틀리게 나온다.

→ **조치**: 년주·월주는 출생 시각을 **베이징 벽시계로 변환해서** 넣는다. 절기 비교가 같은
좌표계에서 이뤄지므로 경계 판정이 맞는다. (`lib/saju/pillars.ts` 의 `instant.beijingClock`)

### 1-2. `sect` 설정이 일주에만 적용되어 학파가 섞인다

`EightChar` 에는 야자시 학파를 정하는 `sect` 가 있고 기본값은 2(자정 기준)다.
그런데 시주 천간은 라이브러리 내부(`lunar.js` 의 `_computeTime`)에서 **항상 23시 기준 일간**으로
계산되며 `sect` 를 보지 않는다.

```
2024-01-01 23:30  일주=甲子(자정 기준)  시주=丙子(乙일 자시 = 23시 기준)
                  → 甲일인데 시주가 乙일 기준. 두 학파가 한 사주에 섞였다.
```

→ **조치**: 시주를 우리가 직접 계산한다. 오서둔(五鼠遁)으로 `시간 = f(일간, 시지)` 를 적용해
어느 학파를 골라도 일주와 시주가 항상 정합한다. (`lib/saju/ganji.ts` 의 `hourGanIndex`)

### 1-3. 진태양시·서머타임·표준자오선 변경 개념이 없다

→ **조치**: `lib/saju/time-correction.ts` 에서 보정한 지방시를 일주·시주 계산에 넣는다.

## 2. 시간 보정 설계

### 2-1. 서머타임과 표준자오선 이력은 tz 데이터베이스에서 가져온다

연도별 서머타임 날짜를 손으로 옮기는 대신 **Node 내장 IANA tz 데이터**(`Asia/Seoul`)를 쓴다.
실측으로 문헌과 전부 일치함을 확인했다.

| 시점 | tz 오프셋 | 문헌 |
| --- | --- | --- |
| 1905-06 | UTC+8:28 | 서울 지방 평균시 |
| 1910-06 | UTC+8:30 | 대한제국 동경 127.5° |
| 1930-06 | UTC+9:00 | 일제 동경 135° |
| 1948~51 여름 | UTC+10:00 | 서머타임 (135° + 1h) |
| 1954-03-15 → 04-15 | +9:00 → +8:30 | **1954-03-21 자오선 변경** |
| 1955~60 여름 | UTC+9:30 | 서머타임 (127.5° + 1h) |
| 1961-07 → 09 | +8:30 → +9:00 | **1961-08-10 자오선 복귀** |
| 1987~88 여름 | UTC+10:00 | 서머타임 부활 |
| 1989 이후 여름 | UTC+9:00 | 서머타임 폐지 |

전 구간(1900~2100, 402개 표본)에서 `실제 오프셋 − 표준자오선 오프셋` 이 **0분 또는 60분**
뿐임을 확인했다. 자오선 이력 표(`MERIDIAN_HISTORY`)와 tz 가 어긋나면 이 검사가 깨진다.

하드코딩 대신 tz 를 쓰는 이유: 정확하고, tzdata 갱신을 자동으로 따라가고, 검증 가능하다.

### 2-2. 보정 방식 3가지

| 모드 | 내용 | 서울 보정량(1990년 기준) |
| --- | --- | --- |
| `standard` | 보정 없음 | 0분 |
| `longitude` **(기본)** | 경도 보정만 (지방 평균태양시) | −32분 |
| `true` | 경도 + 균시차 | −32분 ± 최대 17분 |

기본값을 `longitude` 로 둔 이유: 한국 만세력 다수 관행이 경도 보정만 적용한다.
균시차까지 넣는 엄밀한 진태양시는 옵션으로 뒀다.

보정량은 시기에 따라 달라진다 — 검증기가 확인한 값:

| 조건 | 보정량 |
| --- | --- |
| 1990-05-17 (동경 135°) | −32분 |
| 1958-03-10 (동경 127.5°) | **−2분** ← 당시 표준시가 이미 한반도 중앙 기준 |
| 1988-07-15 (135° + 서머타임) | **−92분** |

### 2-3. 시각 미상일 때는 보정하지 않는다

출생시각을 모르면 정오를 임시로 쓰므로 보정에 의미가 없다. `solarTimeMode` 를 `standard` 로
강제하고 시주를 제외한다. 임의 시각을 채워 넣지 않는다.

### 2-3-1. 시각 입력은 **분 단위**로 받는다 — 12지시 선택을 넣지 않은 이유 (TASK-23)

UI 는 시(0~23)·분(0~59) 드롭다운 두 개다. 분을 5·10분 단위로 줄이지 않았고,
"자시~해시" 12지시만 고르는 방식도 넣지 않았다. 둘 다 **보정 때문에** 안 된다.

시지(時支) 경계는 시계시의 정시에 있지 않다. 경도 보정이 −32분이면 자시(23:00~01:00)의
끝은 시계시 **01:32** 로 밀린다. 그래서 같은 "1시대" 안에서도 앞뒤가 시진이 갈린다.

실측 (1990-05-17 · 서울 · `solarTimeMode: "longitude"` · 보정 −32분):

| 시계시 | 보정 후 | 시주 | 시지 |
| --- | --- | --- | --- |
| 01:30 | 00:58 | 경자 | 자(子) |
| 01:31 | 00:59 | 경자 | 자(子) |
| **01:32** | 01:00 | **신축** | **축(丑)** |
| 01:35 | 01:03 | 신축 | 축(丑) |

- **5분 단위로 줄이면** 경계가 선택지 사이(30 과 35)에 끼어 01:31~01:34 출생자를 표현할 수
  없다. 어느 쪽으로 반올림해도 절반은 시주가 틀린다. 1분 단위여야 한다.
- **12지시만 고르게 하면** 그 시진의 대표 시각을 우리가 정해 채워야 한다. 그것은 2-3 절의
  "임의 시각을 채워 넣지 않는다" 와 정면으로 충돌하고, 더구나 사용자가 고른 시진과 보정 후
  시진이 어긋날 수 있다 (사용자는 시계시로 "축시" 라고 생각하는데 보정하면 자시가 된다).
  모르면 채우지 말고 **시주를 제외**한다.

선택지 표와 이 규칙은 `lib/form/birth-time.ts` 에 있고 `birth-time.test.ts` 가 고정한다.

### 2-4. 자시(子時) 학파

23:00~23:59 출생자의 일주를 어느 날로 볼지에 대한 학파 차이다. 둘 다 지원한다.

| 옵션 | 일주 경계 | 예: 2024-01-01 23:30 |
| --- | --- | --- |
| `yajasi` **(기본)** | 자정 | 일주 갑자 + 시주 **갑자** |
| `jasi` | 23:00 | 일주 을축 + 시주 **병자** |

기본값을 `yajasi` 로 둔 이유: 한국 만세력 다수 관행이 야자시·조자시를 구분한다.
어느 쪽을 골라도 오서둔으로 시주를 다시 계산하므로 **일주와 시주가 항상 같은 학파**다.

## 3. 검증 항목과 결과

### A. 일주 — 율리우스일 기반 60갑자 연속성 (7,236건 · 불일치 0)

일주는 절기와 무관하게 60일 주기로 끊기지 않고 흐른다. 이 성질로 독립 검증했다.

앵커 두 개가 서로 정합함을 먼저 확인했다.

```
1900-01-01 = 갑술일 (60갑자 10번)
2000-01-01 = 무오일 (60갑자 54번)
두 날짜 간격 36,524일 → (10 + 36524) mod 60 = 54 ✅
```

1900~2100 각 달 1·11·21일에 대해 `(10 + 경과일수) mod 60` 과 대조했다.

### B. 년주 — (연도 − 4) mod 60, 입춘 기준 (402건 · 불일치 0)

입춘을 확실히 지난 3/15 는 당해 간지, 입춘 전인 1/15 는 전년 간지여야 한다.
1900~2100 전 연도에서 확인했다.

### C. 월주 — 오호둔 (2,412건 · 불일치 0)

`인월 천간 = (년간 % 5) × 2 + 2` 에서 월지만큼 순행하는 규칙과 대조했다.
갑기년→병인월, 을경년→무인월, 병신년→경인월, 정임년→임인월, 무계년→갑인월.

### D. 시주 — 오서둔 (720건 · 불일치 0)

60일 연속 × 12시진 전수. `시간 = (일간 % 5) × 2 + 시지` 규칙과 대조했다.
시진 경계(자시가 23:00 시작, 01:00 종료)도 확인했다.

### E. 시간 보정 (문헌 대조 · 전건 일치)

2-1 의 표가 그 결과다. 자오선 전환 4개 시점, 서머타임 시행 12개 연도,
비시행 6개 연도, 보정량 4개 케이스, 균시차 범위를 확인했다.

### F. 절기 — 한국천문연구원 공표값 대조 (6건 · 전건 2분 이내)

라이브러리 출력(베이징 시간)을 절대 시각으로 바꾼 뒤, 공표값을 **그 시기 한국 표준시로
해석해** 비교했다. 1958년은 표준시가 UTC+8:30 이었으므로 +9 로 고정 환산하면 30분 어긋난다.

| 연도 | 절기 | 계산(KST) | 공표(KST) | 차 |
| --- | --- | --- | --- | --- |
| 2024 | 입춘 | 17:27 | 17:27 | 0분 |
| 2024 | 우수 | 13:13 | 13:13 | 0분 |
| 2000 | 입춘 | 21:40 | 21:40 | 0분 |
| 1990 | 입춘 | 11:14 | 11:14 | 0분 |
| 1988 | 입춘 | 23:42 | 23:43 | 1분 |
| 1958 | 입춘 | 16:19 | 16:20 | 1분 ← UTC+8:30 시기 |

> 최초 작성 시 2000년 입춘 공표값을 20:40 으로 잘못 적어 검증이 실패했고, 출처 확인 결과
> **21:40 이 맞고 라이브러리가 옳았다.** 검증기의 기대값도 틀릴 수 있다는 사례로 남긴다.

### G. 경계 케이스 (전건 통과)

- 자시 학파 두 방식의 일주가 하루 차이로 갈리는지
- 두 학파 모두 시주 천간이 자기 일간과 오서둔으로 정합한지 (1-2 재발 방지)
- 윤달: 음력 2020-04-15 → 양력 2020-05-07 / 음력 **윤**4-15 → 양력 2020-06-06
- 윤달 표기에 "윤" 이 붙고 평달에는 붙지 않는지
- 시각 미상: 시주 `null`, 보정 비활성, 오행 합 6 (3기둥 × 2)
- 시각 있음: 오행 합 8 (4기둥 × 2)
- 지원 범위 끝단(1900-01-01, 2100-12-31) 이 예외 없이 계산되는지
- 보정으로 날짜가 넘어가는 케이스: 1990-05-17 00:10 → 05-16 23:38 → **전날 일주**
- 60갑자 인덱스 왕복 일치

## 3-2. 파생 근거 검증 (TASK-04)

해석 근거를 늘리면서 **고전 규칙으로 확정되는 것**과 **우리가 정한 관례**를 나눠 담았다.
관례를 사실처럼 내보내면 안 되기 때문이다.

| 항목 | 성격 | 근거 |
| --- | --- | --- |
| 지지 십신 | 고전 | 지장간 본기(정기) 천간을 일간과 비교 |
| 왕상휴수사 | 고전 | 당령자 왕 / 왕이 생하는 것 상 / 왕을 생하는 것 휴 / 왕을 극하는 것 수 / 왕이 극하는 것 사 |
| 신강·신약 3기준 | 고전 | 득령(월지)·득지(일지)·득세(나머지) |
| 대운 순행·역행 | 고전 | 양남·음녀 순행 / 음남·양녀 역행 |
| 대운 간지 | 고전 | 월주에서 순행 또는 역행 |
| 세운 간지 | 고전 | (연도 − 4) mod 60 |
| **오행 점수 배수** | **우리 관례** | 왕 1.5 / 상 1.2 / 휴 1.0 / 수 0.8 / 사 0.6 |
| **신강·신약 4단계** | **우리 관례** | 3기준 충족 개수 → 신강 / 약간 신강 / 약간 신약 / 신약 |
| **대운수 반올림** | **우리 관례** | 일수 ÷ 3 반올림, 최소 1세 (나머지를 개월로 환산하지 않음) |

관례에 해당하는 값은 `lib/saju/analysis.ts` 의 상수(`SEASONAL_MULTIPLIER` 등)로 모아 뒀다.
바꾸려면 그 상수만 고치면 된다.

프롬프트에는 점수를 **숫자로 인용하지 말라**고 명시했다. 우리가 정한 배수에서 나온 값이라
절대적 수치가 아니기 때문이다. 샘플 5건 모두에서 숫자 인용이 없었다.

### H. 지지 십신 (전건 통과)

- 지장간 본기 12건을 문헌값으로 다시 적어 대조
- 지지 십신 120건(일간 10 × 지지 12)이 본기 천간의 십신과 일치
- 자기 천간의 십신은 항상 비견
- 십신 10종이 모두 산출되는지 (누락 분기 없음)

### I. 왕상휴수사 (60건 · 불일치 0)

문헌 표를 그대로 적어 대조했다. 각 계절에서 왕·상·휴·수·사가 정확히 하나씩 나오는지도 확인.

| 계절 | 왕 | 상 | 휴 | 수 | 사 |
| --- | --- | --- | --- | --- | --- |
| 봄(인묘진) | 목 | 화 | 수 | 금 | 토 |

## 3-3. 체질 판정 (TASK-14)

`lib/saju/constitution.ts` — `diet` 유형의 체질 판정을 **코드가** 정한다. LLM 은 서술만 한다.
원국을 코드가 계산하는 것과 같은 이유다: 판정을 매번 즉흥으로 내면 같은 사주에 다른 답이 나온다.

판정 축은 넷이고, 전부 이미 검증된 근거(오행 점수·왕상휴수사·신강신약·십신)에서 파생된다.

| 축 | 값 | 근거 | 성격 |
| --- | --- | --- | --- |
| 오행 균형 | 과다 / 적정 / 부족 | 오행 점수가 평균의 몇 배인가 | **우리 관례**(임계값) |
| 한열(조후) | 한·서늘·중화·따뜻·열 | 계절의 한난 + 원국 화·수 세력 | 고전(순서) + **우리 관례**(눈금) |
| 대사 기조 | 발산형 / 축적형 | 신강 계열 / 신약 계열 | **우리 관례**(2분법) |
| 살이 붙는 패턴 | 근육·식욕·불규칙·스트레스·정체형 | 십신 우세 그룹 | 고전(십신 5분류) + **우리 관례**(대응표) |

| 관례 값 | 상수 | 현재 값 |
| --- | --- | --- |
| 과다 임계 | `EXCESS_RATIO` | 평균 점수의 1.5배 이상 |
| 부족 임계 | `DEFICIENT_RATIO` | 평균 점수의 0.5배 이하 |
| 한열 눈금 | `SEASON_TILT` + 화·수 비교 | 각각 −1·0·+1, 합 −2~+2 를 5단계로 |
| 십신 동점 | `SIPSIN_GROUPS` 순서 | 비겁→식상→재성→관성→인성 중 앞선 쪽 |

절대 개수가 아니라 **평균 대비 비율**로 자르는 이유: 시각 미상이면 글자가 6개뿐이라 같은
"2개" 의 무게가 다르다. 비율로 두면 기둥 수와 무관하게 같은 뜻이 된다.

조후를 넣은 이유: 오행 개수만으로는 "여름에 태어난 화 많은 사주" 와 "겨울에 태어난 화 많은
사주" 가 같아진다. 계절의 한난을 먼저 보고 원국 세력으로 보정하는 것이 고전 조후의 순서다.

### M. 체질 판정 (표본 120건 · `lib/saju/constitution.test.ts`)

60갑자를 서로 다른 보폭으로 훑어 만든 60개 원국 × (시각 있음/미상) 로 검사한다.
난수를 쓰지 않으므로 실패하면 그대로 재현된다.

- **결정론** — 같은 입력 두 번 → 완전히 같은 판정 (완료 기준)
- 십신 동점이면 고전 순서에서 앞선 그룹 (동점 처리를 고정하지 않으면 판정이 흔들린다)
- 오행 3단계가 임계 상수와 항상 일치 / 개수 0인 오행은 항상 부족
- 전부 과다이거나 전부 부족일 수 없음 (평균 기준의 성질)
- 한열 눈금 점수가 −2~+2 이고 5단계와 짝이 맞음, 조후 케이스 10건 표 대조
- **십신을 세는 글자가 신강신약 판정 글자와 같음** (시주 있으면 7자, 없으면 5자 · 일간 제외)
  — 두 판정이 다른 글자를 보면 프롬프트 안에서 근거가 어긋난다
- 패턴 5종이 표본에서 모두 출현 (한쪽으로 몰리면 매핑이 죽은 것)

### N. 표현 가이드 (`constitution.test.ts` · `prompt.test.ts`)

면책 고지가 "진단이나 치료 방법이 아니다" 라고 약속하므로, **사용자에게 인용될 수 있는
문구 57개 전부**를 금지 어휘로 훑는다: 치료·완치·처방·진단·질병·질환·증상·효능·효과·약효·
해독·독소·면역·항암·염증·혈압·혈당·콜레스테롤·보장·반드시 등.

오행-신체 배속(목=간·담, 화=심·소장 …)은 고전 배속이지만 **판정 결과에도 프롬프트에도
내보내지 않는다.** 장기 이름이 나가면 진단처럼 읽힌다. 배속의 출처를 밝히는 주석
(`BODY_AXIS.classical`)으로만 두고, 대신 생활어 축(`axis`: "소화와 먹는 리듬" 등)을 쓴다.
테스트가 판정 결과와 프롬프트 양쪽에서 장부 이름이 없음을 확인한다.

한열 눈금 점수(`thermalScore`)도 오행 점수와 같은 이유로 프롬프트에 숫자로 내보내지 않는다.
십신 글자 수는 원국에서 센 사실이므로 그대로 쓴다.

`lib/prompt.test.ts` 는 판정이 실제로 프롬프트에 실리는지도 본다 — 실리지 않으면 LLM 이
즉흥으로 판정하게 되고, 그러면 이 태스크가 무의미해진다. `general` 유형은 체질 블록을
받지 않으며, 두 유형의 원국 사실 블록이 동일함도 확인한다.

## 4. 남은 한계

고칠 계획이 없거나, 다른 태스크로 넘긴 것들.

1. **절기 시각 오차 1~2분** — 라이브러리가 근사 알고리즘을 쓴다. 절입 시각 2분 안에 태어난
   경우 월주가 갈릴 수 있다. 정밀 천문 계산으로 바꾸려면 별도 작업이 필요하다.
2. **한국 음력 vs 중국 음력** — 라이브러리는 중국 기준으로 음력을 계산한다. 한국천문연구원
   음력과 드물게 하루 차이가 난다(삭 시각이 자정 근처일 때). 음력 입력자에게만 영향.
3. **출생지 경도** — API 는 `longitude` 를 받지만 UI 에는 없다. 기본값 서울(126.9784°).
   부산(129.08°)이면 실제로는 8분 차이가 난다.
4. **균시차 근사** — NOAA 근사식으로 오차 약 0.1분. 실용상 무해하다.
5. **테스트로 고정되지 않음** — 지금은 일회성 스크립트다. Vitest 로 옮기는 것은 TASK-05.
6. **세운은 절입 경계를 따지지 않는다** — 연 단위 표시가 목적이라 해당 연도 간지를 그대로
   쓴다. 입춘 이전 며칠은 엄밀히 전년도 간지다. 일별 운세를 낼 때 다시 봐야 한다.
7. **세는나이 기준** — 대운·세운 나이는 세는나이(출생년=1세)다. 한국 만세력 다수 관행이지만
   만 나이를 쓰는 유파도 있다.
8. **지장간 중기·여기 미반영** — 지지 십신은 본기만 본다. 지장간 전체를 오행 점수에
   반영하는 유파도 있으나, 일수 배분이 학파마다 달라 도입하지 않았다.
9. **체질 판정의 임계값에 외부 근거가 없다** — 1.5배·0.5배는 표본을 보고 정한 우리 관례이지
   문헌값이나 임상 근거가 아니다. 판정이 **재현 가능**하다는 것과 **맞다**는 것은 다르다.
   이 서비스가 보증하는 것은 앞쪽뿐이며, 면책 고지에도 그렇게 적었다.
10. **합·충·형·파 미반영** — 지지 사이의 관계(삼합·육합·충 등)는 오행 세력을 바꾸는 유파가
   많으나, 판정 기준이 학파마다 갈려 체질 판정에 넣지 않았다. 오행 점수는 글자 수와
   계절 기세만 본다. 올해 운세도 같다 — **세운과 원국 사이의 충(沖)·합(合)을 보지 않는다.**
   세운 오행이 과부족에 닿는지만 본다.
11. **월별 운세 없음** — 올해 운세는 연 단위다. 월운을 내려면 절입 경계로 월지를 잡아야 하고
   (한계 6번의 세운 문제와 같은 뿌리), 프롬프트에서 월 특정을 금지해 두었다.
12. **올해 운세의 기준 연도는 서버 시각의 연도다** — 입춘 이전 며칠은 엄밀히 전년도 간지이지만
   (한계 6번) 연 단위 표시가 목적이라 그대로 쓴다. 1~2월 초 이용자에게는 한 해 앞선 판정이
   나갈 수 있다.
