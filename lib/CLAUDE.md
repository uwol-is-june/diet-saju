# 도메인·프롬프트 규칙 (lib)

전체 구조·경계는 루트 `CLAUDE.md`, 화면 규칙은 `components/CLAUDE.md`.

**사실(fact)은 코드가 만들고 해석(interpretation)만 LLM 이 한다.** 이 파일은 그 경계의 안쪽이다.

## 만세력 계산 (`lib/saju/`)

### lunar-javascript 를 그대로 믿지 말 것

`lib/saju/` 가 결함 셋을 보정한다. 재현법은 `docs/saju-validation.md`. **되돌리면 결과가 틀린다.**

1. **절기를 베이징 시간(UTC+8)으로 계산한다** → 년주·월주는 `instant.beijingClock` 을 넣어 같은
   좌표계에서 비교한다.
2. **`sect` 가 일주에만 적용되고 시주에는 반영되지 않는다** → 시주는 `ganji.ts` 의 오서둔으로 직접
   계산한다. **라이브러리의 `getTime*()` 을 쓰지 말 것.**
3. **진태양시·서머타임·표준자오선 변경 개념이 없다** → 일주·시주는 보정된 지방시로 넣는다.

### 고전 규칙과 우리 관례를 섞지 말 것

`lib/saju/analysis.ts` 가 두 종류를 나눠 담는다. 코드가 만든 "사실" 이 실제로는 임의의 선택이면
그것을 사실처럼 내보내면 안 된다.

- **고전 규칙**(이견 없음): 지지 십신(본기 기준), 지장간 표(`JI_JANGGAN`), 왕상휴수사, 신강신약
  3기준(득령·득지·득세), 대운 순행/역행, 대운·세운 간지
- **우리 관례**(상수로 분리): 오행 점수 배수(`SEASONAL_MULTIPLIER`), 신강신약 4단계 표현, 대운수 반올림

관례에서 나온 값은 프롬프트에서 **숫자로 인용하지 말라고 지시한다.** 새 파생 지표를 넣을 때도
이 구분을 유지하고 `docs/saju-validation.md` 에 어느 쪽인지 적는다.

#### 지장간 통근은 신강신약 판정에만 쓴다

`isRootedIn` 이 지지의 **지장간 전체**에서 일간을 돕는 천간(비겁·인성)을 본다.

- **표시는 언제나 본기다.** `jiSipsin` 과 화면·프롬프트의 지지 십신은 그대로. 그래서 "일지 편재인데
  득지 ○" 가 나올 수 있고 `strength.rooted` 가 어느 자리에 뿌리가 섰는지 함께 낸다.
- **득령은 본기 그대로다.** 세 기준을 전부 열면 신강 계열로 쏠려 대사 기조 2분법이 죽는다.
- **일수 가중치를 넣지 않는다** ("있나 없나" 만 본다).
- 지장간 표는 `jiBongi` 가 마지막 항목을 읽는 **단일 소스**다. **본기를 따로 적지 말 것.**

### 그 밖의 계산 규칙

- 라이브러리는 **중국어(간체)** 문자열을 돌려준다. 경계에서 즉시 인덱스로 바꾸고
  (`ganji.ts` 의 `parseGanjiHanja`) 노출 직전에만 한글로 바꾼다. **문자열을 중간 표현으로 들고
  다니지 말 것** (간체/정체 표기 차이로 깨진다).
- 서머타임·표준자오선 이력은 **표를 손으로 만들지 말고** Node 내장 tz 데이터(`Asia/Seoul`)를 쓴다.
- 타입 정의가 없어 `types/lunar-javascript.d.ts` 에 직접 선언했다. 새 API 를 쓰면 여기 먼저 추가한다.
- 출생시각 미상이면 **시주를 제외**한다 (`timeUnknown`). **임의의 시각으로 채워 넣지 않는다.**
  이때 시각 보정도 강제로 끈다.
- 기본 옵션: 시각 보정 `longitude`(경도만), 자시 학파 `yajasi`(자정 기준).
- 절기 테이블은 기준일 주변 1년여만 담는다. 대운수는 앞뒤 45일씩 옮긴 기준일에서도 모아 합친다
  (`collectJeolInstants`). 키가 간체(`惊蛰`)와 로마자(`LI_CHUN`) 두 표기로 오므로 **둘 다 받는다.**
- 출생지 표(`lib/form/birthplaces.ts`)는 `node scripts/build-birthplaces.mjs` 가 만드는 **자동 생성
  결과물**이다. **손으로 고치지 말 것.** 광역시는 구를 합치되 **군(郡)은 뗀다.**
- **해외 출생은 지원하지 않는다** (`wallClockToUtc` 가 `Asia/Seoul` 고정).
- 시각 입력은 시·분 드롭다운이고 **분은 1분 단위**다. 경도 보정으로 시지 경계가 정시에서 밀리므로
  **5분 단위로 줄이면 시주가 틀어진다.** **12지시만 고르게 하지 않는다**(대표 시각을 우리가 채우게 된다).
- **사주 계산 로직을 수정하면 `npm run validate:saju` 를 통과시킨다.** 테스트는 같은 라이브러리를 두 번
  부르지 않는다 — 60갑자 연속성·오호둔·오서둔을 테스트 안에서 독립 구현해 대조하고 절기는 천문
  공표값과 맞춘다. 새 규칙도 같은 방식으로 문헌값을 박아 둔다.
- **합·충·신살(神殺)은 계산하지 않는다.** 신살은 고전에 몸·식습관 대응표가 없어 전부 우리 발명품이
  되고, 이름 자체(귀문관살·백호대살)가 면책 고지를 깨며 판본이 갈린다. **도입하지 않는다.**

## 판정 — 코드가 정하고 LLM 은 서술만 한다

**LLM 에게 판정을 맡기지 말 것.** 프롬프트는 판정을 `계산 완료 · 수정 금지` 로 주고 "다시 판정하지
말고 서술하라" 고 지시한다. **완료 기준은 "같은 사주 → 같은 판정" 이다.**

### 라벨은 문장에 그대로 들어가는 우리말이어야 한다

프롬프트가 **라벨을 그대로 쓰라고 요구하므로**(인용률 99%) **라벨이 곧 사용자가 만나는 유일한
용어**다. 용어를 풀어 주는 일은 본문의 몫이 아니라 **라벨을 고르는 일**이다.

> `이 사주는 ___ 입니다` 에 넣어 읽고 ① 다른 말로 읽히거나 ② 글자에서 뜻이 나오지 않거나
> ③ 같은 척도의 다른 값과 말결이 다르면 **서술형 우리말로 바꾼다.**

- **1~2음절 한자 명사를 라벨로 두지 않는다.** `한`(寒)은 관형사 `한`(一)과 충돌해 본문이
  `늘 서늘한 기운이 맴도는 한 체질입니다` 로 나갔다 — 어려운 게 아니라 **틀리게 읽혔다.**
- **표시용 라벨 층을 만들지 않는다.** 값이 union 타입이고 저장되는 곳이 없으므로 이름을 그대로
  바꾼다. 두 벌이 되면 화면과 프롬프트가 갈린다.
- **사진 슬러그(파일 이름)는 라벨과 함께 바꾸지 않는다** — 바뀌는 것은 Record 의 키뿐이다.
- 라벨을 바꾸면 손으로 따라가야 하는 곳이 셋이다 (나머지는 `Record` 가 컴파일에서 잡는다):
  `scripts/sample-readings.mjs` 의 `THERMAL_WORDS`·표본 `expect` · `docs/saju-validation.md`
  근거표 · 공유 카드가 라벨을 한 줄로 그릴 수 있는 길이(`draw-card.ts` 가 접어 준다).
- **문장 꼬리를 라벨에 기대지 말 것.** `${effect}하는 10년` 처럼 옛 한자 라벨에 맞춘 꼬리가
  남아 있으면 새 라벨에서 `채워 주는하는` 이 된다.

- **새 축을 추가하면 동점 처리를 반드시 고정한다.** 고정하지 않으면 판정이 흔들려 완료 기준이 깨진다.
- 기존 축에서 **1:1 로 파생되는 값은 새 동점을 만들지 않는다** (`MOVEMENT_PLAN`←`dietApproach`,
  `MEAL_PLAN`←`gainPattern`, 대표 종목←`movementKind`).
- 판정에 딸린 한국어 문자열은 프롬프트가 아니라 **근거 데이터**다. 프롬프트 문장은 `lib/prompt.ts`
  한 곳에만 있다.

### 체질 (`constitution.ts`)

판정 축은 다섯 — 오행 과다·부족, 한열(조후), 대사 기조, 살이 붙는 패턴, 다이어트 접근 순서.
**`한열`·`조후` 는 코드와 이 문서에서만 쓰는 이름이다** — 사용자에게 나가는 자리(데이터 블록·
절 지침·화면)에서는 **`몸의 온도`** 로 쓴다. 모델은 데이터 블록에 적힌 항목 이름을 그대로
본문에 옮기므로(표본 30건 중 3~4건), 지시로 막기 전에 **이름 자체를 우리말로 둔다.**
**문구 표까지 함께 훑을 것** — `THERMAL_GUIDE` 의 `tendency` 한 줄에 남아 있던 `한열` 이
지시문을 이기고 본문에 나갔다 (근거 데이터는 프롬프트에 그대로 실린다).
여기에 **재료 범주**가 과다·부족 오행마다 딸려 붙는다. 근거·임계값은 `docs/saju-validation.md`.

- **오행-장부 배속(목=간·담 …)을 사용자에게 내보내지 않는다.** 장기 이름이 나가면 진단처럼 읽힌다.
  `BODY_AXIS.classical` 은 출처 주석일 뿐이고 노출은 생활어 축(`axis`)으로 한다. 테스트가 판정 결과와
  프롬프트 양쪽에서 막는다.
- 사용자에게 인용될 수 있는 문구는 `constitution.test.ts` 가 금지 어휘(치료·효능·진단·질환…)로 훑는다.
- **실행 방법은 일부 개방이다. 방법은 구체적으로 쓰고 수치는 계속 막는다.**
  - **여는 것** — 운동 종류(유산소 중심·근력 중심·풀어 주는 쪽·낮은 강도로 오래)와 강도의 감각, 식사 순서와 시각, 조리
    방식과 음식 온도.
  - **막는 것** — 칼로리·목표 체중·체지방률·감량 기간·횟수/세트/분 수·섭취량, 단식(간헐적 단식 포함)·
    상표 식단 이름, 영양제·보조식품. **"많이 먹어라 / 끊어라" 도 금지.**
  - `constitution.test.ts` 가 처방 어휘와 **문구에 숫자가 섞이는 것**을 막고, **여는 것이 실제로
    열려 있는지도 검사한다** (막는 것만 보면 조용히 다시 닫혀도 모른다).
  - `prompt.test.ts` 가 유형 규칙과 섹션 지침 **두 곳**에 금지가 있는지 본다.
  - `app/disclaimer/page.tsx` 가 이 경계를 서술한다. **범위를 바꾸면 그 문단도 같은 커밋에서 고친다.**
- **한열은 접근 순서에도, 실행 방법 표에도 넣지 않는다.** 한열은 같은 방법을 어느 온도·시간대에
  실행하느냐를 정하는 **다른 층**이다. `MOVEMENT_PLAN`·`MEAL_PLAN` 이 온도·성미를 말하기 시작하면
  층이 무너지므로 테스트가 막는다.
- **식품 이름은 실행 방법 표에 적지 않는다.** 무엇을 먹을지는 `ELEMENT_FOOD`(오행)와
  `THERMAL_GUIDE`(조리·온도)가 정하고 `MEAL_PLAN` 은 **순서와 시각의 규칙**만 정한다.
- `ELEMENT_FOOD` 는 닫힌 목록이다. **프롬프트가 "이 목록 밖의 식품 이름을 쓰지 말라" 고 지시한다** —
  목록을 닫는 것은 코드가 하지만 본문에 다른 식품이 나오는 것은 프롬프트만 막을 수 있다.
  - **재료는 오행이, 조리·온도는 한열이 정한다.** 성미(온성·냉성) 용어를 쓰지 말 것 — 출처가
    한의학이라 면책 고지의 "한의학과 무관" 약속이 깨진다. 조리 문구는 `THERMAL_GUIDE` 하나에만 둔다.
  - 상표명·영양제·보조식품·섭취량 금지. 부족은 "곁들이기", 과다는 "더 늘리지 않기" 까지.
  - **식품 이름 검출기에 명리 용어와 겹치는 부분 문자열을 쓰지 말 것** ("견과" 는 "비견과 겁재" 에 걸린다).
- 콜아웃 **근거 줄** 문구는 `VERDICT_BASIS_*` 표에 있고 **판정 축의 이름을 대지 않는다**
  (`신강신약` · `십신` · `대사 기조` · `걸리는 지점` · `한열` · `오행` 금지 — 검사가 막는다).
  - **문장은 표가 통째로 들고 값만 끼운다** (`verdictMovementBasis` · `verdictFoodBasis`).
    컴포넌트가 조각을 이어 붙이면 그 문장이 금지 어휘 검사를 우회한다.
  - **`DIET_APPROACH_NOTE` 를 참조하지 않는다** — 프롬프트가 "풀어 쓰라" 고 넘기는 값이라 그대로
    가져오면 카드와 본문 첫 문단이 같은 말을 한다.
  - 화면 규칙(두 줄 예산 · 출처를 말하는 다른 자리 셋)은 `components/CLAUDE.md` 에 있다.
- 콜아웃 라벨 문구는 `GAIN_LABEL` 이 고르고 형태는 **"~할 때 붙는 성향"** 으로 고정한다.
  **`~할 때` 는 언제인지만 말하고 왜인지는 말하지 않는다** — `~해서`·`~라서` 로 바꾸면 형태만으로
  경계를 넘는다. `constitution.test.ts` 가 인과 어미와 hedge 어미를 막고 형태도 고정한다.
- **`diet-food` 라벨은 오행 이름이 아니라 재료 이름이다** (`ELEMENT_FOOD.short`).
  - **맛을 라벨에 올리지 않는다** — 몸의 온도가 `더운 쪽` 인 사람 화면에서 `THERMAL_GUIDE` 와 정면으로 부딪힌다.
  - **근거 줄은 계열 이름과 `basis`(맛·빛깔)까지만 받는다.** 나머지 재료를 늘어놓으면 두 줄을
    넘고, 라벨의 재료가 "그것만 먹으라" 로 읽히지 않게 하는 몫은 `밥상에 한 가지씩만` 이 한다.
  - 조사(`을`/`를`)는 받침으로 정한다 — 라벨마다 문자열을 손으로 적으면 표가 하나 더 생긴다.
  - 부족한 오행이 없으면 `오행이 고르게 퍼진 편`(칩은 `오행이 고름`).

### 올해 세운 (`yearly.ts`)

**유형이 아니라 `diet` 의 "올해의 몸 흐름" 절이 쓴다.** 운세는 LLM 이 가장 즉흥적으로 흐르기 쉬운
영역이라 판정을 코드가 한다.

- 축은 둘이지만 **밖으로 나가는 것은 하나뿐이다.**
  - **작용**(세운 오행이 원국의 부족을 채우는가 / 과다에 더하는가 → 채워 주는·겹치는·무던한) —
    `constitution.deficient`/`excess` 에서 계산되므로 원래 몸 쪽 값이다. **프롬프트로 나간다.**
  - **주제**(세운 천간의 십신 그룹) — **프롬프트로 내보내지 않는다.** 생활 영역 어휘라 몸 이야기에
    얹으면 겉돌고, "압박이 늘어 몸이 상한다" 류는 면책 고지가 막는 의학적 주장에 닿는다.
    계산은 남겨 둔다 (생활 영역 유형이 생기면 그대로 쓴다).
- **월별 운세를 계산하지 않는다.** 프롬프트가 두 곳(판정 블록 · `TYPE_RULES.diet`)에서 막고
  `prompt.test.ts` 가 둘 다 확인한다.
- **사건을 예고하지 않는다.** `yearly.test.ts` 가 금지 어휘(반드시·대박·사고·합격…)로 훑는다 —
  **유형이 없어져도 문구는 사용자에게 나가므로 이 검사를 지우지 않는다.**
- 판정 블록은 체질 판정과 **같은 프롬프트 안에** 실린다.

### 대운 10년 (`decade.ts`)

## 유형 (`lib/saju/schema.ts`)

**`READING_TYPES` 에 값을 넣으면 `Record<ReadingType, …>` 를 쓰는 곳이 전부 컴파일 오류로 잡힌다.**
이걸 유지하는 것이 중요하다 — 삼항이나 인덱스 시그니처로 두면 새 유형이 조용히 남의 값을 달고 나간다.

손대야 하는 곳: 유형 문구 셋(`READING_TYPE_LABEL` · `READING_TYPE_DESCRIPTION` ·
`READING_TYPE_META`) · `READING_TYPE_QUESTION` · `READING_TYPE_VISIBILITY` ·
`READING_TYPE_NEEDS_GENDER` · 섹션 계약(`reading/sections.ts`) · 섹션 지침과 유형별 서두·규칙
(`prompt.ts`) · 유형별 판정 블록(`prompt.ts` 의 `VERDICT_BLOCK`) · 판정 한 줄(`reading/verdict.ts` — 화면과 공유 카드가 함께 읽는다) ·
유형 사진(`reading/type-photo.ts`).
유형 선택 카드 · 결과 뒤 링크 · `/admin` · `/reading/[type]` 프리렌더는 목록을 순회하므로 자동이다.

**카드 설명과 메타 설명은 사용자에게 그대로 보이는 문구다.** 판정 문구와 같은 표현 규칙이 적용된다
(처방·수치·예언 어휘 금지). `schema.test.ts` 가 모든 유형의 문구를 훑고 **숫자를 `/\d/` 로 막는다** —
**그 검사를 완화하지 말 것.** 카드와 메타를 하나로 합치지 말 것 (카드는 짧아야 하고, 메타는 무엇을
넣어야 하는지까지 말해야 한다).

### 노출 구분

`READING_TYPE_VISIBILITY` 가 `public`/`internal` 을 정하고 `PUBLIC_READING_TYPES` ·
`INTERNAL_READING_TYPES` 가 **거기서 파생된다.** 손으로 유지하는 두 번째 목록을 만들지 말 것.

| 쓰는 곳 | 도는 목록 |
| --- | --- |
| 유형 선택 카드 · 결과 뒤 링크 | `PUBLIC_READING_TYPES` |
| `/admin` | `INTERNAL_READING_TYPES` |
| `generateStaticParams` | **`READING_TYPES` 전부** (빼면 그 라우트가 죽는다) |

- **내부 유형 페이지와 `/admin` 은 `noindex` 다.**
- **`/admin` 에 인증이 없다 — 숨김이지 보호가 아니다.** 진짜 관리 기능을 붙이려면 인증이 먼저다.

## 섹션 계약 (`lib/reading/sections.ts`)

**JSON 구조화 출력(`responseSchema`)을 쓰지 않는다.** JSON 은 완성 전까지 파싱이 불가능해서 점진
렌더가 죽는다. 형식은 마크다운 제목으로 강제한다.

**`sections.ts` 가 단일 소스다.** 제목 문자열은 거기에만 있고, `prompt.ts` 가 읽어 `## 제목` 지침을
만들고 `ReadingSections.tsx` 가 같은 계약으로 가른다. **제목을 프롬프트나 컴포넌트에 적지 말 것.**

- 이 파일은 클라이언트에서 import 되므로 `server-only` 가 없고 **프롬프트 지시문도 두지 않는다**
  (섹션별 지시문은 `prompt.ts` 가 id 로 붙인다).
- 파서는 **누적 문자열 전체를 매번 다시 파싱한다** (증분 상태를 들면 조각 경계 버그를 다 떠안는다).
- `###` 은 섹션 경계가 아니다. **해시만 도착한 마지막 줄은 보류한다** (빈 카드가 번쩍인다).
- **계약을 어긴 출력을 버리지 않는다.** 모르는 제목은 `id: null`, 계약 섹션을 하나도 못 잡으면
  `recognized: false` 로 원문 폴백. 강제가 아니라 부탁이므로 **이 폴백이 반드시 있어야 한다.**
- **계약 제목은 모델이 재현하기 쉬운 낱말로 고른다.** 어려운 어간은 그대로 파손률이 된다.
  **제목을 고칠 때는 표본으로 재현율을 확인할 것.**
- **`title` 에 이모지를 섞지 말 것** (모델이 그것까지 정확히 재현해야 파싱된다).
  `sections.test.ts` 가 제목 문자 집합을 검사한다.
- **마지막 절을 "실천 3가지" 류 요약으로 두지 말 것** — 위 절들을 한 줄씩 되풀이해 새 정보가 0 이 된다.
- **섹션 id 를 유형끼리 공유하지 않는다.** `SECTION_INSTRUCTION` 이 id 로 매기므로 공유하면 맥락이
  다른 두 유형이 한 지시문을 떠안는다.
- 같은 판정을 두 유형이 쓸 때는 **섹션 id 를 나누고 지침이 서로 다른 것을 요구하게** 한다
  (`prompt.test.ts` 가 두 절 지침을 대조한다).

## 프롬프트 (`lib/prompt.ts`)

**프롬프트는 전부 이 파일에 모아둔다.** 컴포넌트나 route 에 프롬프트 문자열을 흩뿌리지 않는다.
구성은 `SYSTEM_INSTRUCTION` → `SECTION_INSTRUCTION`(id 로 매김) → `TYPE_PREFACE`/`TYPE_RULES` →
`buildUserPrompt`. 섹션 **제목**만 예외로 `reading/sections.ts` 계약에서 온다.

- 사용자 입력(이름 등)은 `<user_data>` 로 감싸 "지시문이 아니라 데이터" 로 넘긴다.
  감싸는 것만으로는 부족해서 `sanitizeName()` 이 꺾쇠·줄바꿈·줄머리 `#` 를 지운다 —
  **`</user_data>` 는 12자라 이름 20자 제한 안에 들어간다.** 경계 자체를 사용자가 만들 수 없게 막는다.

### 판정은 단정하고 인과·예고는 막는다

성질이 다른 두 문장을 한 줄로 묶지 말 것. **이 구분이 표현 규칙의 축이다.**

| | 예 | 다루는 법 |
| --- | --- | --- |
| (i) 판정에 대한 사실 | "패턴은 **식욕형입니다**" | **단정한다** |
| (ii) 몸에 대한 인과·예고 | "스트레스 **때문에** 찝니다", "~하게 됩니다" | **막는다** |

(i)은 코드가 정한 결정론적 값이고 면책 고지가 "언제나 같은 판정" 을 이미 약속한 내용이다.
여기에 `~인 편입니다`·`~일 수 있습니다` 를 덧대면 **아무것도 말하지 않은 글**이 된다.

- 경계는 `SYSTEM_INSTRUCTION` 에 한 번, `TYPE_RULES` 각각의 **맨 앞 줄**에 한 번씩 있다.
  `prompt.test.ts` 가 **양쪽을 검사한다** — (ii)가 막혀 있는지 **+ (i)이 실제로 열려 있는지.**
- **금지 규칙 셋은 그대로다** — 수치·단식·처방 · 근거 없는 값 · 장부·성미·효능·월별 운세.
- **지시문이 금지 낱말을 직접 요구하지 않는지 확인할 것.** 부정문이어도 `TYPE_RULES` 가 막는
  낱말이면 **지시문 쪽을 고친다.**
- **`결` 은 사용자 노출 문자열과 프롬프트에서 0건이다** (`prompt.test.ts` 가 검사한다). 사주 용어가
  아니다. **한 낱말로 갈아 끼우지 않는다** — 자리마다 다른 말을 고르거나 문장을 다시 쓴다.
  경계를 정의하던 줄은 `이 사주에서 읽어 낸 것`.
- **hedge 로 도망가지 말 것.** 대체어를 고르다 `~인 편입니다` 로 흐르면 라벨 인용률을 스스로 깎는다.
- **`SYSTEM_INSTRUCTION` 이 되풀이를 막는다** ("같은 낱말로 모든 절을 쓰지 마세요 · 두세 번까지").
  **여기에 금지 낱말을 예로 적지 않는다** — 적는 순간 그 낱말이 모델 눈앞에 놓인다.
  예시는 대체어 쪽으로만 든다.

#### 금지 낱말이 부정문으로 새는 것은 낱말이 아니라 횟수 문제다

범위를 밝히라는 지시가 그 낱말을 끌어온다("특정 질환을 진단하는 것이 아닙니다").

- **가장 큰 지렛대는 상한이다** — "범위를 밝히는 문장은 글 전체에서 한 번까지".
- **막기만 하지 말고 쓸 문장을 준다** (`저희가 아는 것은 생년월일시뿐이라…` ·
  `효과적입니다` 대신 `~하는 편이 덜 흔들립니다` · `여기서 다루는 것은 밥상까지입니다`).
- **지시문이 견주기를 요구하면 그 낱말이 나간다.** 견주지 말고 근거만 말하게 한다
  ("이 판정의 근거는 명리학 오행뿐입니다").
- **대안 문장 자체가 부정문 꼴이면 안 된다.**
- **남은 부정문은 그대로 둔다.** 판단 기준은 **절대량과 "진짜 위반 0건"** 이다 —
  **부정문 비율을 목표로 삼지 말 것**(낱말을 걷어낼수록 그 비율은 오히려 올라간다).
- `prompt.test.ts` 가 상한 문구와 대안 문장을 **양쪽에서** 검사한다.

### 분량은 절마다 다르고 여는 자리는 장면이다

**균등 배분을 되살리지 말 것.** 모든 절에 같은 분량을 걸면 근거 인용 + 용어 풀이 + 연결이 다
들어가 장면 쓸 자리가 없어진다. 공감은 장면에서 온다.

- 분량은 `SECTION_INSTRUCTION` 마지막 줄의 **`분량:`** 이 정하고, 유형마다 **중심 절**이 하나 이상
  있다. `prompt.test.ts` 가 모든 절에 `분량:` 이 있는지, 중심 절이 있는지, **요약이 중심이 아닌지**를
  검사한다.
- **장면은 중심 절에만 요구한다** (모든 절에 넣으면 장면 나열이 되고 근거가 사라진다).
- **여는 자리 규칙은 전 절 공통이다** — 첫 문장을 명리 용어로 열지 않는다. **`이 사주는` 도 같다.**
  `SYSTEM_INSTRUCTION` 의 **나쁜 예 둘 + 좋은 예 하나를 지우지 말 것** (규칙만으로는 안 잡힌다).
- **본문은 판정 이름 + 그것이 하루에 어떻게 나타나는지까지다. 근거를 대는 일은 화면의 근거 카드
  넷이 맡는다** (원국 표 · 오행 막대 · 대운/세운 · 계산 기준). 계산 **과정**의 항목(득령·득지·득세 ·
  통근 · 왕상휴수사 · 신강신약 · 십신 이름 · 년주·시주)은 **본문에 이름을 쓰지 않고 뜻으로만** 쓴다 —
  읽는 사람이 그 낱말을 다시 만날 곳이 없어 근거가 아니라 **권위 신호**로 작동한다. 예외는
  **태어난 계절** 하나다 (생일에서 바로 나오는 사실이라 확인할 수 있다).
- **판정 라벨은 계속 "반드시 언급" 이다.** 콜아웃에 큰 글씨로 떠 있는 값이라 본문에서 사라지면
  위아래 연결이 끊긴다. 지시문에서 빠진 것은 계산 항목을 요구하던 줄뿐이다.
- **아는 낱말로 갈아 끼우는 쪽으로 도망가지 말 것** (`자리` · `지탱하는 힘` · `밑돌`). 용어보다
  나아 보이지만 무엇을 말하는지 알 수 없어 읽는 사람에게 남는 것이 없다.
- **모델은 지시한 분량의 절반에서 멎는다. 그래도 지시값을 내리지 말 것.**

### 말투는 리포트가 아니라 상담이다

- **존댓말은 `-습니다`체다. `-해요`체로 바꾸지 말 것** (판정을 단정하는 문체와 면책 문구의 톤이
  함께 흔들린다).
- **용어는 글 전체에서 처음 한 번만 풀고, 괄호가 아니라 문장으로 녹인다.**
- **판정에 딸린 문구는 말맛을 살려 쓴다.** 막을 것은 한 줄씩 나열하는 것이지 문구의 구체성이 아니다.
- **`# 말투 예시` 셋을 지우지 말 것.** 예시는 어느 판정에도 없는 사주로 만들고 "복사하지 말고
  말투만 따르라" 를 함께 건다.
- **되짚기(`혹시 ~한 적 있으시죠?`)는 절마다 하나까지, 요약 절에는 없다.**
  **`~때문에 그러셨죠?` 는 금지** (질문 형태여도 몸의 인과를 단정한다).
- **이름이 없으면 호칭을 지어내지 않는다.** `sanitizeName` 의 인젝션 방어는 그대로 둔다.

## Gemini (`lib/gemini.ts`)

- 모델은 `GEMINI_MODEL` 로 주입되고 기본값은 **`gemini-3.5-flash-lite`** 다.
  **`gemini-2.5-*` 는 신규 키에 404 로 폐지됐다.** **Pro 는 유료 전용**이다.
- **`thinkingLevel` 은 `MINIMAL` 고정이다.** lite 에서 `MINIMAL`·`LOW`·`MEDIUM` 은 같은 설정이고
  (추론 토큰 0) 실제 선택지는 `MINIMAL` 과 `HIGH` 뿐이다. `HIGH` 는 첫 글자가 크게 늘고 추론 내용이
  본문으로 새어 섹션 계약을 깨뜨린다. **밋밋함은 추론 예산에서 오지 않는다.**
- **출력 토큰 예산은 추론과 공유한다.** 예산이 마르면 본문이 문장 중간에서 잘리는데
  **스트림은 `error` 가 아니라 `done` 으로 끝난다** — 추론을 켜는 변경에는 상한을 함께 올린다.
- SDK 는 `@google/genai`. 호출은 `ai.models.generateContent({ model, contents, config })`.
- **`temperature` 는 0.9 유지가 실측 결론이다.** 같은 입력에 같은 문장이 필요하면 온도가 아니라
  **캐싱**으로 푼다.
- 실패 분류(`GeminiFailureKind`)와 사용자 문구는 **같은 분류에서 나온다**(`toGeminiError`).
  두 곳에서 따로 판별하면 어긋난다 — 일일 소진에 "1분 후 다시" 라고 하면 거짓말이 된다.
- 로그는 `toSafeLogMessage()` 로 마스킹하고 디버깅에는 `maskedApiKey()` 를 쓴다.

### 무료 등급 일일 한도 — 모델 선택의 핵심 기준

**Lite 계열만 500 RPD 이고 나머지 Flash 는 20 RPD 다.** 무료 등급을 쓰는 동안 **모델을 Lite 밖으로
옮기지 말 것.**

| 모델 | RPM | RPD |
| --- | --- | --- |
| `gemini-3.5-flash-lite` **(기본)** | 15 | **500** |
| `gemini-3.1-flash-lite` | 15 | 500 |
| `gemini-3.5-flash` / `gemini-3-flash` / `gemini-3.6-flash` / `gemini-2.5-flash` | 5 | **20** |

**문서·블로그 수치를 믿지 말 것.** 확인처는 https://aistudio.google.com/rate-limit 대시보드,
또는 429 응답의 `quotaId`/`quotaValue` 뿐이다.

`lib/rate-limit.ts` 의 IP 제한은 **계정 단위 한도와 별개**다. 429 문구는 `quotaId` 의 `PerDay` 로
분당/일일을 구분한다.

## 풀이 서술 품질은 테스트가 아니라 표본으로 잰다

```bash
npm run dev                                                  # 다른 터미널에서
node scripts/sample-readings.mjs --label after --repeat 2
```

**CI 에 넣지 않는다** (Gemini 쿼터를 쓰고 회차마다 결과가 다르다).
기준선은 `docs/saju-validation.md` 에 있다 — **고치기 전에 다시 찍지 말고 그 표를 기준으로 삼는다.**

- 프롬프트·섹션 계약·모델 설정을 건드리는 작업만 이 도구를 쓴다.
- **분량을 늘리는 변경은 두 번 재야 한다** (늘어난 자리를 무엇이 채웠는지 한 번으로는 못 본다).
- 지표는 **보조다.** 지표만 좋아지고 읽기가 나빠지면 지표를 버린다.
- 섹션 제목과 공개 유형 목록을 **소스에서 정규식으로 읽는다** (스크립트에 베껴 두면 세 번째 사본이 된다).
- **산출물(풀이 마크다운)은 커밋하지 않는다.**
